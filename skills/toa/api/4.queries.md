# List with Filters, Sorting and Paging

The shop's back office lists orders: only the pending ones, the largest first, twenty at a time.
A client says so in the query string, and the method's `query` declaration decides how much of
that the client controls: a route can leave the selection open, bound it, or fix it.

## The parameters a list takes

A method that maps an operation with a query accepts the standard parameters.
`GET /store/orders/` is one: [Expose It over HTTP](../start/4.api.md) maps it to the inherited
`enumerate` of `store.orders`, the component [Create a Component](../start/3.component.md)
writes, beside `POST: create` and `anonymous: true`, which the fragments here leave out.

```yaml
# components/store.orders/manifest.toa.yaml
exposition:
  /:
    # …
    io:output: [id, customer, status, total]
    GET: enumerate
```

```http
GET /store/orders/?criteria=total>1000&sort=total:desc&omit=20&limit=10 HTTP/1.1
```

| Parameter | Meaning |
| --- | --- |
| `id` | The identifier of one entity. |
| `criteria` | An [RSQL](https://github.com/jirutka/rsql-parser) expression over entity properties. |
| `sort` | Properties to order by, `;`-separated, each with an optional `:asc` or `:desc`. |
| `omit` | How many entities to skip. Default `0`, at most `1000`. |
| `limit` | How many entities to return. Default `10`, between `1` and `100`. |

`omit` and `limit` apply to a method whose operation works on a list — an observation, a
transition or an effect of scope `entries`, such as `enumerate`. A method that works on one
entity refuses them with `400`.

As a scenario, written with the steps of [Write a Test](../start/5.testing.md) and run with
`npm run features` while `sys` is running (`npm run sys`):

```gherkin
# features/orders.feature
  Scenario: List a customer's pending orders, largest first
    When the request is sent:
      """
      POST /store/orders/ HTTP/1.1
      content-type: application/yaml

      customer: b70a7dbca6b14a2eaac8a9eb4b2ff4db
      items: []
      total: 4200
      """
    Then the response is received:
      """
      201 Created
      """
    When the request is sent:
      """
      GET /store/orders/?criteria=customer==b70a7dbca6b14a2eaac8a9eb4b2ff4db;status==pending&sort=total:desc&limit=1 HTTP/1.1
      accept: application/yaml
      """
    Then the response is received:
      """
      200 OK

      - customer: b70a7dbca6b14a2eaac8a9eb4b2ff4db
        status: pending
      """
    When the request is sent:
      """
      GET /store/orders/?limit=1000 HTTP/1.1
      accept: application/yaml
      """
    Then the response is received:
      """
      400 Bad Request
      """
```

An operation that declares `query: false` takes no query string at all:

```http
HTTP/1.1 400 Bad Request

"Query parameter 'limit' is not allowed"
```

## Criteria

`criteria` is RSQL. Conditions are joined with `;` for *and* and `,` for *or*:

```http
GET /store/orders/?criteria=status==pending;total>=1000 HTTP/1.1
GET /store/orders/?criteria=status==pending,status==approved HTTP/1.1
```

A value is read as what the property holds. A value that cannot be read so is refused:

```http
GET /store/orders/?criteria=total>abc HTTP/1.1
```

```http
HTTP/1.1 400 Bad Request

"Criteria selector 'total' takes a number, and 'abc' is not one"
```

A string property takes whatever is written.

An unquoted `null` or `undefined` means *no value*: `approved==null` selects the orders that hold
no `approved` — never set, or set to `null` — and `approved!=null` those that hold one. It
compares with `==`, `!=`, `=in=` and `=out=`; any other operator with it is `400`. Quoted, it is
text: `note=="null"`.

### Fixing the criteria

A route that declares `criteria` selects with it, and the client adds nothing:

```yaml
exposition:
  /pending:
    io:output: [id, customer, total]
    GET:
      endpoint: enumerate
      query:
        criteria: status==pending
```

```http
GET /store/orders/pending/?criteria=total>1000 HTTP/1.1
```

```http
HTTP/1.1 400 Bad Request

"Query criteria is closed"
```

### Opening the criteria

Criteria that end with `;` are *open*: the client's criteria are added to the route's, joined
with *and*.

```yaml
      query:
        criteria: status==pending;    # open
```

`GET /store/orders/pending/?criteria=total>1000` now selects
`(status==pending);(total>1000)`. The client can narrow the route's selection and never widen
it.

### Criteria and route variables

A route variable other than `id` is a condition of its own, put in front of the route's criteria
and joined with *and*:

```yaml
exposition:
  /of/:customer/pending:
    io:output: [id, total]
    GET:
      endpoint: enumerate
      query:
        criteria: status==pending
```

`GET /store/orders/of/b70a…f4db/pending/` selects `(customer==b70a…f4db);(status==pending)`.

To join the variable with *or* instead, start the criteria with a comma:

```yaml
      query:
        criteria: ,status==pending
```

which selects `(customer==b70a…f4db),(status==pending)`. A leading `;` states the default
explicitly. `POST` is the exception: its route variables go to the input, see
[Map Methods to Operations](3.methods.md#route-variables).

## Sort

```http
GET /store/orders/?sort=total:desc;CREATED:asc HTTP/1.1
```

Ascending is the default: `sort=total` is `sort=total:asc`. `CREATED` is one of the
[system properties](../logic/1.state.md#system-properties) every stored object carries.

A route that declares `sort` orders by it. Ending the value with `;` opens it, and the client's
`sort` is appended after the route's:

```yaml
      query:
        sort: status:asc;    # then by whatever the client asks
```

`GET …?sort=total:desc` then orders by `status:asc;total:desc`.

## Paging: omit and limit

Declare a default and the bounds a client may move within:

```yaml
exposition:
  /:
    io:output: [id, status, total]
    GET:
      endpoint: enumerate
      query:
        sort: CREATED:desc
        limit:
          value: 20
          range: [1, 50]
        omit:
          range: [0, 500]
```

`value` is what applies when the request says nothing; without it the lower bound of the range
is used. A request outside the range is refused:

```http
HTTP/1.1 400 Bad Request

"Query limit must be between 1 and 50 inclusive"
```

A number alone is a constant the client cannot change:

```yaml
      query:
        limit: 5
```

Where nothing is declared the defaults are:

```yaml
omit:
  value: 0
  range: [0, 1000]
limit:
  value: 10
  range: [1, 100]
```

They hold for a route to a transition or an effect over `entries` as well: a `PUT` that carries
no `limit` changes ten entities, never the whole collection.

**`omit` needs an order.** A request with `omit` to a route that neither declares nor receives a
`sort` is answered `400`. Declare `sort` on every route a client pages through, as above.

## A fixed query

Putting these together, a route can be a complete, closed question:

```yaml
exposition:
  /top:
    io:output: [id, customer, total]
    GET:
      endpoint: enumerate
      query:
        criteria: status==approved
        sort: total:desc
        limit: 10
  /latest:
    io:output: true
    GET:
      endpoint: observe
      query:
        sort: CREATED:desc
```

`GET /store/orders/top/` returns the ten largest approved orders, and
`GET /store/orders/latest/` the newest order.

## Identifier

One entity is usually selected by a route variable named `id`. A client may also send it as a
parameter, where the route has no such variable:

```yaml
exposition:
  /order:
    io:output: true
    GET: observe
```

```http
GET /store/orders/order/?id=4c4759e6f9c74da989d64511df42d6f4 HTTP/1.1
```

## Text search

For an entity with a text index (declared in a
[migration](../logic/20.migrations.md)), a method can accept a `search` parameter. It is
off unless declared. The catalogue is a component of its own,
[`store.catalog`](../logic/1.state.md#identifiers-of-another-shape), whose products have a `title`
and a `price`:

```yaml
# components/store.catalog/manifest.toa.yaml
exposition:
  /:
    io:output: [id, title, price]
    GET:
      endpoint: enumerate
      query:
        search: true
```

```http
GET /store/catalog/?search=copper+kettle HTTP/1.1
```

A `search` sent to a method that does not declare it is `400`.

## Projection

`projection` lists the entity properties an observation reads from the storage. The operation
receives those, the `id` and the system properties, and nothing else:

```yaml
exposition:
  /:
    io:output: [id, status, total]
    GET:
      endpoint: enumerate
      query:
        projection: [status, total]
```

Use it for wide entities of which a route needs little: the properties that are not listed are
never loaded. A method without a projection reads the whole entity.

- `id` is always read; naming it in the projection is refused.
- Only a method mapped to an observation may declare one. Declared for any other type, the
  component does not start.
- A projection decides what is read. What the client receives is still decided by
  [`io:output`](6.io.md#choose-what-comes-back).

## Parameters of the operation

Query-string parameters other than the standard ones are refused, unless the method declares
them as `parameters`. Declared parameters are not part of the query: they are put into the
operation's **input**, which must be an object.

```yaml
# components/store.catalog/manifest.toa.yaml
exposition:
  /quote:
    io:output: true
    GET:
      endpoint: quote          # a computation taking { product, quantity }
      query:
        parameters: [product, quantity]
```

```http
GET /store/catalog/quote/?product=kettle&quantity=3 HTTP/1.1
```

A parameter that is not declared is refused:

```http
HTTP/1.1 400 Bad Request

"Query parameter 'foo' is not allowed"
```

## Streams of a collection

A method mapped to an operation of scope `stream` answers the selected entities and then a token
to continue from ([Read a Large Collection](../logic/15.collections.md)); every component with an
entity [inherits](../logic/5.prototype.md) one, named `stream`. Its query follows different
rules:

- `limit` is the size of a window. A stream route that declares no `limit` answers the whole
  collection in one reply and takes no `limit` from the client.
- `omit` is refused. The next window is read with the token.
- `token` continues from where a previous reply ended.
- `stop` ends the read after the first window; the token then continues with changes only.
- `sort`, beside `limit` or `token`, takes `id` and `CREATED` only.

```yaml
# components/store.orders/manifest.toa.yaml
exposition:
  /feed:
    GET:
      endpoint: stream
      io:output: [id, status, total, VERSION]
      query:
        criteria: status==pending
        limit: { value: 100, range: [1, 500] }
```

```http
GET /store/orders/feed/ HTTP/1.1
GET /store/orders/feed/?token=eyJ2IjoxLCJwIjoi... HTTP/1.1
GET /store/orders/feed/?sort=CREATED:desc&stop HTTP/1.1
```

`token` and `stop` sent to a method that is not a stream are `400`. A token under criteria or
an order other than its own is `400`; a token the storage can no longer continue from is
`410 Gone`, and the client reads the collection again without one. The shape of the reply and
how a client follows it is in [Stream Through the API](9.streams.md#collection-streams).

## Reference

Keys of a method's `query`:

| Key | Type | Meaning |
| --- | --- | --- |
| `criteria` | string | Fixed criteria. A trailing `;` opens them; a leading `,` or `;` says how route variables are joined. |
| `sort` | string | Fixed order. A trailing `;` opens it. |
| `limit` | integer or `{ value, range }` | Constant, or default and bounds. |
| `omit` | integer or `{ value, range }` | Constant, or default and bounds. |
| `search` | boolean | Accept the `search` parameter. |
| `projection` | array of strings | Properties an observation reads. |
| `parameters` | array of strings | Query-string parameters passed to the input. |

Parameters of a request:

| Parameter | Accepted when |
| --- | --- |
| `id` | The operation takes a query. |
| `criteria` | The route's criteria are open or undeclared. |
| `sort` | The route's sort is open or undeclared. |
| `omit`, `limit` | The operation's scope is `entries`; within the declared range. `omit` only beside a `sort`, declared or sent. |
| `search` | The method declares `search: true`. |
| `token`, `stop` | The method maps a stream operation. |
| declared `parameters` | Listed in `parameters`. |

The version a write is conditional on travels in the `if-match` header, not in the query string;
see [Prevent lost updates](8.caching.md#prevent-lost-updates).
