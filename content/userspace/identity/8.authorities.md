# Authorities and the Edge

Some things the gateway decides from the request itself, before or beside identity: the domain it arrived at, the address it came from, and headers it must or must not carry. All of
it is declared in the Context annotation, except `require`, which is a directive.

## Authorities

One application can be served on several domains. An *authority* is the application's own name for
one of them:

```yaml
# context.toa.yaml
exposition:
  authorities:
    store: store.example.com
    partners: partners.example.com
```

Keys are authority identifiers, values are host names as they arrive in the request's `host`
header. `authorities` is the one required key of the annotation; an application on a single domain
declares one.

A value can differ per environment by suffixing the key:

```yaml
exposition:
  authorities:
    store: store.example.com
    store@staging: store.example.dev
```

The host of a request is lowercased and looked up among the values. A host that is not declared is
still served, and its authority identifier is the host name itself. A `host` that is not a host
name (or a bracketed IPv6 address), with an optional port, is answered `400 Bad Request`.

### Identities belong to an authority

Credentials are stored and issued per authority:

- A username under `store` and the same username under `partners` are different credentials, and
  may belong to different identities. Each may be created; a duplicate within one authority is
  `409`.
- A `Token` issued under one authority is `401` under another.
- A provider's token presented under two authorities resolves to two identities.
- One-time passwords and passkeys are bound to the authority they were issued or registered in.

So a customer of the shop and a partner are separate populations even when a person uses the same
email for both. The principal, likewise, is named
[with its authority](2.credentials.md#the-principal).

**Do not rename an authority identifier once it has users.** Stored credentials and issued tokens
refer to the identifier; changing `store` to `shop` orphans all of them. Changing the host name
behind an identifier is safe.

### Passing the authority to an operation

When an operation needs to know which domain was asked, map it into the input:

```yaml
# components/store.catalog/manifest.toa.yaml
exposition:
  /:
    GET:
      auth:anonymous: true
      map:authority: authority
      endpoint: enumerate
```

The value of [`map:authority`](../gateway/7.mapping.md#the-host) is the input property that receives
the identifier (`store`, not `store.example.com`). For an undeclared host it receives the host name.
Operations that call the identity components, such as
[issuing a one-time password](5.passwordless.md#issuing-a-code), get the `authority` they must pass
this way.

## The client address

In production the gateway sits behind a load balancer, an ingress or a CDN, so every connection
comes from that machine. The address of the actual client is in a header the edge writes. Name it:

```yaml
# context.toa.yaml
exposition:
  ip: cf-connecting-ip
```

Use the header your edge **overwrites**: `CF-Connecting-IP`, `X-Real-IP`, `X-Forwarded-For`,
depending on the infrastructure. A client can send any of these itself, so the choice matters:
name a header the edge does not control and clients choose their own address. Where the header
holds a list, the last value is taken, the one the edge appended.

The address of the connection is never used. Without `ip`, or for a request that lacks the header,
the request has no address, and whatever is keyed on the address lets it through. The gateway
notes this in its log.

Two things read the address:

- the [counter of failed authentications](2.credentials.md#failed-attempts), `bouncer`, which
  cannot be declared without `ip`;
- request throttling keyed on `ip`, described in [Input and Output](../gateway/6.io.md#throttling).
  The gateway's own token and client registration endpoints are throttled this way, see
  [OAuth](9.oauth.md#limits).

## Refusing by header: `censor`

Some requests must be refused wherever they are aimed, typically by country, which a CDN reports
in a header.

```yaml
# context.toa.yaml
exposition:
  censor:
    header: cf-ipcountry
    values: [KP, SY]
```

A request whose `header` holds one of `values` is answered:

```http
451 Unavailable For Legal Reasons
```

with an empty body, whatever its path. It is refused before routing and authentication, and no
operation is called.

- The header name matches in any case. A value matches exactly: `kp` is not `KP`.
- A request without the header, or with a value not listed, is served.
- Both keys are required; `values` has at least one entry.
- The reply carries CORS headers and the preflight is answered, so a page in a browser can read
  the status and show a message.
- The header is taken as it arrives. As with `ip`, it is only as trustworthy as the edge that
  writes it: a client reaching the gateway around the edge sends what it likes.

## Requiring headers: `require`

The `require` directives make a route insist on request headers. They are declared on the tree,
like `auth`:

```yaml
# components/store.orders/manifest.toa.yaml
exposition:
  /:customer/:order:
    auth:id: customer
    require:header: if-match
    PUT: transit
```

```http
PUT /store/orders/2428c31ecb6e4a51a24ef52f0c4181b9/7d1a…/ HTTP/1.1
host: store.example.com
authorization: Token eyJhbGciOiJkaXIi...
content-type: application/yaml

status: cancelled
```

```http
400 Bad Request

Header required: if-match
```

Here it forces clients to say which version of the order they are changing, so that concurrent
edits cannot silently overwrite each other. `require:headers` takes a list:

```yaml
require:headers: [if-match, if-unmodified-since]
```

## Annotation keys in this article

| Key | Value | Default |
| --- | --- | --- |
| `authorities` | Map of authority identifier to host. Required. | |
| `ip` | Name of the header holding the client address. | none: requests have no address |
| `bouncer` | `attempts`, `interval`; see [failed attempts](2.credentials.md#failed-attempts). Requires `ip`. | off |
| `censor` | `header` and `values`. | off |
