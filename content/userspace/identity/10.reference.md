# Identity Reference

Everything from this chapter in one place: the resources the gateway serves, the settings and
secrets behind them, and the statuses a client meets. Each entry links to where it is taught.

## Resources

All of these exist in every application. `:identity` is an identity id. "Self" means credentials
of the identity in the path.

### Identity

| Request | Does | Access |
| --- | --- | --- |
| `GET /identity/` | [Answers the caller's identity](1.identities.md#asking-who-you-are); creates a transient one without credentials. | anyone |
| `POST /identity/` | [Creates an identity](1.identities.md#an-identity-without-an-entity) for new credentials. | no identity yet |
| `GET /identity/credentials/:identity/` | [Lists stored credentials](2.credentials.md#listing-credentials). | self |

### Basic credentials

### OAuth

Served only with the `oauth` annotation.

| Request | Does | Access |
| --- | --- | --- |
| `GET /.well-known/oauth-authorization-server` | [Server metadata](9.oauth.md#discovery). Also at `/.well-known/openid-configuration`. | public |
| `GET /.well-known/oauth-protected-resource[/path]` | Protected resource metadata. | public |
| `POST /identity/clients/` | [Registers a client](9.oauth.md#registration). | no credentials |

## Secrets

Values that must not be written into the Context. Each is given as a `$NAME` reference and deployed
separately; [Configuration](../services/2.configuration.md#secrets) describes how.

| Setting | What it is |
| --- | --- |
| `identity.tokens.keys[].key` | Token encryption key, generated with `toa key`. At least one is required. |
| `identity.basic.pepper` | Password hashing pepper. |
| `identity.federation.trust[].secret` | A provider's client secret. |
| `identity.federation.trust[].signature.key` | A provider's private key for client assertions, PKCS8 PEM. |

```yaml
# context.toa.yaml
configuration:
  identity.tokens:
    keys:
      - id: 2026q4
        key: $IDENTITY_TOKENS_KEY
  identity.basic:
    pepper: $IDENTITY_BASIC_PEPPER
    principal:
      authority: store
      username: root
  identity.federation:
    trust:
      - iss: https://accounts.google.com
        aud: 1045282659797-example.apps.googleusercontent.com
        secret: $GOOGLE_CLIENT_SECRET
```

## Statuses

What a client of the application has to handle.

| Status | Meaning | What to do |
| --- | --- | --- |
| `401 Unauthorized` | The request has no identity and the route needs one: no credentials, or credentials that are wrong, expired, revoked, banned, from another authority, or of an unknown scheme. Also an OAuth token used outside its resource. | Sign in again. |
| `403 Forbidden` | The identity is known and not admitted: no directive grants, a custom token's permissions exclude the request, the wrong scheme for an `auth:scheme` route, an unauthorized input property, credentials sent to an anonymous route, or inception with credentials that already have an identity. | Do not retry as is. |
| `422 Unprocessable Entity` | An identity component refused with a code: `INVALID_USERNAME`, `INVALID_PASSWORD`, `INVALID_CREDENTIALS`, `EXISTS`, `PRINCIPAL_LOCKED`, `INACCESSIBLE_SCOPE`, `UNKNOWN_CLIENT`, `FAILED`, `INVALID`, `MISS`, or a federation code. | Read `code`. |
| `409 Conflict` | The username is taken. | Choose another. |
| `429 Too Many Requests` | Too many failed authentications from this address, or a throttled endpoint. | Wait `retry-after` seconds. |
| `451 Unavailable For Legal Reasons` | The request matched `censor`. | Nothing. |
| `400 Bad Request` | A malformed `host`, a missing required header, a non-object body where `auth:delegate` applies, or an OAuth error with `error` and `error_description`. | Fix the request. |

The body of a `401` or `403` does not say which reason applied, beyond the two texts quoted in
[Access](6.access.md). The reason for a rejected credential is in the gateway's log.

Alongside every successful status: **a response may carry an `authorization` header, and the client
must switch to the token in it.**
