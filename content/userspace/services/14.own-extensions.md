# Extensions of Your Own

The supplied extensions and connectors use a public interface, and an application can add its
own: an aspect that wraps an internal system so that every component can declare its use, or a
storage for a database the platform does not supply. The model article
[Extensions](../../model/platform/1.extensions.md#the-same-mechanism-for-everyone) explains why
this is the place for a platform concern the runtime does not address.

It is an advanced topic; most applications never need it.

## An aspect

Suppose several components of the shop need the warehouse's inventory system, reached through a
client library. Instead of each component creating a client, an extension provides it as an
aspect.

An extension is a package that exports a `Factory`. Its `aspect` method is asked once for each
component that declares the extension, and returns what goes on that component's context:

```javascript
// extensions/warehouse/index.js
import { Connector } from '@toa.io/core'
import { connect } from 'warehouse-client'

export class Factory {
  aspect (locator, declaration) {
    return new Warehouse(declaration)
  }
}

class Warehouse extends Connector {
  name = 'warehouse'

  #declaration
  #client

  constructor (declaration) {
    super()

    this.#declaration = declaration
  }

  async open () {
    this.#client = await connect(process.env.WAREHOUSE_URL, this.#declaration)
  }

  async close () {
    await this.#client.disconnect()
  }

  invoke (method, ...args) {
    return this.#client[method](...args)
  }
}
```

```json
{
  "name": "warehouse",
  "version": "0.0.0",
  "private": true,
  "type": "module"
}
```

- `locator` identifies the component the aspect is for (`locator.namespace`, `locator.name`,
  `locator.id`); `declaration` is what the component wrote under the extension's key.
- `name` is the key the aspect takes on the context. Two aspects with the same name in one
  component stop it from starting.
- `aspect` may return several aspects as an array.
- `open` and `close` are called as the component connects and disconnects. **Do not touch the
  outside world before `open`**: no connections and no I/O in constructors.

### Declaring it in a component

A component names the extension under `extensions` in its manifest, by a path relative to the
manifest or by a package reference. The value is the declaration handed to the factory:

```yaml
# components/store.catalog/manifest.toa.yaml
name: catalog
namespace: store

extensions:
  ../../extensions/warehouse:
    region: eu
```

### Using it in an operation

The aspect is called through `context.aspects`, under its name. The arguments are passed to
`invoke`, and what `invoke` returns is returned:

```javascript
// components/store.catalog/operations/stock.js
export async function computation (input, context) {
  return await context.aspects.warehouse('available', input.product)
}
```

## Checking the declaration

An extension can validate and normalize what components declare by exporting a `manifest`
function beside its `Factory`. It receives the declaration and the component's manifest, and
returns the declaration to use:

```javascript
// extensions/warehouse/index.js
export function manifest (declaration, manifest) {
  if (declaration?.region === undefined)
    throw new Error(`Component '${manifest.name}' declares no warehouse region`)

  return declaration
}
```

It runs when manifests are read, so a wrong declaration stops a deployment before anything is
built. It must return a value; returning `undefined` is an error:

```text
Extension '../../extensions/warehouse' hasn't returned manifest
```

## The Context annotation and deployment

An extension receives its part of the Context through a `deployment` function. It is given the
components that declare the extension and the annotation, and answers what a deployment needs,
such as environment variables:

```javascript
// extensions/warehouse/index.js
export function deployment (instances, annotation) {
  return {
    variables: {
      global: [{ name: 'WAREHOUSE_URL', value: annotation }]
    }
  }
}
```

The annotation is written in the Context under `annotations`, keyed by the package's name:

```yaml
# context.toa.yaml
annotations:
  warehouse: https://warehouse.internal
  warehouse@local: http://localhost:9000
```

Variables declared this way are written by
[`toa env`](../running/2.environments.md#the-local-environment) for local runs and set on the
workloads of a deployment, which is how the aspect above finds `WAREHOUSE_URL` in its `open`.

## What else a factory can provide

`Factory` methods are all optional. Besides `aspect`:

| Method | Provides |
| --- | --- |
| `tenant(locator, declaration, manifest)` | Something that runs beside each component that declares the extension, without being on its context. |
| `service()` | A process of the extension's own, run beside the application's components. `null` where it is off. |
| `resident(host)` | Something the extension keeps in every process, whatever that process runs. `null` where it keeps nothing. |

Whatever these return follows the same rule as an aspect: it connects in `open`, releases in
`close`, and does nothing before `open`.

### Going quiet

A deployment can be [halted](../running/11.halt.md), and a halt begins by taking every process
quiet: it keeps everything it holds open and stops everything it does of its own accord. A part of
an extension that acts on its own timing, a timer or a poll, says how to stop and resume by
overriding `pause` and `unpause`:

```javascript
class Poller extends Connector {
  pause () {
    clearTimeout(this.timer)
  }

  unpause () {
    this.arm()
  }
}
```

**Whatever makes a call on its own timing belongs in `pause`.** Connections stay open through a
quiet period; `unpause` alone undoes it, and nothing is rebuilt.

### Services and ports

A service that listens picks a port the platform does not use. Ports `8000` to `8005` are taken;
see [Extensions](1.extensions.md#ports-taken-by-extension-services).

### Residents

What `resident` returns lives as long as the process: it connects before the rest of the process
is built and goes down after it. It may have a `complete()` method, called when everything the
process was built with has connected. A resident survives a halt.

## A storage of your own

A storage connector is a package too. A component names it in its entity declaration, by path or
package reference:

```yaml
# components/store.orders/manifest.toa.yaml
entity:
  storage: ./storage
  properties:
    customer: { type: string }
```

The package exports a `Factory` whose `storage` method returns the storage for a component, and
may export `deployment` exactly as an extension does:

```javascript
// components/store.orders/storage/index.js
export class Factory {
  storage (locator, entity) {
    return new Storage(locator, entity)
  }
}

export function deployment (instances, annotation) {
  return {
    variables: {
      global: [{ name: 'ORDERS_DATABASE', value: annotation }]
    }
  }
}
```

```yaml
# context.toa.yaml
annotations:
  orders-storage: postgres://db.example.com
```

where `orders-storage` is the `name` in the storage's `package.json`.

Features that rely on particular guarantees of a storage, such as
[committed events](../reliability/2.committed-events.md), [`once`](../reliability/3.idempotency.md),
transitions over a set and [collection streams](../flow/4.collection-streams.md), are available only
where the storage provides them; see
[Connectors](12.connectors.md#what-a-storage-must-be-able-to-do). Migrations are applied by the
MongoDB storage only.

## Keeping deployment light

Commands that only read declarations, such as a deployment or type generation, load an
extension's package to call `manifest` and `deployment`. If the package's entry pulls in heavy
dependencies, ship a `definition.js` beside it that exports those functions on their own; it is
read instead of the entry, and what the extension runs is not loaded.
