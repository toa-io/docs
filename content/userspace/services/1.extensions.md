# Extensions

Everything in this chapter is provided by an *extension* or a *connector*: a package that adds a
capability to the platform, which a component uses by declaring it. The model article
[Extensions](../../model/platform/1.extensions.md) explains what they are; this one shows the two
places you write something for them.

## Using an extension from a component

A component asks for an extension with a top-level key in its manifest, named after the extension.
The smallest declaration has no value at all:

```yaml
# components/store.catalog/manifest.toa.yaml
name: catalog
namespace: store

stash: ~
```

That is enough for the operations of `store.catalog` to find the extension on their context:

```javascript
// components/store.catalog/operations/price.js
export async function computation (input, context) {
  return await context.stash.get(input.product)
}
```

What an extension puts on the operation context is called an *aspect*. Most extensions take a
declaration with content rather than `~`; the content is the extension's own and is described in
its article:

```yaml
# components/store.orders/manifest.toa.yaml
configuration:
  schema:
    properties:
      limit: { type: integer }
  defaults:
    limit: 5000
```

A manifest that declares something the extension does not accept is refused when the manifest is
read, before anything starts.

### Extensions every component has

Three extensions are present in every component without a declaration:

| Extension | On the context |
| --- | --- |
| Telemetry | `context.logs`, `context.span`, `context.metrics` |
| Fetch | `context.fetch` |
| Introspection | nothing; the component appears in the topology |

A component still writes a `telemetry` or `introspection` key when it has something to say to
them: the metrics it records, or that it wants to be left out of the topology.

`context.atom` is also there for every component. It is provided by a connector, not an
extension, and has no manifest key at all.

## Setting an extension up in the Context

How an extension is set up for the whole application is written in `context.toa.yaml`, under the
same key. These declarations are called *annotations*:

```yaml
# context.toa.yaml
name: store

stash: redis://redis.example.com

telemetry:
  logs:
    level: info
```

The manifest says the component uses a cache; the Context says where the cache is. A component
never reads an address.

### Values per environment

Any key of the Context can be given for one environment by appending `@` and the environment's
name. The plain key is what every other environment takes:

```yaml
# context.toa.yaml
stash@local: redis://localhost:6379
stash@production: redis://redis.internal:6379

telemetry:
  logs:
    level: debug
    level@production: info
```

The suffix works at any depth of an annotation, on a key that holds a value or a whole block.
Environments themselves are the subject of [Environments](../running/2.environments.md).

## The full form

The short keys are shortcuts. A manifest groups its extensions under `extensions`, keyed by
package reference, and a Context groups its annotations under `annotations`:

```yaml
# components/store.catalog/manifest.toa.yaml
extensions:
  '@toa.io/extensions.stash': ~
```

```yaml
# context.toa.yaml
annotations:
  '@toa.io/extensions.stash': redis://redis.example.com
```

You need the full form only for an extension that has no shortcut, which means one of your own:
see [Extensions of Your Own](14.own-extensions.md).

## Ports taken by extension services

Some extensions run a process of their own, a *service*, and each service that listens takes a
fixed port. Avoid them for anything you run in the same process:

| Port | Taken by |
| --- | --- |
| `8000` | the gateway |
| `8001` | the readiness probe of a composition |
| `8002` | the introspection UI |
| `8003` | the configuration UI |
| `8004` | the readiness probe of the gateway |
| `8005` | streamed calls to a component |

Two services that claim the same port in one process are refused when the deployment is exported:

```text
Port 8001 is claimed by both the readiness probe and the readiness probe of 'exposition-gateway'
```
