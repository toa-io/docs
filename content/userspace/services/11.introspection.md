# Introspection

Introspection collects the *topology* of the running application: its components, what they
declare, and which of them actually call each other. It is on for every component without a
declaration. The model article [Introspection](../../model/platform/4.introspection.md) explains
what the topology is for.

## What you get without doing anything

With the gateway deployed, the topology is published in two forms on the application's hosts:

- a page at `/.introspection/`, which draws the graph;
- an HTTP API under `/introspection/`, which the page reads and which you can query.

Both need the `system:introspection` role ([Roles and Bans](../identity/7.roles.md#system-scopes)).

**Introspection needs the gateway**, which publishes its API. An application that does not use
the gateway has to turn introspection off:

```yaml
# context.toa.yaml
introspection: false
```

## What the topology contains

**Nodes** are components, described from their manifests when a composition starts:

```yaml
namespace: store
component: orders
entity:
  storage: '@toa.io/storages.mongodb'
  schema:
    properties:
      customer: { type: string }
      total: { type: integer }
operations:
  - endpoint: approve
    type: transition
    scope: entry
    input: …
    output: …
events:
  - label: created
  - label: approved
receivers:
  - label: store.accounts.credited
    source: store.accounts
    event: credited
    operation: reconcile
```

An operation's `description` from the manifest is carried along, so it is worth writing one:

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  approve:
    description: Debits the customer's account and marks the order approved.
```

Event relations between components are known exactly from receivers and need no traffic to
appear.

**Edges** are calls observed while the application runs. Calls are made from code and no manifest
lists them, so an edge appears once the call has happened:

```yaml
src:
  namespace: store
  component: orders
  operation: approve
dst:
  namespace: store
  component: accounts
  operation: debit
```

The source of an edge is one of:

| `src` | The call was made by |
| --- | --- |
| `namespace`, `component`, `operation` | an operation of a component |
| `namespace`, `component`, `event` | the delivery of that event to a receiver |
| `service` | a service, such as the gateway or the command line; `unknown` for a caller that did not identify itself |

A local call and a remote one are recorded the same way. A call is an edge whether the operation
replied, returned an error or threw.

**An edge is the pair it connects and nothing else.** Inputs, replies and anything else the
application passes between its components are not collected.

## Leaving a component out

A component is excluded from the topology in its manifest:

```yaml
# components/store.accounts/manifest.toa.yaml
introspection: false
```

It is then not described as a node, and calls to it produce no edges.

## The page

The page is published at `/.introspection/` on the hosts the Context declares for ingress, and
the service behind it listens on port `8002`:

```yaml
# context.toa.yaml
ingress:
  hosts:
    - api.example.com
```

```text
https://api.example.com/.introspection/
```

The host has to be one the gateway serves too, because the page reads the API on its own origin.
The page itself is public, but shows nothing without an API session that has the
`system:introspection` role.

To collect the topology without publishing the page:

```yaml
# context.toa.yaml
introspection:
  ui: false
```

## The API

```http
GET /introspection/nodes/ HTTP/1.1
host: api.example.com
authorization: Token ...
accept: application/yaml
```

```yaml
- id: f5f5f72d2495c71128a41f810a199452
  namespace: store
  component: orders
  version: 7bb04bba
```

| Request | Answers |
| --- | --- |
| `GET /introspection/nodes/` | every node |
| `GET /introspection/nodes/:id/` | one node, with what it declares |
| `GET /introspection/edges/` | every observed edge; `[]` when nothing has been called |
| `GET /introspection/edges/:id/` | one edge |

## The Context annotation

All keys are optional:

```yaml
# context.toa.yaml
introspection:
  interval: 300
  threshold: 1024
  ui: true
  halt: false
  resources:
    cpu: [100m, 500m]
    memory: [128Mi, 256Mi]
```

| Key | Default | |
| --- | --- | --- |
| `interval` | `300` | Seconds between updates of the topology with newly observed calls. |
| `threshold` | `1024` | The number of distinct observed interactions that triggers an update before the interval ends. |
| `ui` | `true` | Publishes the page. |
| `halt` | `false` | Accepts halt signals, which stop the whole deployment: `true`, or bounds for what a signal may ask. See [Halt](../running/11.halt.md#enabling). |
| `resources` | the Context's `resources` | What the introspection service may take in a deployment: a pair of request and limit for `cpu` and for `memory`. `resources: ~` deploys it without any. |

Observed calls are reported in batches, so a new edge appears within `interval` seconds of the
first call, not at once. Lower `interval` in an environment where you want to watch the graph
form:

```yaml
introspection:
  interval@local: 5
```

## Using it

- **To learn or check the structure.** The graph shows the application as it is, not as a diagram
  drawn some time ago says it is.
- **To find a cycle before it closes.** Event subscriptions that could form a circle are visible
  as declared relations, before any call chain is refused at run time.
- **To decide on compositions.** Components with many edges between them are candidates for
  sharing a composition.
- **To see what is unused.** A declared relation with no observed edge, in an environment with
  real traffic, never fires.
