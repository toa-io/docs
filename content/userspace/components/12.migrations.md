# Migrations

Indexes and changes to stored data are declared as *migrations*: files in the component's
`migrations` directory, applied automatically when the component starts.

## Indexes

```yaml
# components/store.orders/migrations/0001-indexes.yaml
- index:
    name: index_customer
    keys: { customer: asc, CREATED: desc }
```

A file is a list of steps, applied in order. The file name without its extension is the
migration's id, and migrations are applied in the order their ids sort — so number them:

```
migrations/
  0001-indexes.yaml
  0002-note-defaults.yaml
```

An index should exist for every query the application makes often: the properties its `criteria`
filter on, followed by those it sorts by.

| `index` field | |
| --- | --- |
| `name` | The index's name. |
| `keys` | Properties, each `asc`, `desc`, `hash` or `text`. |
| `unique` | `true` to refuse a second object with the same keys. |
| `sparse` | `true` to index only objects that have the property. |
| `partial` | A filter; only matching objects are indexed. |
| `ttl` | Seconds after the moment in the key at which the object is removed. |

A `text` index is what a query's `search` uses.

To change an index, edit its declaration in a **new** migration: an index whose name is taken by
one of another shape is dropped and made again. To remove one:

```yaml
- dropIndex:
    name: index_customer
```

### Unique indexes and deleted objects

A deleted object stays in storage, and so keeps its place in a unique index: the value could
never be used again. Leave deleted objects out of the index:

```yaml
- index:
    name: unique_number
    keys: { number: asc }
    unique: true
    partial: { DELETED: null }
```

The same filter keeps any index smaller.

### Expiry

A `ttl` index removes objects some time after a [moment](1.manifest.md#moments) they hold. The
system timestamps are moments, so a retention policy for deleted objects needs no property of its
own:

```yaml
- index:
    name: index_deleted
    keys: { DELETED: asc }
    ttl: 2592000 # thirty days after deletion
```

Live objects have `DELETED: null` and are never removed by it.

## Changing data

```yaml
# components/store.orders/migrations/0002-note-defaults.yaml
- update:
    filter: { note: { $exists: false } }
    update: { $set: { note: '' } }
```

| Step | Fields |
| --- | --- |
| `update` | `filter`, and `update` — an object, or a list to run as an aggregation pipeline. |
| `delete` | `filter`; `{}` means every object. |
| `images` | `true` to keep what an object was before each change, which [reading only what changed](../flow/4.collection-streams.md) needs; `false` to stop. |

Steps are written in MongoDB's own dialect. A pipeline can compute from existing values — which
is how a property is converted when a moment format is added to it:

```yaml
- update:
    filter: { expires: { $type: number } }
    update:
      - $set: { expires: { $toDate: { $toLong: '$expires' } } }
```

## The rules

**Applied once per database** — not per replica, not per start — and never again. An index
dropped by hand is not recreated; write another migration. **Never edit a migration that has
been applied**; add a new one.

**Must be idempotent.** A replica that dies while applying a migration leaves it to another,
which applies it again from its first step.

**Runs before the component serves**, and every replica waits for it. A long backfill over a
large collection does not belong here: make it an operation that something calls.

**Lands while the previous release is still serving.** In a rolling update, the first new
replica applies the migration while old replicas go on reading the collection. If the old code
can read what the migration leaves, nothing more is needed. If it cannot — a rename, a property
that changes meaning — stop the deployment first; see [Halt](../running/11.halt.md).

**Inherited.** A [prototype](5.prototype.md#a-prototype-of-your-own)'s migrations are applied
ahead of the component's own.

**MongoDB only.** A component that declares migrations for another storage does not start:

```
Component 'store.orders' declares migrations, which storage '@toa.io/storages.null' does not apply
```
