# Guards

The entity schema says what a valid object is. A *guard* says what a valid **change** is: a
total that never grows after approval, a status that never leaves `cancelled`. It is written
once and holds for every operation of the component, inherited ones included.

## Writing a guard

A guard is a file in the component's `guards` directory that exports `guard`:

```javascript
// components/store.orders/guards/final.js
export function guard (order, origin) {
  return origin?.status !== 'cancelled' || order.status === 'cancelled'
}
```

| Argument | |
| --- | --- |
| first | The state about to be stored. |
| `origin` | The state it replaces; `null` for a new object. |
| `context` | The [operation context](8.context.md). |

Return `true` to let the change through. Nothing is declared in the manifest.

Every guard of the component is checked before each write. They are synchronous: a guard decides
from the two states it is given.

## When a guard refuses

The change is not stored, and the call fails with an exception that names the guard. Over HTTP it
is a `500`.

**A guard is a safety net, not a way to answer callers.** A refusal a caller should expect is an
[error](3.errors.md) returned by the operation:

```javascript
// operations/reopen.js
export async function transition (input, entry) {
  if (entry.status === 'cancelled')
    return new Error('CANCELLED')

  entry.status = 'pending'
}
```

The guard is what still holds when somebody adds another operation next year and forgets the
check — or calls `transit` directly.

## Guard or schema

| The rule is about | Put it in |
| --- | --- |
| one property's shape or range | the entity schema |
| several properties of one state: `held <= balance` | a guard |
| the state before and after: `total` only decreases | a guard |
| who may do it, or anything outside the object | the operation |
