# The Operation Context

The last argument of every operation is its *context*: the only way an operation reaches
anything outside itself. [Context](../../model/basics/6.context.md) explains why there is one
door.

```javascript
export async function transition (input, entry, context) { /* … */ }
export async function computation (input, context) { /* … */ }
```

## Calls

| | |
| --- | --- |
| `context.local.<operation>(request)` | Calls an operation of the same component. |
| `context.remote.<namespace>.<name>.<operation>(request)` | Calls an operation of another component. |

See [Requests](4.requests.md).

## Ids, time and randomness

| | |
| --- | --- |
| `context.id()` | A new id, of the same form as an entity's. |
| `context.now()` | Milliseconds since the epoch, as `Date.now()`. |
| `context.random()` | A number in `[0, 1)`, as `Math.random()`. |

**Use these instead of `Date.now()`, `Math.random()` and id generators.** An operation that is
[continued](../reliability/5.continuity.md) after a failure is given the same answers on its
later attempt; a value taken elsewhere would differ between the two.

## Where it runs

| | |
| --- | --- |
| `context.name` | The name of the application, as in the Context. |
| `context.env` | The environment it was deployed as. |
| `context.region` | The rank of the region; `0` unless there are [several](../running/10.regions.md). |
| `context.instance` | The name of this process, for [stateful operations](../flow/6.stateful.md). |

Prefer [configuration](../services/2.configuration.md) to branching on `context.env`.

## What extensions add

The rest of the context comes from extensions. Some are there for every component, others once
the manifest declares them.

| | From | Declared by | Covered in |
| --- | --- | --- | --- |
| `context.configuration` | configuration | `configuration:` | [Configuration](../services/2.configuration.md) |
| `context.fetch()` | fetch | — | [Fetch](../services/4.fetch.md) |
| `context.logs`, `context.metrics`, `context.span` | telemetry | — | [Telemetry](../services/7.logs.md) |
| `context.stash` | stash | `stash:` | [Stash](../services/5.stash-and-state.md) |
| `context.state` | state | `state:` | [Lifecycle](10.lifecycle.md) |
| `context.storages` | storages | `storages:` | [Files](../gateway/10.storages.md) |
| `context.delay()` | cadence | `cadence:` | [Cadence](../flow/3.delays.md) |
| `context.atom` | atomicity | — | [Shared Decisions](../services/6.shared-decisions.md) |

```yaml
# components/store.orders/manifest.toa.yaml
configuration:
  schema:
    type: object
    properties:
      limit: { type: integer }
  defaults:
    limit: 100000
```

```javascript
export async function transition (input, entry, context) {
  if (entry.total > context.configuration.limit)
    return new Error('LIMIT_EXCEEDED')

  // …
}
```

## Keeping the context

The context object lives as long as the component, and what it holds can change — configuration
may be updated while the component runs. Read from it when you need a value; do not copy values
out of it into module variables.

## Outside the context

An operation should reach the outside world through the context: that is what lets the runtime
trace, meter, secure and retry it. Reading a file that ships with the component or using a pure
library is fine. Opening connections, reading environment variables and keeping module-level
state are what the rules of a [genuine operation](2.operations.md#what-an-operation-must-be)
exclude.
