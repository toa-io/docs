# Prototype

A component inherits from a *prototype*: another component whose entity, operations and events
become its own. Unless told otherwise, every component that declares an entity inherits from the
*generic prototype*, which is where `transit`, `observe` and the rest come from.
[The Prototype](../../model/foundations/4.prototype.md) explains the idea.

## The operations

| Operation | Type | Scope | What it does |
| --- | --- | --- | --- |
| `transit` | transition | entry | Merges the input into the object and returns it. Creates one when called without a query. |
| `observe` | observation | entry | Returns the object, or `null`. |
| `enumerate` | observation | entries | Returns the list the query selects. |
| `stream` | observation | stream | Returns the selection as a stream. |
| `assign` | assignment | changeset | Sets the properties given in the input. |
| `terminate` | assignment | changeset | Marks the object deleted. |
| `ensure` | effect | entry | Returns the object matching the request's `entity`, creating it if there is none. |

```javascript
const order = await context.remote.store.orders.observe({ query: { id } })

const pending = await context.remote.store.orders.enumerate({
  query: { criteria: 'status==pending', sort: ['CREATED:desc'], limit: 50 }
})

await context.remote.store.orders.assign({ query: { id }, input: { note: 'gift' } })
await context.remote.store.orders.terminate({ query: { id } })
```

The entity schema still applies: `transit` and `assign` cannot store an invalid object, and
[guards](9.guards.md) apply to them as to any operation.

## The events

The generic prototype also gives every component three events:

| Event | Published when |
| --- | --- |
| `created` | an object is created |
| `updated` | an existing object is changed |
| `deleted` | an object is marked deleted |

Each carries the object's new state. Other components can
[receive](7.receivers.md) `store.orders.created` without `orders` declaring anything.

## Constraining an inherited operation

An inherited operation can be declared in the manifest to give it what the prototype could not
know. A declaration is merged with the inherited one:

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  transit:
    concurrency: retry
    input:
      type: object
      properties:
        note: { type: string, maxLength: 256 }
      additionalProperties: false
```

`transit` must be declared with a `concurrency` before it can be used to change existing
objects.

## Forwarding

`forward` gives an inherited implementation another name and a contract of its own:

```yaml
operations:
  add:
    forward: transit
    query: false
    input:
      type: object
      properties:
        customer: { type: string }
        total: { type: integer, minimum: 0 }
      required: [customer, total]

  annotate:
    forward: assign
    query: true
    input:
      type: object
      properties:
        note: { type: string, maxLength: 256 }
      additionalProperties: false
```

`add` creates an order from exactly these properties, `annotate` sets a note on an existing one,
and neither needed a file. Most of a typical component's write operations that carry no rules
are forwards with a narrow input.

## Replacing an inherited operation

A file in `operations` with the name of an inherited operation replaces its implementation:

```javascript
// components/store.orders/operations/terminate.js
export async function transition (input, entry, context) {
  if (entry.status === 'approved')
    return new Error('APPROVED')

  entry.DELETED = context.now()
}
```

Deletion is a write of `DELETED`, which is all `terminate` is.

## Going without

`prototype: null` inherits nothing: no operations, no events. A component that declares no
entity has no prototype to begin with.

```yaml
prototype: null
```

## A prototype of your own

Any component directory can be a prototype. Name it by path:

```yaml
# components/store.orders/manifest.toa.yaml
prototype: ../prototypes/auditable
```

The component inherits the prototype's entity properties, operations, events, extension
declarations and [migrations](12.migrations.md), and the prototype in turn inherits from its own
— the generic one unless it says otherwise. What the component declares itself wins over what it
inherits.

A prototype that declares migrations must have a `name`: its migrations are recorded under it.
