# Operations

An operation is one thing a component does: a function in a file, and optionally a declaration
in the manifest. This article covers how to write and declare one.

## A file is an operation

```javascript
// components/store.orders/operations/approve.js
export async function transition (input, entry, context) {
  entry.status = 'approved'

  return entry
}
```

The file name is the operation's name — its *endpoint*. The function receives:

1. **`input`** — the arguments the caller sent.
2. **state** — what the runtime retrieved for this call. Absent for operations without state.
3. **`context`** — the [operation context](8.context.md): calls to other operations,
   [configuration](../services/2.configuration.md), everything else the runtime provides.

What it returns is the reply.

Two things are read from the code, without running it:

- **The exported name is the operation's type**: `transition`, `observation`, `assignment`,
  `computation`, `effect` or `unmanaged`.
- **The name of the second parameter is its scope**: `entry`, `entries`, `changeset` or `stream`.

## Types

The type says what the operation does with state.

### Transition

Receives the current state, may change it, and the changed state is stored.

```javascript
// operations/cancel.js
export async function transition (input, entry) {
  if (entry.status !== 'pending')
    return new Error('NOT_PENDING')

  entry.status = 'cancelled'
}
```

Change the object you are given; do not replace it. Called without a query, a transition
receives a blank object and creates an entity; see [Requests](4.requests.md#creating).

A transition **may run more than once for one call** — when the state changed underneath it, or
when the call is delivered again — so it must come to the same decision each time it is given the
same state.

### Observation

Receives the current state and returns something derived from it. Nothing it changes is stored.

```javascript
// operations/summary.js
export async function observation (input, entry) {
  return { status: entry.status, total: entry.total }
}
```

### Assignment

Receives an empty *changeset* instead of the current state, and fills it with the values to set.
Properties left out are not touched.

```javascript
// operations/note.js
export async function assignment (input, changeset) {
  changeset.note = input.text
}
```

An assignment is cheaper than a transition — nothing is read — and cannot conflict with a
concurrent write. Use it when the new values follow from the input alone. If the decision
depends on the current state, it is a transition.

### Computation

Uses no state and has no side effects. It has no state parameter:

```javascript
// operations/quote.js
export async function computation (input, context) {
  return input.total * context.configuration.rate
}
```

### Effect

Does something beyond the component's own state: sends an email, calls an external API,
orchestrates calls to other components.

```javascript
// components/store.notifications/operations/receipt.js
export async function effect (input, context) {
  const order = await context.remote.store.orders.observe({ query: { id: input.order } })

  await context.fetch('https://mail.example.com/send', {
    method: 'POST',
    body: JSON.stringify({ to: order.customer, total: order.total })
  })
}
```

An effect has no state by default. Give it a second parameter named after a scope and it
receives state like an observation does:

```javascript
export async function effect (input, entry, context) { /* … */ }
```

The runtime cannot undo or deduplicate what an effect does outside the component. What that asks
of you is in [Delivery](../reliability/1.delivery.md).

### Unmanaged

Receives the storage's own client — for MongoDB, the collection — for reads the query model
cannot express:

```javascript
// operations/totals.js
export async function unmanaged (input, collection) {
  return await collection
    .aggregate([{ $group: { _id: '$status', total: { $sum: '$total' } } }])
    .toArray()
}
```

**An unmanaged operation reads. It never writes.** A write made here has no version, no
timestamps, no validation and no event, and is not replicated to other regions. Filter on
`DELETED: null` yourself: deleted objects are still in the collection.

### Summary

| Type | Receives | Stores changes | Safe |
| --- | --- | --- | --- |
| `transition` | current state | yes | no |
| `observation` | current state | no | yes |
| `assignment` | empty changeset | yes | no |
| `computation` | — | — | yes |
| `effect` | optionally, current state | no | no |
| `unmanaged` | the storage client | — | no |

A *safe* operation cannot change anything. A caller may demand that a call only reads, and such
a call is refused by an unsafe operation; see [Call Chains](../reliability/6.call-chains.md).

## Scopes

The scope is how much state the operation works on.

| Scope | Second parameter | The operation receives | Allowed for |
| --- | --- | --- | --- |
| `entry` | `entry` | one object | transition, observation, effect |
| `entries` | `entries` | an array of objects | transition, observation, effect |
| `stream` | `stream` | a stream of objects | observation, effect |
| `changeset` | `changeset` | an empty object to fill | assignment |
| `none` | — | nothing | computation, effect, unmanaged |

```javascript
// operations/pending.js
export async function observation (input, entries) {
  return entries.map((order) => ({ id: order.id, total: order.total }))
}
```

A transition over `entries` changes several objects as one unit: they are stored all or none. If
any of them changed since it was read, nothing is written, and the operation is run again or
fails, as its `concurrency` says.

```javascript
// operations/expire.js
export async function transition (input, entries) {
  for (const order of entries)
    order.status = 'cancelled'
}
```

`stream` is for collections too large to hold in memory; see
[Collection Streams](../flow/4.collection-streams.md).

## Declaring an operation

An operation that needs nothing beyond its file needs no declaration. The manifest adds what the
code does not say:

```yaml
# manifest.toa.yaml
operations:
  approve:
    description: Approves a pending order and charges the customer.
    concurrency: retry
    query: true
    input:
      type: object
      properties:
        note: { type: string, maxLength: 256 }
      additionalProperties: false
    output:
      type: object
      properties:
        id: { type: string }
        status: { type: string }
    errors: [NOT_PENDING, INSUFFICIENT_FUNDS]
```

### Input and output

`input` is the JSON Schema of the arguments. A request that does not fit is refused before the
function runs, so the function never checks shapes or types. An operation that declares no
`input` accepts none.

`output` is the JSON Schema of the reply. A reply that does not fit is the component's mistake,
not the caller's: the call fails with an exception. Declaring `output` is optional, and it is
what generated types, the gateway's descriptions and tools for models are built from.

Rules that depend on the current state — "only a pending order" — are not schema. They are the
operation's code.

### Concurrency

A transition over existing state must say what happens when the state was changed by someone
else between its read and its write:

| `concurrency` | On conflict |
| --- | --- |
| `retry` | The operation is run again on the fresh state. |
| `none` | The call fails with an exception. |

`retry` is right for nearly every transition. Only a transition declared `query: false` — one
that always creates — goes without `concurrency`.

### Query

| `query` | Meaning |
| --- | --- |
| *(not stated)* | A call may carry a query. |
| `true` | A call must carry one. |
| `false` | A call must not. For a transition: it always creates. |

### Description

`description` says what the operation is, for a reader. It appears above the endpoint in
[generated types](11.typescript.md#generated-types), in the gateway's description of its routes,
and in tools offered to models.

### Type and scope, stated

`type` and `scope` can be declared, and must be where the code cannot be read — a function
produced by another function has no parameter names:

```javascript
// operations/create.js
export const transition = withAudit(async (input, entry) => { /* … */ })
```

```yaml
operations:
  create:
    scope: entry
```

### All properties

| Property | Values | Covered in |
| --- | --- | --- |
| `description` | text | above |
| `type`, `scope` | see [Types](#types), [Scopes](#scopes) | above |
| `input`, `output` | JSON Schema | above |
| `errors` | list of codes | [Errors](3.errors.md) |
| `query` | `true`, `false` | above, [Requests](4.requests.md) |
| `concurrency` | `retry`, `none` | above |
| `forward` | an operation's name | [Prototype](5.prototype.md#forwarding) |
| `once` | `true`, or seconds | [Idempotency](../reliability/3.idempotency.md) |
| `unchained` | `true` | [Call Chains](../reliability/6.call-chains.md) |
| `stream` | an input property's name | [Streamed Calls](../flow/5.streamed-calls.md) |
| `stateful` | `true` | [Stateful Operations](../flow/6.stateful.md) |
| `bindings`, `bridge` | connector names | [Connectors](../services/12.connectors.md) |

## Other ways to write one

A function is the usual form. Two more exist for an operation that needs to prepare something
once.

A class named after the type, with an `execute` method. `mount` is called once, before the first
call:

```javascript
// operations/quote.js
export class Computation {
  #rates

  async mount (context) {
    this.#rates = await load(context)
  }

  execute (input) {
    return input.total * this.#rates[input.currency]
  }
}
```

A factory, named `<Scope><Type>Factory` — `EntryTransitionFactory`,
`EntriesObservationFactory`, `ChangesetAssignmentFactory` — whose `create` returns an object
with `execute`:

```javascript
export class EntryTransitionFactory {
  async create () {
    return new Approval()
  }
}
```

In either form, keep the reference to `context` rather than copying values out of it: what it
holds — configuration, for one — can change while the component runs.

## Modules and shared code

A component is written as ES modules or CommonJS. To use ES modules, put a `package.json` with
`"type": "module"` beside the manifest, or name the files `.mjs`. Operations can also be written
in [TypeScript](11.typescript.md).

Every file directly in `operations` is an operation. Code shared between operations lives in a
directory beside it or inside it — `lib/`, `operations/lib/` — not among the operation files:

```
store.orders/
  manifest.toa.yaml
  package.json
  operations/
    approve.js
    cancel.js
    lib/
      totals.js
```

A component's dependencies are its own: list them in its `package.json`.

## What an operation must be

The runtime retries, replicates and relocates operations. It can do so because an operation is:

1. **Stateless** — it keeps nothing between calls.
2. **Deterministic** — the same input and state give the same result. Take ids, time and
   randomness from the [context](8.context.md#ids-time-and-randomness).
3. **Autonomous** — it assumes nothing about where it runs.
4. **Pure** — its only effects are the state it changes and what it does through the context.
5. **Non-exceptional** — it does not throw to say no. See [Errors](3.errors.md).

[Operations](../../model/basics/3.operations.md#genuine-operations) in the mental model explains
what each rule buys.
