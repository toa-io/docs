# Events

An event announces that an object changed. An operation never publishes one: you declare what
kind of change is an event, and the runtime publishes it when such a change is stored.
[Events](../../model/basics/5.events.md) explains the model.

## Declaring an event

An event is a file in the component's `events` directory. The file name is the event's name, and
it exports a `condition`:

```javascript
// components/store.orders/events/approved.js
export function condition (event) {
  return event.origin?.status !== 'approved' && event.state.status === 'approved'
}
```

After every stored change of an order, the condition is called. Where it returns `true`,
`store.orders.approved` is published, carrying the order's new state. Nothing is added to the
manifest.

The argument describes the change:

| | |
| --- | --- |
| `state` | The object after the change. |
| `origin` | The object before it; `null` if it was just created. |
| `input` | The input of the operation that made the change. |
| `trailers` | What the operation left in `TRAILERS`; see [below](#trailers). |

The condition is evaluated for a change made by *any* operation — yours, inherited or forwarded.
That is the point: `approved` is published however the order became approved.

An event with no `condition` is published on every change.

The second argument is the [operation context](8.context.md), for a condition that depends on
[configuration](../services/2.configuration.md).

## Payload

By default the payload is the object's new state. Export `payload` to send something else:

```javascript
// components/store.orders/events/approved.js
export function condition (event) {
  return event.origin?.status !== 'approved' && event.state.status === 'approved'
}

export function payload (event) {
  return {
    id: event.state.id,
    customer: event.state.customer,
    total: event.state.total
  }
}
```

A narrow payload is a smaller promise to subscribers. Keep the `id`, and keep `VERSION` if
subscribers need to [tell a repeat](../reliability/1.delivery.md).

## Trailers

Sometimes an event needs something the operation knew and the state does not keep — who made the
change, or why. A transition writes it into `TRAILERS`:

```javascript
// components/store.orders/operations/cancel.js
export async function transition (input, entry) {
  if (entry.status !== 'pending')
    return new Error('NOT_PENDING')

  entry.status = 'cancelled'
  entry.TRAILERS.reason = input.reason
}
```

```javascript
// components/store.orders/events/cancelled.js
export function condition (event) {
  return event.origin?.status !== 'cancelled' && event.state.status === 'cancelled'
}

export function payload (event) {
  return { id: event.state.id, reason: event.trailers.reason }
}
```

`TRAILERS` is never stored with the object. Its values must be serializable. An assignment has no
object to hold trailers, so its events have none.

## Inherited events

The generic prototype declares `created`, `updated` and `deleted` for every component
([Prototype](5.prototype.md#the-events)). An event file of the same name replaces the inherited
one.

## What is published

An event is published only where something consumes it: a [receiver](7.receivers.md) in the same
application, or a line in the Context for consumers outside it:

```yaml
# context.toa.yaml
events:
  - store.orders.approved
```

Locally — `toa compose`, `toa mono`, tests — every event is published.

## What subscribers can rely on

An event and the change it announces are stored together: if the change is stored, the event
will be published, and an operation that returned an error or discarded its change publishes
nothing. Events are delivered **at least once** and **in no guaranteed order**.
[Committed Events](../reliability/2.committed-events.md) covers what that means for both sides.

## Writing conditions

- **Compare `origin` with `state`.** `state.status === 'approved'` alone is true on every later
  change of an approved order, and the event would be published each time.
- **`origin` is `null` for a new object.** Use `event.origin?.status`.
- **Keep it a pure function.** A condition that throws blocks the publication of every event of
  that change until it stops throwing.
