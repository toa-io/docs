# Lifecycle

Operations keep nothing between calls. What a component needs to set up once — a client of an
external service, a table loaded from a file, a subscription — is set up in *run commands*:
functions called at fixed moments of the component's life, outside any operation.

## Run commands

A module in the component's `rc` directory exports one or more of the commands:

```javascript
// components/store.notifications/rc/mailer.js
export async function preflight (context) {
  context.state.mailer = await connect(context.configuration.mail)
}

export async function dispose (context) {
  await context.state.mailer.close()
}
```

Each receives the [operation context](8.context.md). The file name is yours to choose; a
component may have several modules.

| Command | Called |
| --- | --- |
| `preflight` | On start, before any operation is served. |
| `settle` | On start, once the component can call its own operations through `context.local`. |
| `ready` | On start, once every operation is served and receivers are consuming. |
| `pause` | When the process is told to go quiet, while still whole and serving. |
| `resume` | When it is working again after going quiet without being stopped. |
| `dispose` | On stop, after the component has stopped serving. |

## Process memory

`context.state` is an object that lives as long as the component and is shared by its run
commands and operations. A component gets it by declaring the extension:

```yaml
# manifest.toa.yaml
state: ~
```

```javascript
// operations/receipt.js
export async function effect (input, context) {
  await context.state.mailer.send(input)
}
```

It is the memory of one process: every replica has its own, and it is gone on restart. It is the
right place for a client or a cache, and the wrong place for anything the application must
remember. See [State](../services/5.stash-and-state.md) for the alternatives.

## Releasing what you opened

`dispose` is the counterpart of `preflight`. During it the component can still call other
components, but nothing calls into it any more, so do not call its own operations.

**Anything left open holds the process.** A composition exits when its last handle is released:
a timer, a socket or a stream that `dispose` did not close keeps it alive, in production and in
tests alike.

## Announcing a process

`ready` is the moment to tell others the process exists. A process that serves
[stateful operations](../flow/6.stateful.md) hands out its name there, because a call addressed
to it before `ready` may be refused:

```javascript
// rc/register.js
export async function ready (context) {
  await context.remote.store.registry.register({ input: { instance: context.instance } })
}
```

`settle` and `ready` have no counterpart on stop.

## Going quiet

Before a deployment is [halted](../running/11.halt.md), every process is told to stop doing
anything of its own accord. The runtime quiets what it knows about. `pause` is where a component
does the same with what the runtime cannot see — an interval, a watcher, a subscription to
something outside:

```javascript
// rc/poller.js
export function preflight (context) {
  context.state.poller = setInterval(() => poll(context), 1000)
}

export function pause (context) {
  clearInterval(context.state.poller)
}

export const resume = preflight

export const dispose = pause
```

After `pause`, one of two things happens:

- The process is stopped and later started anew. `preflight` runs on the new component.
- The halt is called off. The component is the same one, with the same `context.state`, and
  only `resume` runs.

So `resume` must take again whatever `pause` released. **A component that exports `pause` and no
`resume` does not start.**

A component that keeps its own timer and does not release it in `pause` goes on making calls
while the deployment is supposed to be quiet, and that is what calls a halt off.
