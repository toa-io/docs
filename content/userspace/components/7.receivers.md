# Receivers

A receiver turns an event into a call to one of the component's own operations.

## Binding an event to an operation

```yaml
# components/store.notifications/manifest.toa.yaml
receivers:
  store.orders.approved: receipt
```

When `store.orders.approved` is published, `receipt` is called with the event's payload as its
input. The event is named `<namespace>.<component>.<event>`.

The publishing component knows nothing of this. Dependency points from the receiver to the
event.

## Adapting the event

The payload is rarely the request the operation expects. A file in `receivers`, named after the
event, exports `request` and builds it:

```javascript
// components/store.notifications/receivers/store.orders.approved.js
export function request (order) {
  return {
    input: { order: order.id, total: order.total }
  }
}
```

The returned request is like any other, so it can carry a query — which is how an event about
one object becomes a change of another:

```javascript
// components/store.loyalty/receivers/store.orders.approved.js
export function request (order) {
  return {
    query: { id: order.customer },
    input: { points: Math.floor(order.total / 100) }
  }
}
```

## Skipping events

Export `condition` to receive only some of the events:

```javascript
// components/store.loyalty/receivers/store.orders.approved.js
export function condition (order) {
  return order.total >= 1000
}

export function request (order) {
  return { query: { id: order.customer }, input: { points: 10 } }
}
```

Where it returns `false`, the event is done with and the operation is not called.

## One adapter for several events

`arguments` are passed to `request` and `condition` after the payload, so several receivers can
share logic that differs by a constant:

```yaml
receivers:
  store.orders.approved:
    operation: notify
    arguments: [approved]
  store.orders.cancelled:
    operation: notify
    arguments: [cancelled]
```

```javascript
// receivers/store.orders.approved.js
export function request (order, kind) {
  return { input: { order: order.id, kind } }
}
```

## Receiving your own events

A component may receive its own events. It is the way to continue work after a change is stored
without making the caller wait:

```yaml
# components/store.orders/manifest.toa.yaml
receivers:
  store.orders.created: reserve
```

## What a receiving operation must expect

Nobody waits for the reply of a call a receiver makes. Therefore:

- **A returned error ends it.** The event is done with. If the refusal must be visible, the
  operation writes it down.
- **An exception retries it.** The event is delivered again, with growing pauses, and is set
  aside for an operator if it keeps failing.
- **It may arrive more than once, and out of order.**

So the operation must leave the same state when given the same event twice:

```javascript
// applied twice, adds twice
entry.points += input.points

// applied twice, ends the same
entry.status = input.status
```

Where that is not natural, see [Delivery](../reliability/1.delivery.md) and
[Idempotency](../reliability/3.idempotency.md).

## Events from outside the application

An event published by another system has no component to be found by. State the binding and
where to consume it from:

```yaml
receivers:
  payment_settled:
    operation: settle
    binding: amqp
    source: payments
```

`source` names a broker declared in the Context; see
[Connectors](../services/12.connectors.md). A name in the `<namespace>.<component>.<event>` form
needs no `source`: it is `<namespace>.<component>`.

```yaml
receivers:
  billing.invoices.paid:
    operation: settle
    binding: amqp
```

## All properties

| Property | Meaning |
| --- | --- |
| `operation` | The operation to call. A receiver written as a string is this alone. |
| `arguments` | Values passed to `request` and `condition` after the payload. |
| `binding` | Where the event is consumed from; stated for events from outside. |
| `source` | The broker of an outside event, as named in the Context. |
| `bridge` | What runs the receiver's code; `node` by default. |
