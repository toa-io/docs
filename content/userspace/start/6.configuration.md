# Add Configuration

The shop refuses orders above a limit, and the limit is not the same everywhere: large in
production, small where the tests run. A value like that is *configuration*: the component
declares it, reads it from the operation context, and the Context sets it.

## Declare the value

```yaml
# components/store.orders/manifest.toa.yaml
configuration:
  schema:
    type: object
    properties:
      limit:
        type: integer
        minimum: 0
  defaults:
    limit: 5000
```

`schema` is a JSON Schema of the component's configuration; `defaults` is what the component runs
with unless the Context says otherwise.

## Read it

The rule needs code, so `create` stops forwarding and becomes an operation of its own:

```typescript
// components/store.orders/operations/create.ts
import type { Context, CreateInput, State } from '../types/index.d.ts'

export async function transition (input: CreateInput, entry: State, context: Context) {
  if (input.total > context.configuration.limit)
    return new Error('LIMIT_EXCEEDED')

  Object.assign(entry, input)

  return entry
}
```

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  create:
    query: false
    errors: [LIMIT_EXCEEDED]
    input:
      type: object
      properties:
        customer: { type: string }
        items: { type: array }
        total: { type: integer, minimum: 0 }
      required: [customer, items, total]
```

`context`, the last parameter of every operation, is the operation context.
`context.configuration` is the configuration object, already checked against the schema, so the
operation does not validate it. Never read an environment variable or a file for a setting.

Try it:

```shell
$ npm run env
$ toa mono ./components/*
```

```shell
$ curl -i http://localhost:8000/store/orders/ \
    -H 'content-type: application/json' \
    -d '{"customer":"c1","items":[],"total":7000}'
```

```http
HTTP/1.1 422 Unprocessable Entity
content-type: application/json

{"code":"LIMIT_EXCEEDED"}
```

A component that declares configuration gets it from a service that `toa mono` starts. Started
with `toa compose` alone it waits for that service; name it with
`toa compose ./components/* --service configuration`.

## Set the value in the Context

```yaml
# context.toa.yaml
configuration:
  identity.tokens:
    # …
  store.orders:
    limit: 100000
```

Values are given per component, by `<namespace>.<name>`. A value here stands over the manifest's
default; a default the Context does not mention stays.

The Context is read when `.env` is written, so write it again and restart:

```shell
$ npm run env
$ toa mono ./components/*
```

The same request now answers `201 Created`.

A key that names no component, or a component that declares no configuration, stops `toa env`:

```text
Component 'foo.bar' does not request configuration or does not exist.
```

## One value per environment

Append `@<environment>` to a key to give it a value for one environment only:

```yaml
# context.toa.yaml
configuration:
  store.orders:
    limit: 100000
    limit@local: 10000
```

`local` is the environment of your machine, the one `toa env` writes when no other is named. The
limit is `10000` there and `100000` in every other environment. An environment is not declared
anywhere; it is named on the command line:

```shell
$ toa env                              # local
$ toa env staging --as .env.staging    # another one, into another file
$ toa deploy production
```

The suffix works on any key of the Context, at any depth, which is how the addresses of the
[first article](1.application.md#the-context) get their production values:

```yaml
# context.toa.yaml
mongodb: mongodb://localhost
mongodb@production: mongodb://mongo.internal.example.com

exposition:
  authorities:
    shop: localhost:8000
    shop@production: api.store.example
```

The tests run in `local`, so they can rely on its limit:

```gherkin
# features/orders.feature
  Scenario: An order above the limit
    When the request is sent:
      """
      POST /store/orders/ HTTP/1.1
      content-type: application/yaml
      accept: application/yaml

      customer: c1
      items: []
      total: 10001
      """
    Then the response is received:
      """
      422 Unprocessable Entity

      code: LIMIT_EXCEEDED
      """
```

```shell
$ npm run env
$ npm run features
```

Everything about environments is in
[Give Each Environment Its Values](../shipping/2.environments.md).

## Secrets, and changing a value while running

A value that must not be stored with the sources, an API key for instance, is declared with
`format: secret`; the Context then holds only a `$NAME` reference, as it does for the key under
`identity.tokens`, and the value is supplied to each environment separately.
[Keep Settings and Secrets out of the Code](../platform/2.configuration.md) covers secrets,
nested values and everything else the manifest and the Context take. A value can also be changed
in a running application, without a deployment:
[Change a Setting without Redeploying](../platform/3.configuration-values.md).
