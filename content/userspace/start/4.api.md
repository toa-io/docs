# Expose It over HTTP

The shop's website has to list orders, show one, create one and approve one. A component serves no
HTTP itself: it declares which of its operations appear as HTTP resources, and the *gateway*, a
service of the runtime, serves them.

## Declare the resources

Add an `exposition` section to the manifest:

```yaml
# components/store.orders/manifest.toa.yaml
exposition:
  /:
    anonymous: true
    io:output: true
    GET: enumerate
    POST: create
    /:id:
      GET: observe
      PUT: approve
```

The component's routes are mounted under `/<namespace>/<name>`:

| Request | Calls |
| --- | --- |
| `GET /store/orders/` | `store.orders.enumerate` |
| `POST /store/orders/` | `store.orders.create`, with the body as input |
| `GET /store/orders/<id>/` | `store.orders.observe` of that order |
| `PUT /store/orders/<id>/` | `store.orders.approve` of that order |

- `:id` is a route variable; its value selects the order.
- `io:output: true` lets replies through. Without it a request succeeds with `204 No Content` and
  no body.
- `anonymous: true` lets anyone call these routes. Without an access rule a route answers
  `401 Unauthorized`.

Both are written once on `/` and apply to everything nested in it.

Opening the whole API to everyone is fine for a first run and for nothing else. Signing users in
starts at [Sign Users Up and In](../access/1.identities.md); the rules that say who may call what
are in [Restrict Who Can Call a Route](../access/6.access.md).

## Run the application

The [Context](1.application.md#the-context) already names the host the API is served on:

```yaml
# context.toa.yaml
exposition:
  authorities:
    shop: localhost:8000
```

`toa compose` starts components only. `toa mono` starts them together with every service they
need, the gateway among them, in one process:

```shell
$ toa map
$ toa mono ./components/*
```

```text
{"severity":"INFO","message":"Composition complete", … }
{"severity":"INFO","message":"HTTP Server is listening", … }
{"severity":"INFO","message":"Ready", … }
```

The gateway listens on port `8000`. From now on `toa mono` is the way to run the application
locally; `toa call` works with it as before.

## Send requests

Create an order:

```shell
$ curl -i http://localhost:8000/store/orders/ \
    -H 'content-type: application/json' \
    -d '{"customer":"c1","items":[{"product":"kettle","quantity":1}],"total":4200}'
```

```http
HTTP/1.1 201 Created
content-type: application/json

{"id":"01a10df7b5e47692b3c64a94cff78bfd","VERSION":1,"DELETED":null,"REGION":0,"status":"pending","CREATED":1791235700196,"UPDATED":1791235700196,"customer":"c1","items":[{"product":"kettle","quantity":1}],"total":4200}
```

Read it, this time as YAML. The gateway answers in the format the `accept` header asks for, and
reads bodies in the format `content-type` names:

```shell
$ curl -H 'accept: application/yaml' http://localhost:8000/store/orders/01a10df7b5e47692b3c64a94cff78bfd/
```

```yaml
VERSION: 1
DELETED: null
REGION: 0
status: pending
CREATED: 1791235700196
UPDATED: 1791235700196
customer: c1
items:
  - product: kettle
    quantity: 1
total: 4200
id: 01a10df7b5e47692b3c64a94cff78bfd
```

List the orders, then approve the one just created:

```shell
$ curl http://localhost:8000/store/orders/
$ curl -i -X PUT http://localhost:8000/store/orders/01a10df7b5e47692b3c64a94cff78bfd/
```

```http
HTTP/1.1 200 OK
content-type: application/json

{"VERSION":2, … "status":"approved", … }
```

## An error over HTTP

Approve the same order again. The error the operation returns is answered with `422` and the error
as the body:

```shell
$ curl -i -X PUT http://localhost:8000/store/orders/01a10df7b5e47692b3c64a94cff78bfd/
```

```http
HTTP/1.1 422 Unprocessable Entity
content-type: application/json

{"code":"NOT_PENDING"}
```

Other answers you will meet early:

| Status | When |
| --- | --- |
| `400 Bad Request` | The body does not fit the operation's `input`. The body of the response says why: `"must have required property 'total'"`. |
| `401 Unauthorized` | The route has no access rule that lets the caller in. |
| `404 Not Found` | There is no such order, or no such route. A path without the trailing slash is answered `"Trailing slash is required"`. |
| `405 Method Not Allowed` | The route does not declare the method. |
