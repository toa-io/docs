# Create a Component

The shop keeps orders. An order has a customer, items, a total and a status, and it may be
approved only while it is pending.

## Describe an order

A component starts with a manifest:

```yaml
# components/store.orders/manifest.toa.yaml
name: orders
namespace: store

entity:
  properties:
    customer:
      type: string
    items:
      type: array
      items:
        type: object
        properties:
          product: { type: string }
          quantity: { type: integer, minimum: 1 }
        required: [product, quantity]
    total:
      type: integer
      minimum: 0
    status:
      type: string
      enum: [pending, approved, cancelled]
  required: [customer, items, total, status]
  blank:
    status: pending
```

`entity` is a JSON Schema of one order. `blank` is what a new order holds before anything is
written to it. The directory is named `<namespace>.<name>`.

That is already a component. Ask the runtime what it sees:

```shell
$ toa export manifest --path components/store.orders
```

```yaml
operations:
  assign:
    type: assignment
    scope: changeset
  enumerate:
    type: observation
    scope: entries
  observe:
    type: observation
    scope: entry
  terminate:
    type: assignment
    scope: changeset
  # …
```

The output is the whole manifest as the runtime reads it; these operations are in it though you
declared none. Every component with an entity inherits them:

| Operation | Does |
| --- | --- |
| `observe` | Returns one order. |
| `enumerate` | Returns a list of orders. |
| `assign` | Sets the given properties of an order. |
| `terminate` | Deletes an order. |
| `transit` | Creates an order or changes one from its input. Available once you declare it. |

[Use the Inherited Operations](../logic/5.prototype.md) describes each of them.

## Create orders without code

Declare an operation that forwards to the inherited `transit` and say what it accepts:

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  create:
    forward: transit
    query: false
    input:
      type: object
      properties:
        customer: { type: string }
        items: { type: array }
        total: { type: integer, minimum: 0 }
      required: [customer, items, total]
```

- `forward: transit` — `create` runs the inherited implementation; there is no file to write.
- `query: false` — a call never selects an existing order, so `create` only creates.
- `input` — a JSON Schema of the argument. A call that does not fit is refused before anything
  runs.

## Add a rule

An order is approved only while it is pending. An operation with a rule is a file in the
component's `operations` directory, named after the operation:

```javascript
// components/store.orders/operations/approve.js
export async function transition (input, entry) {
  if (entry.status !== 'pending')
    return new Error('NOT_PENDING')

  entry.status = 'approved'

  return entry
}
```

The function receives the order as `entry`, changes it, and returns what the caller gets. It does
not load the order or save it: the runtime does both. To refuse, return an `Error` whose message
is a code.

The name of the function, `transition`, says that the operation changes state; the name of the
second parameter, `entry`, that it works on one order. The manifest adds what the code cannot say:

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  create:
    # …
  approve:
    concurrency: retry
    query: true
    errors: [NOT_PENDING]
```

- `concurrency: retry` — if the order was changed by someone else while `approve` was running,
  run it again on the fresh order. A transition that takes a query has to declare it.
- `query: true` — a call must select an order.
- `errors` — every code the operation may return. A code that is not listed is refused instead of
  reaching the caller.

Check that the runtime read it:

```shell
$ toa export manifest --path components/store.orders
```

```yaml
operations:
  approve:
    concurrency: retry
    query: true
    errors:
      - NOT_PENDING
    type: transition
    scope: entry
  # …
```

A mistake in the manifest stops the command, which says what is wrong:

```text
must have required property 'concurrency'
```
