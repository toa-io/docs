# Create an Application

A small shop takes orders. Its application is a directory: one file that describes the application
as a whole, a directory per component, and the scenarios that test it.

```text
store/
  package.json
  docker-compose.yaml
  context.toa.yaml
  components/
    store.orders/
      manifest.toa.yaml
      operations/
  features/
```

- `context.toa.yaml` is the *Context*: the application's name and where its infrastructure is.
- A component is a directory under `components/` with a `manifest.toa.yaml`. Nothing lists the
  components; the directories are the list. [Create a Component](2.component.md) writes the first.
- `features/` holds test scenarios; see [Write a Test](5.testing.md).

## package.json

```json
{
  "name": "store",
  "private": true,
  "type": "module",
  "scripts": {
    "dock": "docker compose up -d",
    "env": "toa env --dev && toa map",
    "features": "cucumber-js"
  },
  "devDependencies": {
    "@cucumber/cucumber": "13.2.1",
    "@toa.io/agent": "1.0.0-alpha.320",
    "@toa.io/operations": "1.0.0-alpha.325",
    "@toa.io/runtime": "1.0.0-alpha.325",
    "@toa.io/userland": "1.0.0-alpha.325"
  }
}
```

| Package | Gives you |
| --- | --- |
| `@toa.io/runtime` | The runtime and the `toa` command line. |
| `@toa.io/operations` | What `toa env` and the deployment commands need. |
| `@toa.io/userland` | The stage, which starts components inside a test. |
| `@toa.io/agent` | An HTTP client for tests that reads requests written as text. |
| `@cucumber/cucumber` | The runner of the test scenarios. |

Everything is a development dependency: the application is deployed as images that the runtime
builds, not as an npm package. Node.js 24 or later is required.

## The Context

```yaml
# context.toa.yaml
name: store
registry: registry.example.com/store

amqp: amqp://localhost
mongodb: mongodb://localhost
stash: redis://localhost

storages:
  tmp:
    provider: tmp
    directory: store

exposition:
  authorities:
    shop: localhost:8000

configuration:
  identity.tokens:
    keys:
      - id: key0
        key: $IDENTITY_TOKENS_ENCRYPTION_KEY0

ingress:
  hosts: [localhost]

resources: ~
```

This is the least a Context can hold; the commands that read it refuse a shorter one, naming what
is missing.

| Key | Says |
| --- | --- |
| `name` | The application's name. Its database is called the same. |
| `registry` | Where images are pushed on deployment. A local run does not touch it. |
| `amqp` | The broker that carries calls and events between components. |
| `mongodb` | The database that keeps the state of components. |
| `stash` | A Redis for short-lived shared data. The gateway's sign-in uses it. |
| `storages` | Where files are stored. `tmp` keeps them in a temporary directory, which is enough locally. |
| `exposition.authorities` | The hosts the HTTP API is served on, each under a name of your choice. |
| `configuration` | Settings of components. The only one without a default is the key the gateway signs users in with; `$NAME` refers to a secret. |
| `ingress.hosts` | The hosts of a deployment's ingress. |
| `resources` | CPU and memory of deployed processes. `~` is none. |

**An unknown top-level key is refused**, so a misspelled one is found at once.

Every key is described in [Describe the Application](../shipping/1.context.md). Most values differ
between your machine and production, and any key can be given per environment:
[Add Configuration](6.configuration.md#one-value-per-environment) shows how.

## Local infrastructure

A local run needs three services, and the project's `docker-compose.yaml` provides them:

| Service | Context key | Notes |
| --- | --- | --- |
| RabbitMQ | `amqp` | User `developer`, password `secret`. |
| MongoDB | `mongodb` | User `developer`, password `secret`. It must run as a replica set; one member is enough. |
| Redis | `stash` | No credentials. |

```shell
$ npm run dock
```

`developer` and `secret` are the credentials `toa env --dev` writes for the local environment, so
a compose file that uses them needs no further setup. If the services listen on other ports, say
so in the Context: `amqp: amqp://localhost:5682`.
