# Running Locally

A component runs in a *composition*: a process that hosts one or more components. Locally, one
composition usually hosts all of them.

## What it needs

- **Node.js**, a current LTS release.
- **`@toa.io/runtime`** and the `toa` command line in the project's `devDependencies`.
- **The infrastructure the components use.** By default calls and events travel over RabbitMQ,
  and state is kept in MongoDB, so a local run needs both — typically from a
  `docker-compose.yaml` in the project.

The Context says where they are:

```yaml
# context.toa.yaml
name: store
registry: registry.example.com/store

amqp: amqp://localhost
mongodb: mongodb://localhost
```

`name` and `registry` are required; the registry is where images are pushed on deployment, and a
local run does not touch it.

Addresses usually differ between your machine and production; a key suffixed with `@local`
applies to the local environment only. See [Environments](../running/2.environments.md).

## Environment and map

A process reads its settings from environment variables, and what the application's components
provide from a *map*. Both are generated from the Context:

```shell
$ toa env --dev
$ toa map
```

`toa env` writes `.env` for the `local` environment. `--dev` fills credentials with development
defaults; without it, fill them in the file yourself — values already there are kept when the file
is written again. [`toa map`](../running/4.contracts.md#the-map) writes `.map.json`.

**Run both again when the Context or a component's sources change.** A component's version is a
hash of its sources, and a composition whose component differs from what the map states is
refused at start.

Both files are generated: add `.env*` and `.map.json` to `.gitignore`.

## Starting a composition

```shell
$ toa compose ./components/*
```

The arguments are paths to components. The process stays up, serving their operations, until
it is interrupted. `--kill` stops it as soon as it has started, which is a quick way to check
that every manifest is valid and everything connects:

```shell
$ toa compose ./components/* --kill
```

## Calling an operation

From another terminal:

```shell
$ toa call store.orders.transit "{ input: { customer: 'c1', total: 1500 } }"
$ toa call store.orders.enumerate "{ query: { limit: 10 } }"
```

The first argument is `<namespace>.<name>.<operation>`; the second is the request, written as
YAML or JSON. The reply is printed. A returned error is printed as a reply; an exception is
printed to stderr, and the command exits with a non-zero code.

## Everything in one process

Some features run as *services* beside the compositions: the gateway that serves HTTP, for
example. `toa mono` starts the components and every service their extensions need in a single
process:

```shell
$ toa mono ./components/*
```

This is the usual way to run an application locally once it exposes anything over HTTP; see
[Resources](../gateway/1.exposing.md).

## Seeing what the runtime read

```shell
$ toa export manifest --path components/store.orders
```

prints the manifest as the runtime understands it: with the prototype's operations merged in, and
with each operation's `type` and `scope` as they were read from the code. When a component does
not behave as declared, look here first.

The complete list of commands and flags is in [The Command Line](../running/6.cli.md).
