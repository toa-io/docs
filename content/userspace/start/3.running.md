# Run It and Call an Operation

The component is written. Start it on your machine and call its operations from the command line.

## Prepare

With the [local infrastructure](1.application.md#local-infrastructure) running, in the project
directory:

```shell
$ toa env --dev
$ toa map
```

`toa env` writes `.env`: the settings a process needs, taken from the Context. `--dev` fills in
the local credentials. `toa map` writes `.map.json`: what each component of the application
provides. Neither prints anything.

Both files are generated. Add `.env*` and `.map.json` to `.gitignore`.

## Start

```shell
$ toa compose ./components/*
```

```text
Runtime 1.0.0-alpha.325
{"severity":"INFO","message":"Starting composition", … "components":["store.orders"]}
{"severity":"INFO","message":"Connecting to MongoDB", … }
{"severity":"INFO","message":"Composition complete", … }
{"severity":"INFO","message":"Ready", … }
```

The arguments are paths to components. The process, a *composition*, serves their operations
until you interrupt it.

## Call

From another terminal, create an order:

```shell
$ toa call store.orders.create "{ input: { customer: 'c1', items: [{ product: 'kettle', quantity: 1 }], total: 4200 } }"
```

```javascript
{
  id: '01a10df7b5c77300a7b56c1d0b5f039f',
  VERSION: 1,
  DELETED: null,
  REGION: 0,
  status: 'pending',
  CREATED: 1791235700167,
  UPDATED: 1791235700167,
  customer: 'c1',
  items: [ { product: 'kettle', quantity: 1 } ],
  total: 4200
}
```

The first argument is `<namespace>.<name>.<operation>`. The second is the request, written as YAML
or JSON: `input` is the argument of the operation, `query` selects the state it works on. The
runtime assigned the `id`, took `status` from `blank` and added the properties in capitals, which
are its own.

List the orders, then read one:

```shell
$ toa call store.orders.enumerate "{ query: { criteria: 'status==pending', limit: 10 } }"
$ toa call store.orders.observe "{ query: { id: '01a10df7b5c77300a7b56c1d0b5f039f' } }"
```

Approve it:

```shell
$ toa call store.orders.approve "{ query: { id: '01a10df7b5c77300a7b56c1d0b5f039f' } }"
```

```javascript
{
  VERSION: 2,
  status: 'approved',
  // …
}
```

Approve it again, and the rule answers:

```text
RemoteError
    at …
  code: 'NOT_PENDING'
}
```

A returned error is a reply like any other: it is printed, and the command exits with `0`.

A request that does not fit the operation is not a reply. It is an exception: printed to stderr,
with exit code `1`.

```shell
$ toa call store.orders.create "{ input: { customer: 'c1' } }"
```

```text
RequestContractException {
  code: 202,
  message: "must have required property 'total'",
  …
}
```

Everything a request can hold is in [Call Operations and Select State](../logic/4.calls.md).

## After a change

A composition does not pick up edits. After changing a component, stop it, write the map again,
and start it:

```shell
$ toa map
$ toa compose ./components/*
```

Starting without `toa map` is refused:

```text
'store.orders' is composed at a version the component map does not state. Run `toa map`.
```

After changing the Context, run `toa env --dev` again as well. The `env` script of
[`package.json`](1.application.md#packagejson) does both.

## Check that it starts

```shell
$ toa compose ./components/* --kill
```

`--kill` stops the composition as soon as it has started and exits with `0` if both went well:
a quick check that every manifest is valid and everything connects.
