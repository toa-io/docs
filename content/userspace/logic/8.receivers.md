# React to an Event

After an order is approved, the customer gets a receipt. The orders component only
[announces](7.events.md) the approval; `store.notifications` reacts to it. A *receiver* turns an
event into a call to one of the component's own operations.

## Binding an event to an operation

```yaml
# components/store.notifications/manifest.toa.yaml
name: notifications
namespace: store

entity:
  associated: true
  properties:
    kind: { type: string, enum: [receipt, cancellation] }
    customer: { type: string }
    total: { type: integer }

operations:
  receipt:
    concurrency: retry
    query: true
    input:
      type: object
      properties:
        customer: { type: string }
        total: { type: integer }
      required: [customer, total]

receivers:
  store.orders.approved: receipt
```

The event is named `<namespace>.<component>.<event>`. A component has at most one receiver per
event.

```javascript
// components/store.notifications/receivers/store.orders.approved.js
export function request (order) {
  return {
    query: { id: order.id },
    input: { customer: order.customer, total: order.total }
  }
}
```

```javascript
// components/store.notifications/operations/receipt.js
export async function transition (input, entry) {
  entry.kind = 'receipt'
  entry.customer = input.customer
  entry.total = input.total
}
```

The file in `receivers`, named after the event, exports `request`: it is given the event's
payload and builds the request the operation is called with. Here a notification is kept under
the order's own id, so one order has one receipt however many times the event arrives. Sending
the email itself is in [Call an External Service](11.external.md).

Run both components, approve an order, and look:

```shell
$ toa compose ./components/*
$ toa call store.orders.approve "{ query: { id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11' } }"
$ toa call store.notifications.observe "{ query: { id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11' } }"
```

```javascript
{
  id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11',
  kind: 'receipt',
  customer: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f',
  total: 1500,
  VERSION: 1,
  // …
}
```

The reaction happens after `approve` has answered, so in a test wait for it rather than reading
at once.

`store.orders` knows nothing of this, and nothing in it changes when a subscriber is added.

### Without a receiver file

With only the line in the manifest, the operation is called with the event's payload as its
input and no query. That fits an operation whose input is the payload as it is:

```yaml
receivers:
  store.orders.approved: record
```

## Skipping events

Loyalty points are credited only for orders of 1000 or more. Export `condition` to receive only
some of the events:

```javascript
// components/store.loyalty/receivers/store.orders.approved.js
export function condition (order) {
  return order.total >= 1000
}

export function request (order) {
  return { query: { id: order.customer }, input: { order: order.id, points: 10 } }
}
```

Where it returns `false`, the event is done with and the operation is not called.

## One operation for several events

The shop notifies about approvals and cancellations alike. `arguments` are passed to `request`
after the payload, so receivers can share an operation and differ by a constant:

```yaml
# components/store.notifications/manifest.toa.yaml
receivers:
  store.orders.approved:
    operation: notify
    arguments: [receipt]
  store.orders.cancelled:
    operation: notify
    arguments: [cancellation]
```

```javascript
// components/store.notifications/receivers/store.orders.approved.js
export function request (order, kind) {
  return { query: { id: order.id }, input: { kind } }
}
```

```javascript
// components/store.notifications/operations/notify.js
export async function transition (input, entry) {
  entry.kind = input.kind
}
```

Each event still has its own file in `receivers`.

## Receiving your own events

A component may receive its own events. It is a way to continue work after a change is stored
without making the caller wait:

```yaml
# components/store.orders/manifest.toa.yaml
receivers:
  store.orders.created: reserve
```

## What the operation must expect

Nobody waits for the reply of a call a receiver makes. So:

- **A returned error ends it.** The event is done with. If the refusal must be visible, the
  operation writes it down.
- **An exception has it tried again**, after a growing pause, and set aside for an operator if it
  keeps failing ([Operating](../shipping/10.operating.md)). Never throw to refuse.
- **The event may arrive more than once, and out of order.**

So the operation must leave the same state when given the same event twice:

```javascript
// applied twice, adds twice
entry.points += input.points

// applied twice, ends the same
entry.status = input.status
```

Where that is not natural, see [Handle Repeated Calls](10.repeats.md). The reasons are in the
model: [Delivery](../../model/reliability/1.delivery.md).

## Events from outside the application

The payment provider's system publishes `payment_settled` to a broker of its own. Such an event
has no component to be found by, so state the binding and where to consume it from:

```yaml
# components/store.orders/manifest.toa.yaml
receivers:
  payment_settled:
    operation: settle
    binding: amqp
    source: payments
```

`source` names a broker declared in the Context; see [Connectors](../platform/11.connectors.md).
It cannot be `context`. The receiver's file is named after the event as written:
`receivers/payment_settled.js`.

A name in the `<namespace>.<component>.<event>` form needs no `source`: it is
`<namespace>.<component>`.

```yaml
receivers:
  billing.invoices.paid:
    operation: settle
    binding: amqp
```

## All properties

| Property | Meaning |
| --- | --- |
| `operation` | The operation to call. A receiver written as a string is this alone. |
| `arguments` | Values passed to `request` after the payload. |
| `binding` | Where the event is consumed from; stated for events from outside. |
| `source` | The broker of an outside event, as named in the Context. |
| `bridge` | What runs the receiver's code; `node` by default. |
