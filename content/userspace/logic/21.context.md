# The Operation Context

An order above a configured limit is refused; approving one debits a wallet kept by another
component; a voucher needs an id and an expiry time. Everything an operation needs from outside
itself comes through its last argument, the *context*:

```typescript
// components/store.orders/operations/approve.ts
import type { Context, State } from '../types/index.d.ts'

export async function transition (input: null, entry: State, context: Context) {
  if (entry.total > context.configuration.limit)
    return new Error('LIMIT_EXCEEDED')

  const reply = await context.remote.billing.wallets.debit({
    query: { id: entry.customer },
    input: { amount: entry.total, ref: entry.id }
  })

  if (reply instanceof Error)
    return reply

  entry.status = 'approved'

  return entry
}
```

`approve` is the transition [Create a Component](../start/3.component.md#add-a-rule) writes for
`store.orders`. `limit` is the setting [Add Configuration](../start/6.configuration.md) declares,
and `billing.wallets.debit` the operation [Refuse a Request](3.errors.md#returning-an-error)
writes: it takes an `amount` and a `ref`, what the money is for.

```shell
$ npm run restart
$ npx toa call store.orders.approve "{ query: { id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11' } }"
```

It is the last argument whatever the operation's type:

```typescript
export async function transition (input: Input, entry: State, context: Context) { /* … */ }
export async function computation (input: Input, context: Context) { /* … */ }
```

[Events](7.events.md) and [guards](6.guards.md) are given a context too.

## Ids, time and randomness

| | |
| --- | --- |
| `context.id()` | A new id, of the same form as an object's. |
| `context.now()` | Milliseconds since the epoch, as `Date.now()`. |
| `context.random()` | A number in `[0, 1)`, as `Math.random()`. |

**Use these instead of `Date.now()`, `Math.random()` and id generators.** An operation written
as a [multi-step workflow](12.workflows.md) is given the same answers when it is resumed; a
value taken elsewhere would differ between the two runs.

## Rules

**Read from the context when you need a value; do not copy values out of it.** The context
object lives as long as the component, and what it holds can change: configuration may be
updated while the component runs.

**Reach the outside world through the context.** Reading a file that ships with the component
and using a pure library are fine. Opening connections, reading environment variables and
keeping module-level state are not; see
[the rules for operation code](2.operations.md#rules-for-operation-code).
