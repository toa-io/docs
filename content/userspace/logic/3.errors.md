# Refuse a Request

An order cannot be approved when the customer's balance is too low, and whoever asked must be
told why. An operation says "no" by **returning** an `Error` whose message is a code, and by
declaring that code in the manifest.

## Returning an error

```javascript
// components/store.accounts/operations/debit.js
export async function transition (input, entry) {
  if (entry.balance < input.amount)
    return new Error('INSUFFICIENT_FUNDS')

  entry.balance -= input.amount

  return { balance: entry.balance }
}
```

## Declaring errors

```yaml
# components/store.accounts/manifest.toa.yaml
operations:
  debit:
    concurrency: retry
    query: true
    input:
      type: object
      properties:
        amount: { type: integer, minimum: 1 }
      required: [amount]
    errors: [INSUFFICIENT_FUNDS]
```

Try it on an account that holds nothing:

```shell
$ toa call store.accounts.debit "{ query: { id: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f' }, input: { amount: 1500 } }"
```

The command prints the error, which carries the code, and exits with `0` — a refusal is a reply:

```text
RemoteError
    …
  code: 'INSUFFICIENT_FUNDS'
```

Over HTTP the same refusal is a `422` with the error as the body.

A returned error:

- **Stores nothing.** A transition or an assignment that returns one leaves the state as it was,
  and no event is published.
- **Is not a failure.** Nothing is retried, logged as a failure or alarmed by it.
- **Must be declared.** On a local run, returning a code that is missing from `errors` fails the
  call with an exception instead of handing an unknown code to the caller. Declare the code.

## Handling an error from a call

A call resolves to the output or to the error. Tell them apart with `instanceof`:

```javascript
// components/store.orders/operations/approve.js
export async function transition (input, entry, context) {
  if (entry.status !== 'pending')
    return new Error('NOT_PENDING')

  const reply = await context.remote.store.accounts.debit({
    query: { id: entry.customer },
    input: { amount: entry.total }
  })

  if (reply instanceof Error)
    return reply

  entry.status = 'approved'

  return entry
}
```

Returning the error passes it on as this operation's own answer, so its code must be among this
operation's `errors` too:

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  approve:
    concurrency: retry
    query: true
    errors: [NOT_PENDING, INSUFFICIENT_FUNDS]
```

To answer something else, read `reply.code`:

```javascript
if (reply instanceof Error) {
  if (reply.code === 'INSUFFICIENT_FUNDS')
    return new Error('PAYMENT_DECLINED')

  return reply
}
```

In a [test](../start/5.testing.md) the check is the same:

```javascript
const reply = await orders.invoke('approve', { query: { id } })

assert.ok(reply instanceof Error)
assert.equal(reply.code, 'INSUFFICIENT_FUNDS')
```

## Exceptions

Anything *thrown* is a failure nobody chose: a bug, or something the operation depends on being
away. Do not throw on purpose, and declare nothing for it.

You will meet exceptions that are thrown for you:

| The call | Over HTTP |
| --- | --- |
| does not fit the operation's input or query | `400` |
| selects an object that does not exist | `404` |
| names a version the object is no longer at | `412` |
| lost a race with `concurrency: none`, or is a refused duplicate | `409` |
| went unanswered for too long | `504` |
| failed in any other way, including a reply that does not fit `output`, a state that does not fit the entity schema and a refusing [guard](6.guards.md) | `500` |

`toa call` prints an exception to stderr and exits with `1`. The gateway's side is in
[Requests and Responses](../api/5.protocol.md).

An exception from a call is thrown where the call was made:

```javascript
const reply = await context.remote.store.accounts.debit(request) // may throw
```

**Do not catch it** unless you can truly answer in its place. An operation that lets it through
fails in turn, which is usually right. An operation that swallows it returns a wrong answer, and
nothing retries a wrong answer.

## Three rules

**Do not throw to refuse.** Where nobody waits for the reply — a
[receiver](8.receivers.md#what-the-operation-must-expect), a [task](9.tasks.md) — a thrown
refusal is tried again and again, then set aside as though something were broken. A returned
error ends the work.

**Do not return an error for a failure.** A returned error says that everything worked. Nothing
will be tried again.

**Do not assume once.** An operation may run more than once for one call or one event; see
[Handle Repeated Calls](10.repeats.md).

[Replies](../../model/basics/2.replies.md) in the model explains why the two are kept apart.

## Deciding not to write

A customer is charged for a subscription only if the balance allows; if not, that is a normal
outcome with an answer of its own, not a refusal. Set `DISCARD` on the state:

```javascript
// components/store.accounts/operations/charge.js
export async function transition (input, entry) {
  if (entry.balance < input.amount) {
    entry.DISCARD = true

    return { balance: entry.balance, charged: false }
  }

  entry.balance -= input.amount

  return { balance: entry.balance, charged: true }
}
```

```shell
$ toa call store.accounts.charge "{ query: { id: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f' }, input: { amount: 1500 } }"
```

```javascript
{ balance: 0, charged: false }
```

Nothing is written, `VERSION` does not grow, no event is published, and the caller receives the
output. Whatever the function changed on a discarded state is dropped without being validated.

Over `entries`, an entry flagged `DISCARD` is left out of the write and the rest are stored.

## The four outcomes

| | The operation | State | The caller gets |
| --- | --- | --- | --- |
| Output | returns a value | stored | the value |
| Discard | returns a value, with `DISCARD` set | untouched | the value |
| Error | returns `new Error('CODE')` | untouched | an `Error` with `code` |
| Exception | throws | untouched | an exception thrown at the call |
