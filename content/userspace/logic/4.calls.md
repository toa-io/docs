# Call Operations and Select State

Approving an order charges the customer's account, and the back office lists a customer's
pending orders, newest first. Both are calls: one operation asking another to do something, and
saying which state to do it to.

## A call

```javascript
// components/store.orders/operations/approve.js
const reply = await context.remote.store.accounts.debit({
  query: { id: entry.customer },
  input: { amount: entry.total }
})
```

The argument is a *request*. Its two main parts are kept apart: `input` is what the operation is
asked to do, `query` is which state it does it to. The same request from the command line:

```shell
$ toa call store.accounts.debit "{ query: { id: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f' }, input: { amount: 1500 } }"
```

```javascript
{ balance: 3500 }
```

| | |
| --- | --- |
| `context.remote.<namespace>.<name>.<operation>(request)` | An operation of another component. |
| `context.local.<operation>(request)` | An operation of the same component. |

Both return a promise of the reply: the output, or an `Error` the operation returned
([Refuse a Request](3.errors.md#handling-an-error-from-a-call)). Neither needs to know where the
other component runs. A component in the `default` namespace is called as
`context.remote.<name>.<operation>`.

A local call is a real call, not a function call: the request is validated, state is retrieved
and stored, and events are published, as for a call from outside.

The request may be left out for an operation that takes no input and no query.

## Input

`input` must fit the operation's `input` schema. A request that does not fit throws an exception
at the call, before anything is sent.

## Query

A query selects state within the operation's [scope](2.operations.md#scopes).

### One object

```javascript
{ query: { id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11' } }
```

A query that selects nothing is an exception for a transition or an assignment, and the
operation does not run. An observation over `entry` runs nevertheless, and the inherited
`observe` answers `null`:

```shell
$ toa call store.orders.observe "{ query: { id: '00000000000000000000000000000000' } }"
```

```javascript
null
```

A query may also select one object by criteria; the first match in sort order is taken:

```javascript
{ query: { criteria: 'customer==8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f;status==pending', sort: ['CREATED:desc'] } }
```

### Several objects

```shell
$ toa call store.orders.enumerate "{ query: { criteria: 'status==pending;total>=1000', sort: ['CREATED:desc'], limit: 10 } }"
```

```javascript
[
  { id: '0c9e3b1f6a2d4e8f9b7c5d3a1e2f4b6c', total: 4200, status: 'pending', /* … */ },
  { id: '3f7a9d2c1b4e4a6f8c5d0e1b2a3c4d5e', total: 1800, status: 'pending', /* … */ }
]
```

From an operation:

```javascript
const orders = await context.remote.store.orders.enumerate({
  query: {
    criteria: 'status==pending;total>=1000',
    sort: ['total:desc', 'id:asc'],
    omit: 20,
    limit: 10
  }
})
```

### Query properties

| Property | Meaning |
| --- | --- |
| `id` | One object by identity. |
| `ids` | Several objects by identity. |
| `criteria` | A filter over properties, in RSQL. |
| `search` | A full-text search; needs a `text` [index](20.migrations.md#indexes). |
| `sort` | A list of `property`, `property:asc` or `property:desc`. |
| `omit`, `limit` | Skip the first objects of the selection, and take at most so many. |
| `sample` | Take so many objects at random from the selection. |
| `projection` | The properties the operation is given; `id` always is. Observations only. |
| `version` | The `VERSION` the object must be at. Not for observations. |
| `deleted` | `true` to select deleted objects as well. |
| `token`, `stop` | Continuing a stream; see [Read a Large Collection](15.collections.md). |

### Criteria

Criteria are written in [RSQL](https://github.com/jirutka/rsql-parser#grammar-and-semantic):

| | |
| --- | --- |
| `status==pending`, `status!=pending` | equal, not equal |
| `total>1000`, `total>=1000`, `total<1000`, `total<=1000` | comparison |
| `status=in=(pending,approved)`, `status=out=(cancelled)` | one of, none of |
| `a==1;b==2` | and |
| `a==1,b==2` | or |
| `(a==1,b==2);c==3` | grouping |

Values are read as the type the property is declared with. `note==null` matches objects where
the property is absent or null; quote a value to mean the text: `note=="null"`.

Criteria can name system properties: `CREATED>1764000000000`.

Add an [index](20.migrations.md#indexes) for every query the application makes often.

### What each operation accepts

- **`omit` and `limit`** are accepted by an operation over `entries` — an observation, a
  transition or an effect. Such a call *requires* `ids` or `limit`, and a `limit` is at least `1`.
- **`omit` requires `sort`**: pages of an unordered selection repeat and miss objects.
- **A stream** accepts `limit` and a `token` instead of `omit`.
- **`projection`** is for observations only: a transition writes back what it read, so it reads
  all of it.
- An operation declared `query: false` accepts no query; one declared `query: true` requires
  one. An operation of a component without an entity accepts none.

A query that breaks one of these rules is an exception, like an input that does not fit.

## Creating

A transition called without a query creates an object: it receives a blank one with a fresh
`id`, and what it leaves is stored as new.

```javascript
// components/store.orders/operations/create.js
export async function transition (input, entry) {
  entry.customer = input.customer
  entry.items = input.items
  entry.total = input.total

  return { id: entry.id }
}
```

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  create:
    query: false
    input:
      type: object
      properties:
        customer: { type: string }
        items: { type: array }
        total: { type: integer, minimum: 0 }
      required: [customer, items, total]
```

```shell
$ toa call store.orders.create "{ input: { customer: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f', items: [{ product: 'p1', quantity: 2 }], total: 1800 } }"
```

```javascript
{ id: '3f7a9d2c1b4e4a6f8c5d0e1b2a3c4d5e' }
```

`query: false` makes it create-only. Without it, the same operation would also change an
existing order when called with a query — which is what the inherited `transit` does, and rarely
what an operation with rules wants.

For an [associated](1.state.md#an-object-identified-by-something-else) entity there is no
creation: a query by `id` always selects an object, written or not.

## Changing only what you have seen

Every write increments the object's `VERSION`. A caller that read an object and wants its change
applied only if nothing changed since names the version it saw:

```javascript
const reply = await context.remote.store.orders.transit({
  query: { id: order.id, version: order.VERSION },
  input: { total: 1200 }
})
```

If the object is at another version, the call fails with an exception — over HTTP, `412`. This
is the caller's check; [`concurrency`](2.operations.md#concurrency) on the operation is about
changes that happen while it runs.

## Deleted objects

Nothing is removed from storage. The inherited `terminate` sets `DELETED`, and from then on
queries do not find the object. `deleted: true` in a query finds it again — to show it, or to
restore it by assigning `DELETED: null`:

```shell
$ toa call store.orders.assign "{ query: { id: '3f7a9d2c1b4e4a6f8c5d0e1b2a3c4d5e', deleted: true }, input: { DELETED: null } }"
```

## Choosing what comes back

`output` in a request names the properties of the reply the caller wants; the rest is not sent:

```shell
$ toa call store.orders.enumerate "{ query: { criteria: 'status==pending', limit: 100 }, output: [id, total] }"
```

```javascript
[
  { id: '0c9e3b1f6a2d4e8f9b7c5d3a1e2f4b6c', total: 4200 },
  { id: '3f7a9d2c1b4e4a6f8c5d0e1b2a3c4d5e', total: 1800 }
]
```

It applies to each object of a reply that is a list. Unlike `projection`, it works for any
operation, and it trims what the operation returned rather than what it was given.

## The whole request

| Property | Meaning | Where |
| --- | --- | --- |
| `input` | The operation's arguments. | above |
| `query` | Which state it works on. | above |
| `output` | The properties of the reply to send back. | above |
| `entity` | State handed to an effect instead of a query: the matching object is found or created. | [Use the Inherited Operations](5.prototype.md#the-operations) |
| `task` | `true` hands the call over to be run later, without waiting for it. | [Do Work in the Background](9.tasks.md) |
| `id` | The identity of the call, for operations declared `once`. | [Handle Repeated Calls](10.repeats.md) |
| `instance` | The process a stateful operation is called on. | [Keep Something in a Process](17.processes.md) |
