# Write Operations

An order may be approved only while it is pending. A rule like that is an operation: a function
in a file of the component's `operations` directory, and, where needed, a declaration in the
manifest.

## A file is an operation

```javascript
// components/store.orders/operations/approve.js
export async function transition (input, entry, context) {
  if (entry.status !== 'pending')
    return new Error('NOT_PENDING')

  entry.status = 'approved'

  return entry
}
```

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  approve:
    concurrency: retry
    query: true
    errors: [NOT_PENDING]
```

Restart the composition and call it:

```shell
$ toa call store.orders.approve "{ query: { id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11' } }"
```

```javascript
{
  id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11',
  customer: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f',
  items: [],
  total: 1500,
  status: 'approved',
  VERSION: 2,
  // …
}
```

A second call answers the error `NOT_PENDING` (see [Refuse a Request](3.errors.md)).

The file name is the operation's name. The function receives:

1. **`input`** — the arguments the caller sent.
2. **state** — what the call's [query](4.calls.md#query) selected. Absent for operations that
   use no state.
3. **`context`** — the [operation context](21.context.md): calls to other operations,
   configuration, and the rest of what an operation may use.

What it returns is the reply.

Two things are read from the code:

- **The exported name is the operation's type**: `transition`, `observation`, `assignment`,
  `computation`, `effect` or `unmanaged`.
- **The name of the second parameter is its scope**: `entry`, `entries`, `changeset` or `stream`.

## Types

The type says what the operation does with state. Pick it by what the requirement needs.

### Transition: change state by a rule

Receives the current state; what it leaves is stored.

```javascript
// operations/cancel.js
export async function transition (input, entry) {
  if (entry.status !== 'pending')
    return new Error('NOT_PENDING')

  entry.status = 'cancelled'
}
```

Change the object you are given; do not replace it. Called without a query, a transition
receives a blank object and creates one (see [Creating](4.calls.md#creating)).

A transition **may run more than once for one call**, so it must come to the same decision each
time it is given the same state. Do not count, send or record anything outside the state from
inside one.

### Observation: answer from state

Receives the current state and returns something derived from it. Nothing it changes is stored.

```javascript
// operations/summary.js
export async function observation (input, entry) {
  return { status: entry.status, total: entry.total }
}
```

```shell
$ toa call store.orders.summary "{ query: { id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11' } }"
```

```javascript
{ status: 'approved', total: 1500 }
```

### Assignment: set values without reading

Receives an empty *changeset* and fills it with the values to set. Properties left out are not
touched.

```javascript
// operations/note.js
export async function assignment (input, changeset) {
  changeset.note = input.text
}
```

`note` is a property declared in the entity like any other. Use an assignment when the new
values follow from the input alone: nothing is read, and it cannot conflict with another write.
If the decision depends on the current state, write a transition.

### Computation: calculate

Uses no state and changes nothing. It has no state parameter:

```javascript
// operations/quote.js
export async function computation (input, context) {
  return input.total * context.configuration.rate
}
```

### Effect: act outside the component

Sends an email, calls an external API, orchestrates calls to other components.

```javascript
// components/store.notifications/operations/receipt.js
export async function effect (input, context) {
  const order = await context.remote.store.orders.observe({ query: { id: input.order } })

  await context.fetch('https://mail.example.com/send', {
    method: 'POST',
    body: JSON.stringify({ to: order.customer, total: order.total })
  })
}
```

An effect has no state by default. Give it a second parameter named after a scope and it
receives state as an observation does:

```javascript
export async function effect (input, entry, context) { /* … */ }
```

What an effect did outside the component is not undone or deduplicated when it runs again; see
[Handle Repeated Calls](10.repeats.md) and [Call an External Service](11.external.md).

### Unmanaged: a read the query cannot express

Receives the storage's own client — for MongoDB, the collection:

```javascript
// operations/totals.js
export async function unmanaged (input, collection) {
  return await collection
    .aggregate([
      { $match: { DELETED: null } },
      { $group: { _id: '$status', total: { $sum: '$total' } } }
    ])
    .toArray()
}
```

```shell
$ toa call store.orders.totals
```

```javascript
[ { _id: 'approved', total: 1500 }, { _id: 'pending', total: 4200 } ]
```

**An unmanaged operation reads. It never writes.** A write made here has no version, no
timestamps, no validation and no event, and does not reach other regions. Filter on
`DELETED: null` yourself: deleted objects are still in the collection.

### Summary

| Type | Receives | Stores changes | Allowed in a read-only call |
| --- | --- | --- | --- |
| `transition` | current state | yes | no |
| `observation` | current state | no | yes |
| `assignment` | empty changeset | yes | no |
| `computation` | — | — | yes |
| `effect` | optionally, current state | no | no |
| `unmanaged` | the storage client | — | no |

Read-only calls are in [Loops and Read-Only Calls](18.chains.md).

## Scopes

The scope is how much state the operation works on.

| Scope | Second parameter | The operation receives | Allowed for |
| --- | --- | --- | --- |
| `entry` | `entry` | one object | transition, observation, effect |
| `entries` | `entries` | an array of objects | transition, observation, effect |
| `stream` | `stream` | a stream of objects | observation, effect |
| `changeset` | `changeset` | an empty object to fill | assignment |
| `none` | — | nothing | computation, effect, unmanaged |

```javascript
// operations/pending.js
export async function observation (input, entries) {
  return entries.map((order) => ({ id: order.id, total: order.total }))
}
```

```shell
$ toa call store.orders.pending "{ query: { criteria: 'status==pending', limit: 10 } }"
```

```javascript
[ { id: '0c9e3b1f6a2d4e8f9b7c5d3a1e2f4b6c', total: 4200 } ]
```

A transition over `entries` changes several objects together: they are stored all or none.

```javascript
// operations/expire.js
export async function transition (input, entries) {
  for (const order of entries)
    order.status = 'cancelled'
}
```

`stream` is for collections too large to hold in memory; see
[Read a Large Collection](15.collections.md).

## Declaring an operation

An operation that needs nothing beyond its file needs no declaration. The manifest adds what the
code does not say:

```yaml
# components/store.orders/manifest.toa.yaml
operations:
  approve:
    description: Approves a pending order and charges the customer.
    concurrency: retry
    query: true
    input:
      type: object
      properties:
        note: { type: string, maxLength: 256 }
      additionalProperties: false
    output:
      type: object
      properties:
        id: { type: string }
        status: { type: string }
    errors: [NOT_PENDING, INSUFFICIENT_FUNDS]
```

### Input and output

`input` is the JSON Schema of the arguments. A request that does not fit is refused before the
function runs, so the function never checks shapes or types. An operation that declares no
`input` accepts none.

```shell
$ toa call store.orders.approve "{ query: { id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11' }, input: { note: 42 } }"
```

fails with an exception that names the property; over HTTP it is a `400`.

`output` is the JSON Schema of the reply. It is optional, and it is what
[generated types](19.typescript.md#generate-the-types), the gateway's description of its routes
and tools for models are built from. On a local run a reply that does not fit `output` fails the
call with an exception, so the mistake is found before it ships.

Rules that depend on the current state — "only a pending order" — are not schema. They are the
operation's code.

### Concurrency

A transition over existing state must say what happens when someone else changed the state
between its read and its write:

| `concurrency` | On conflict |
| --- | --- |
| `retry` | The operation is run again on the fresh state. |
| `none` | The call fails with an exception; over HTTP, `409`. |

`retry` is right for nearly every transition. Only a transition declared `query: false` — one
that always creates — goes without `concurrency`. A manifest that leaves it out elsewhere is
refused.

### Query

| `query` | Meaning |
| --- | --- |
| *(not stated)* | A call may carry a query. |
| `true` | A call must carry one. |
| `false` | A call must not. For a transition: it always creates. |

### Description

`description` says what the operation is, for a reader. It appears above the endpoint in
generated types, in the gateway's description of its routes, and in tools offered to models.

### Type and scope, stated

`type` and `scope` can be declared, and must be where the code does not show them — a function
produced by another function has no parameter names to read:

```javascript
// operations/create.js
export const transition = withAudit(async (input, entry) => { /* … */ })
```

```yaml
operations:
  create:
    scope: entry
```

### All properties

| Property | Values | Where |
| --- | --- | --- |
| `description` | text | above |
| `type`, `scope` | see [Types](#types), [Scopes](#scopes) | above |
| `input`, `output` | JSON Schema | above |
| `errors` | list of codes | [Refuse a Request](3.errors.md#declaring-errors) |
| `query` | `true`, `false` | above, [Call Operations and Select State](4.calls.md#query) |
| `concurrency` | `retry`, `none` | above |
| `forward` | an operation's name | [Use the Inherited Operations](5.prototype.md#forwarding) |
| `once` | `true`, or seconds (`600` at least) | [Handle Repeated Calls](10.repeats.md) |
| `unchained` | `true` | [Loops and Read-Only Calls](18.chains.md) |
| `stream` | an input property's name | [Stream a Reply or an Input](16.streams.md) |
| `stateful` | `true` | [Keep Something in a Process](17.processes.md) |
| `bindings`, `bridge` | connector names | [Connectors](../platform/11.connectors.md) |

## Preparing something once

A function is the usual form. Two more exist for an operation that needs to prepare something
before its first call.

A class named after the type, with an `execute` method. `mount` is called once, before the first
call; `unmount`, if there is one, when the component stops:

```javascript
// operations/quote.js
export class Computation {
  #rates

  async mount (context) {
    this.#rates = await load(context)
  }

  execute (input) {
    return input.total * this.#rates[input.currency]
  }
}
```

A factory, named `<Scope><Type>Factory` — `EntryTransitionFactory`,
`EntriesObservationFactory`, `ChangesetAssignmentFactory` — whose `create` returns an object
with `execute`:

```javascript
// operations/approve.js
export class EntryTransitionFactory {
  async create () {
    return new Approval()
  }
}
```

In either form, keep the reference to `context` and read from it when needed; do not copy values
out of it. What it holds — configuration, for one — can change while the component runs.

## Modules and shared code

A component is written as ES modules or CommonJS. For ES modules, put a `package.json` with
`"type": "module"` beside the manifest, or name the files `.mjs`. Operations can also be written
in [TypeScript](19.typescript.md).

Every file directly in `operations` is an operation. Code shared between operations lives in a
directory beside it or inside it — `lib/`, `operations/lib/` — not among the operation files:

```text
store.orders/
  manifest.toa.yaml
  package.json
  operations/
    approve.js
    cancel.js
    lib/
      totals.js
```

A component's dependencies are its own: list them in its `package.json`.

## Rules for operation code

1. **Keep nothing between calls.** No module-level variables that change. What must live in a
   process is in [Keep Something in a Process](17.processes.md).
2. **Same input and state, same result.** Take ids, time and randomness from the
   [context](21.context.md#ids-time-and-randomness), not from `Date` or `Math`.
3. **Assume nothing about where it runs.** No environment variables, no local files that do not
   ship with the component, no connections of your own.
4. **Act only through the state and the context.**
5. **Do not throw to say no.** Return an [error](3.errors.md).

[Operations](../../model/basics/3.operations.md#genuine-operations) in the model explains what
each rule buys.
