# Describe State

The shop takes orders. An order has a customer, a list of items, a total in minor units, and a
status that starts as `pending`. Describing that is the `entity` section of the component's
manifest.

## An entity

```yaml
# components/store.orders/manifest.toa.yaml
name: orders
namespace: store

entity:
  properties:
    customer:
      type: string
    items:
      type: array
      items:
        type: object
        properties:
          product: { type: string }
          quantity: { type: integer, minimum: 1 }
        required: [product, quantity]
    total:
      type: integer
      minimum: 0
    status:
      type: string
      enum: [pending, approved, cancelled]
  required: [customer, total, status]
  blank:
    items: []
    status: pending
```

- **`properties`** are [JSON Schema](https://json-schema.org/) definitions, one per property.
- **`required`** names the properties every stored order has.
- **`blank`** is what an order holds before anything is written to it. It need not be a whole
  valid order, but each value must fit the property it names.

With the component [running](../start/3.running.md), create an order with the inherited
`transit` operation and read it back:

```shell
$ toa call store.orders.transit "{ input: { customer: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f', total: 1500 } }"
```

```javascript
{
  id: '5b1ad5d8a4c54e1dbb2a4a0b6e1f0c11',
  customer: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f',
  items: [],
  total: 1500,
  status: 'pending',
  VERSION: 1,
  CREATED: 1764000000000,
  UPDATED: 1764000000000,
  DELETED: null,
  REGION: 0
}
```

`items` and `status` came from `blank`; the properties in capitals are written by the runtime.

Every write is checked against the schema, whichever operation makes it. A state that does not
fit is not stored and the call fails with an exception:

```shell
$ toa call store.orders.transit "{ input: { customer: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f', total: -1 } }"
```

A rule about one property's shape or range belongs here. A rule about a change — "an approved
order's total never grows" — is a [guard](6.guards.md); a rule about who may do what and when is
an [operation](2.operations.md).

## Name and namespace

`name` and `namespace` are the component's address: other components call `store.orders`, and its
events are `store.orders.<event>`. Each is a letter followed by up to 31 letters and digits. The
namespace `system` is reserved.

A manifest that states no `name` takes both from its directory: `components/store.orders` is
`orders` in `store`. A component with no namespace belongs to `default` and is addressed as
`default.orders`.

## One definition for a property

Operations usually repeat parts of the entity schema in their input. YAML anchors keep one
definition:

```yaml
entity:
  properties:
    total: &total
      type: integer
      minimum: 0

operations:
  create:
    input:
      type: object
      properties:
        total: *total
```

## System properties

Every stored object carries properties you do not declare:

| Property | What it holds |
| --- | --- |
| `id` | The object's identity: 32 hexadecimal characters, assigned at creation. |
| `VERSION` | A counter that grows with every write. |
| `CREATED`, `UPDATED` | When it was created and last written, in milliseconds since the epoch. |
| `DELETED` | When it was deleted, or `null`. |
| `REGION` | Which region wrote it; `0` unless the application runs in [several](../shipping/8.regions.md). |

Read them, filter and sort by them in a [query](4.calls.md#query), index them. Do not declare
them in `properties` or name them in `blank`; only `id` may be declared. A manifest that does is
refused:

```text
System property 'DELETED' cannot be overridden
```

Two more exist only on the state a transition receives and are never stored: `TRAILERS`
([Announce a Change](7.events.md#trailers)) and `DISCARD`
([Refuse a Request](3.errors.md#deciding-not-to-write)). Neither may be declared.

## Identity

An operation never generates an `id`: it is assigned when the object is created.

### An object identified by something else

Each customer has one account, and the customer's id is the natural id of the account. Declare
the entity `associated`:

```yaml
# components/store.accounts/manifest.toa.yaml
name: accounts
namespace: store

entity:
  associated: true
  properties:
    balance:
      type: integer
      minimum: 0
  required: [balance]
  blank:
    balance: 0
```

Now any `id` names an account. Reading one that was never written answers its blank, and the
first write creates it. There is no "create an account" step and no "account not found":

```shell
$ toa call store.accounts.observe "{ query: { id: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f' } }"
```

```javascript
{ id: '8d1f0c2e5a7b4c3d9e6f1a2b3c4d5e6f', balance: 0, VERSION: 0 }
```

### Identifiers of another shape

To use identifiers that are not 32 hexadecimal characters, declare `id` yourself:

```yaml
# components/store.catalog/manifest.toa.yaml
entity:
  associated: true
  properties:
    id:
      type: string
      pattern: ^[A-Z]{3}-[0-9]{4}$
    title:
      type: string
```

```shell
$ toa call store.catalog.transit "{ query: { id: 'TEA-0042' }, input: { title: 'Green tea' } }"
```

## Moments

A property that holds a point in time is declared with a format. It is then stored as a date, so
that an [index](20.migrations.md#indexes) sorts, compares and expires by it:

```yaml
entity:
  properties:
    paid: { type: string, format: date-time }        # an ISO 8601 string in your code
    expires: { type: integer, format: epoch-millis } # what context.now() answers
```

Your code reads and writes the value as declared. Three things to know:

- `epoch-millis` is a moment, not a duration. A timeout or an interval declared with it would be
  stored as a date in 1970.
- Only a property of the object itself is stored as a date. A `date-time` nested in an object or
  in an array is validated and stored as the string it is.
- Adding the format to a property that already holds data needs a
  [migration](20.migrations.md#changing-data) that converts what is stored.

## A component without state

A component that keeps nothing declares no `entity`. It still has operations: computations and
effects (see [Write Operations](2.operations.md#types)).

## Storage

`storage` names where the state is kept. It defaults to MongoDB and is rarely stated:

```yaml
entity:
  storage: mongodb
```

`storage: ~` keeps nothing: writes are validated and dropped, and no query finds anything. Use
it for a component under test. Other storages are in
[Connectors](../platform/11.connectors.md).

## The whole manifest

| Key | Declares | Where |
| --- | --- | --- |
| `name`, `namespace` | The component's address. | above |
| `entity` | Its state: `properties`, `required`, `blank`, `associated`, `storage`. | above |
| `operations` | What it does. | [Write Operations](2.operations.md) |
| `prototype` | What it inherits. | [Use the Inherited Operations](5.prototype.md) |
| `receivers` | Which events it reacts to. | [React to an Event](8.receivers.md) |
| `bindings`, `bridge` | How it is called and what runs its code. | [Connectors](../platform/11.connectors.md) |
| `configuration`, `exposition`, `realtime`, `storages`, `stash`, `state`, `cadence`, `continuity`, `telemetry`, … | The extensions it uses. | [Extensions](../platform/1.extensions.md) |
| `version`, `files`, `ignore`, `build` | How it is versioned and built. | [Upgrades](../shipping/7.upgrades.md), [Deployment](../shipping/4.deployment.md) |

Events and guards are files, not manifest keys: see [Announce a Change](7.events.md) and
[Protect an Invariant](6.guards.md). A manifest with an unknown key is refused when it is read.

To see the manifest as it is understood — with inherited operations merged in and each
operation's type and scope as read from the code:

```shell
$ toa export manifest --path components/store.orders
```
