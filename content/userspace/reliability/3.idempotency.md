# Idempotency

An operation [may be delivered the same call twice](1.delivery.md#what-an-operation-must-tolerate).
For `store.accounts.debit` that means a customer charged twice. Declare `once`, and the same call
arriving again changes nothing and is answered with what the first arrival answered. The model's
[Idempotency](../../model/reliability/3.idempotency.md) describes the idea.

## Declaring it

```yaml
# components/store.accounts/manifest.toa.yaml
operations:
  debit:
    type: transition
    scope: entry
    concurrency: retry
    once: true
    input:
      type: object
      properties:
        amount: { type: integer, minimum: 1 }
      required: [amount]
    errors: [INSUFFICIENT_FUNDS]
```

The operation itself is written as before:

```javascript
// components/store.accounts/operations/debit.js
export async function transition (input, entry) {
  if (entry.balance < input.amount) return new Error('INSUFFICIENT_FUNDS')

  entry.balance -= input.amount

  return entry
}
```

Now when `store.orders.approve` is delivered twice and calls `debit` twice, the second call finds
that it was already applied. The balance moves once, and both calls get the same reply. The
caller cannot tell them apart, which is the point: most duplicates are requests whose reply was
lost on the way back, and their sender is still waiting for an answer.

### Which operations can declare it

| operation                                  | `once`                                           |
| ------------------------------------------ | ------------------------------------------------ |
| transition over `scope: entry`             | yes                                              |
| assignment                                 | yes                                              |
| transition over `scope: entries`           | no                                               |
| observation, computation                   | no — nothing is written                          |
| effect                                     | no                                               |

An effect does not need it for its own entity: one called with `entity` in the request gets or
creates that entity, so a second arrival creates nothing.

It needs a storage that can commit the record of a call with the entity: MongoDB as a replica set
or a sharded cluster. **A component that declares `once` on anything else does not start**, and
says which component and which storage. There is no weaker mode.

## The identity of a call

Two arrivals are the same call when they carry the same *identity*. You rarely handle it:

- A call made from an operation takes its identity from the call that operation is serving. If
  `approve` runs twice for one request, it calls `debit` under the same identity both times.
- A call that starts a chain — from the gateway, a receiver handling an event, a [task](4.tasks.md)
  — is given one when it is made, and keeps it through every redelivery.

The identity is not the content. Two debits of the same amount from the same account are two
calls if they were made twice, and one call if a single request was delivered twice.

A request can also state its identity itself, as `id` beside `input` and `query`:

```yaml
id: aa11e57cc0e14fce95c4496c21086781
query:
  id: 6b93e57cc0e14fce95c4496c21086781
input:
  amount: 500
```

Sent twice, this debits once and answers the same both times, even if the second request carries
another `input`. That is how to try `once` out by hand; inside an operation, leave `id` to the
runtime.

An operation that declares `once` refuses a call that arrives without an identity rather than
run unguarded.

### Chains

A duplicate at the start of a chain is absorbed at every hop that declares `once`:

```
POST /orders/42/approval   delivered twice
  store.orders.approve     once: the second arrival is answered from the first
    store.accounts.debit   once: would refuse the repeat even if approve ran again
```

**A hop that does not declare `once` is a break in that.** If `approve` does not declare it, a
duplicate runs `approve` again; `debit` is still protected, because the repeated call carries the
same identity.

For the identities of a re-run to line up with the first run's, **an operation should make the
same calls in the same order given the same input.** One that branches on something that moved
between the two runs makes different calls, and the duplicate is missed.

## From HTTP clients

A client that retries a request it never saw answered is making a second request, and only the
client knows it is the same one. It says so with a header:

```http
POST /orders/42/approval/ HTTP/1.1
idempotency-key: 3f1c8a2e-6d0b-4c1f-9a57-0e2b7c9d4a11
```

The gateway turns the key into the identity of the call. A retry with the same key is the same
call, and is answered with what the first one answered.

The client generates the key and repeats it only to retry the same request. What makes two
requests the same call:

- **who is calling** — a key one client picked never collides with another client's;
- **the key**;
- **the method and the path** — one key sent to two routes is two calls.

The body is not part of it. The same key with a different body is answered with the first reply.

Three things to know:

- **A route nothing authenticates has no caller to scope a key by**, so two clients that pick
  the same key collide there. Put authentication on a state-changing route.
- **A key sent to a method whose operation does not declare `once` is accepted and does
  nothing.**
- Whether a method is safe to retry this way is in what it answers to `OPTIONS`, as `once`, and the
  discovery page marks it. [Discovery](../gateway/16.discovery.md) covers both.

## How long a call is remembered

`once: true` remembers a call for the deployment's window, one hour unless the Context says
otherwise:

```yaml
# context.toa.yaml
inbox:
  retention: 3600 # seconds
```

An operation whose callers may retry later than the rest states its own window, in seconds:

```yaml
# components/store.accounts/manifest.toa.yaml
operations:
  debit:
    once: 86400 # a client may retry a payment for a day
```

The operation's number wins over the Context's.

Choose the window by how late a duplicate can arrive — a redelivery, the retries of a message,
whatever a client does — not by how long the change matters. Every call is kept for that long, so
a busy operation with a long window keeps many records.

**The minimum is `600` seconds** in both places. Retries alone can repeat a call for most of ten
minutes, and a manifest or a Context that states less is refused.

A duplicate that arrives after the window is a new call.

## What it does not give

`once` is about what is written to the component's own state. Its limits are precise.

**A call that changed nothing is not remembered.** If the operation returned an error, threw, or
[discarded](../components/3.errors.md) its change, there is no record. The same call made again
runs again — and, nothing having changed, answers the same way.

**The code may still run more than once.** A duplicate that arrives while the first is in flight
runs to the end before its write is refused. A transition with `concurrency: retry` runs again on
every conflict. What is prevented is the second *write*.

**So what the operation does outside its state is still yours to make safe.** An email, a charge to
a third party, anything through [`context.fetch`](../services/4.fetch.md) or
[`context.stash`](../services/5.stash-and-state.md) happens once per run, not once per call:

```javascript
export async function transition (input, entry, context) {
  entry.balance -= input.amount

  // made on every run, including the run of a duplicate
  await context.remote.store.notifications.send({ input: { to: entry.id } })

  return entry
}
```

Here the call to `send` carries the same identity on every run, so `send` is protected if it
declares `once` itself. A request to a third party has no such protection; move it to an effect
under [continuity](5.continuity.md), or give the third party a key to deduplicate on.

**It holds within one region.** Where the application runs in several
[regions](../running/10.regions.md#once-is-regional), a call is remembered in the region where it
was made; a duplicate arriving in another is applied there.

## Operating

Remembered calls are kept beside the entities, in a collection named after the component with
`_inbox` appended:

```javascript
db.store_accounts_inbox.countDocuments() // calls remembered right now
db.store_accounts_inbox.findOne({ _id: '<the call identity>' }) // what that call answered
```

Records expire on their own, up to a minute late. There is nothing to clean up and nothing to
replay. A component that declares no `once` has no such collection.
