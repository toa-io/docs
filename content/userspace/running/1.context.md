# The Context File

`context.toa.yaml` describes the application as a whole: what it is called, what it connects to,
how its components are grouped into processes, and how it is deployed. Components say what the
application does; the Context says where and how it runs. See
[The Big Picture](../../model/foundations/2.overview.md) for the idea.

Every top-level key follows. Most are taught in detail elsewhere, and each section says where.

## The smallest Context

```yaml
# context.toa.yaml
name: store
registry: registry.example.com/store

amqp: amqp://localhost
mongodb: mongodb://localhost
```

`name` and `registry` are required. The two addresses tell the components where the broker and the
database are. With this file, `toa env`, [`toa map`](4.contracts.md#the-map) and `toa compose` are
enough to run the application locally, as [Running](../start/3.running.md) shows.

The components of a Context are the directories under `components/` beside the file. Nothing lists
them.

**An unknown top-level key is refused.** A misspelled key fails every command that reads the
Context, naming the key.

Every key, at any depth, may carry an `@<environment>` suffix to give a value for one environment
only: `mongodb@production: mongodb://db.internal`. [Environments](2.environments.md) covers this.

## Identity

```yaml
name: store
version: 1.4.0
description: A small shop
```

- **`name`** — letters, digits and underscores in words joined by hyphens, starting with a letter.
  It names the deployed release and the image repository, and it scopes what the application keeps
  on shared infrastructure: its database is called `store`.
- **`version`** — the version of the deployed chart. A local run does not need it; `toa deploy`
  refuses a Context without one.
- **`description`** — the chart's description. Optional.

## The runtime

```yaml
runtime:
  version: 1.0.0
  registry: https://npm.example.com
  proxy: http://proxy.example.com:3128
```

- **`version`** — the Toa release the deployed images are built on. Absent, it is the release of
  the CLI that deploys. `runtime: 1.0.0` is shorthand for the same.
- **`registry`**, **`proxy`** — the npm registry and proxy an image build installs from, for
  builds behind a private registry.

The whole key is optional. See [Images](8.images.md).

## The registry

```yaml
registry:
  base: registry.example.com/store
  platforms: [linux/amd64]
  credentials: registry-credentials
  services: published
  build:
    arguments: [NPM_TOKEN]
    run: apk add --no-cache ffmpeg
```

Where images are pushed and how they are built. `registry: <string>` is shorthand for
`registry.base`. Every option is explained in [Images](8.images.md).

## Compositions

```yaml
compositions:
  - name: core
    components: [store.orders, store.accounts]
    services: [exposition]
    replicas: 3

evicted:
  components: [store.pictures]

resources:
  cpu: [200m, 1]
  memory: [256Mi, 1Gi]

mono:
  replicas: 2
```

- **`compositions`** — which components run together as one process, how many replicas, with what
  resources.
- **`evicted`** — components and services this deployment leaves out.
- **`resources`** — the default CPU and memory for every workload that states none of its own.
- **`mono`** — replicas and resources of the single-image deployment.

All four are covered in [Compositions](3.compositions.md).

## Ingress

```yaml
ingress:
  hosts: [api.example.com]
  class: nginx
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: 16m
  default: true
```

Where the services that are reachable from outside land in the cluster. See
[Deployment](7.deployment.md#ingress).

## Infrastructure and extensions

Every other key configures a connector or an extension. These keys are *annotations*: values the
Context hands to a package. Each known package has a shortcut, and the shortcut is the key.

```yaml
amqp: amqp://rmq.example.com
mongodb: mongodb://mongo.example.com
stash: redis://redis.example.com

exposition:
  authorities:
    main: api.example.com

configuration:
  store.orders:
    limit: 10000
```

| Key | What it configures | Taught in |
| --- | --- | --- |
| `amqp` | the broker the components talk through | [Connectors](../services/12.connectors.md#bindings) |
| `mongodb` | the database | [Connectors](../services/12.connectors.md#storages) |
| `http` | where a component answers streamed calls | [Streamed Calls](../flow/5.streamed-calls.md#addresses) |
| `stash` | transient shared state (Redis) | [Stash and State](../services/5.stash-and-state.md#the-context-annotation) |
| `storages` | file storages | [Storages](../gateway/10.storages.md) |
| `exposition` | the gateway | [Running the Gateway](../gateway/17.running.md#reference) |
| `realtime` | realtime routes | [Realtime](../gateway/13.realtime.md#configuration) |
| `configuration` | component configuration values and secrets | [Configuration](../services/2.configuration.md#values-from-the-context) |
| `telemetry` | logs, traces, metrics | [Exporting Telemetry](../services/10.exporting-telemetry.md) |
| `introspection` | the topology and [halt](11.halt.md) | [Introspection](../services/11.introspection.md#the-context-annotation) |
| `cadence` | pulses and delayed calls | [Delays](../flow/3.delays.md#running-cadence) |
| `continuity` | resuming failed tasks | [Continuity](../reliability/5.continuity.md#deployment) |
| `convergence` | [regions](10.regions.md) | this chapter |

A package without a shortcut is configured under `annotations`, by its package name. The shortcut
keys are the same thing written short:

```yaml
annotations:
  '@toa.io/extensions.stash': redis://redis.example.com
```

### Addresses

`amqp`, `mongodb` and `stash` take addresses. An address can be given for everything, for a
namespace, or for one component, and a component takes the most specific one that matches it:

```yaml
mongodb:
  .: mongodb://mongo.example.com              # everything
  store: mongodb://store.mongo.example.com    # every component of `store`
  store.catalog: mongodb://catalog.example.com # `store.catalog` alone
```

`mongodb: mongodb://mongo.example.com` is the same map with the `.` key alone. **An address never
carries credentials**; they are supplied as secrets. [Variables and secrets](9.secrets.md) has
the rules.

### Services and their resources

Some extensions run a process of their own: the gateway (`exposition`), the configuration values
service (`configuration`), the topology explorer (`introspection`), the scheduler (`cadence`).
The gateway, the values service and the explorer take `resources` inside their own annotation,
in the same form as the Context's:

```yaml
exposition:
  resources:
    cpu: [200m, 2]
    memory: [200Mi, 1Gi]
```

Without it the service takes the Context's `resources`.

## Runtime settings

A few keys tune the runtime itself. All are optional, and each is explained where its mechanism
is taught.

```yaml
atomicity:
  redis: redis://redis.example.com
  interval: 1000

outbox:
  interval: 5000
  batch: 100
  retention: 86400

inbox:
  retention: 3600

addressed:
  timeout: 30000

events:
  - store.orders.approved
```

| Key | Sets | Taught in |
| --- | --- | --- |
| `atomicity.redis` | one Redis address, or an odd number of independent ones, where replicas decide together | [Shared Decisions](../services/6.shared-decisions.md#setting-it-up) |
| `atomicity.interval` | how often a replica registers, ms, at least `100` | same |
| `outbox.interval` | how often unpublished events are looked for, ms, at least `100` | [Committed Events](../reliability/2.committed-events.md#settings) |
| `outbox.batch` | how many are read at once | same |
| `outbox.retention` | seconds a published event is kept as a change log | same |
| `inbox.retention` | seconds a call is remembered for deduplication, at least `600` | [Idempotency](../reliability/3.idempotency.md#how-long-a-call-is-remembered) |
| `addressed.timeout` | ms an addressed call waits for its reply by default | [Stateful Operations](../flow/6.stateful.md#waiting) |
| `events` | events consumed outside the application | below |

### Events consumed outside

A deployed component publishes an event only when something consumes it: a receiver somewhere in
the application. An event that another application reads has no receiver here, so the Context
names it:

```yaml
events:
  - store.orders.approved
```

Each entry is `<namespace>.<component>.<event>`. Without the entry and without a receiver, a
deployment does not publish `approved` at all.

This applies to deployments only. A local run, `toa mono`, and a composition booted in a test
publish every event. See [Events](../components/6.events.md) for declaring events.

## Every top-level key

| Key | Required | Purpose |
| --- | --- | --- |
| `name` | yes | the application's name |
| `registry` | yes | where images go and how they are built |
| `version` | to deploy | the chart's version |
| `description` | no | the chart's description |
| `runtime` | no | Toa version, npm registry and proxy for builds |
| `compositions` | no | components grouped into processes |
| `evicted` | no | what this deployment leaves out |
| `resources` | to deploy | default CPU and memory, or `null` |
| `mono` | no | replicas and resources for `--mono` |
| `ingress` | no | hosts, class and annotations for exposed services |
| `annotations` | no | configuration of packages by package name |
| shortcut keys | no | `amqp`, `mongodb`, `http`, `stash`, `storages`, `exposition`, `realtime`, `configuration`, `telemetry`, `introspection`, `cadence`, `continuity`, `convergence` |
| `atomicity`, `outbox`, `inbox`, `addressed`, `events` | no | runtime settings |

## A complete example

```yaml
# context.toa.yaml
name: store
version: 1.4.0

registry:
  base@local: localhost:5000
  base@production: registry.example.com/store
  platforms@local: ~

resources:
  cpu: [200m, 1]
  memory: [256Mi, 1Gi]

compositions:
  - name: core
    components: [store.orders, store.accounts, store.catalog]
    replicas: 3
  - name: media
    components: [store.pictures]

amqp@local: amqp://localhost
amqp@production: amqp://rmq.internal.example.com

mongodb@local: mongodb://localhost
mongodb@production: mongodb://mongo.internal.example.com

exposition:
  authorities:
    main@local: localhost:8000
    main@production: api.example.com

ingress:
  hosts@production: [api.example.com]

configuration:
  store.orders:
    limit: 10000
    limit@local: 100
```
