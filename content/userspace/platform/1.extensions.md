# Turn On a Platform Feature

The catalog needs a cache, orders need a price limit that changes without a release, and somebody
wants to count approvals. None of that is code you write: each is a feature of the platform that a
component switches on by naming it in its manifest. A feature is provided by an *extension* or a
*connector*; the model article [Extensions](../../model/platform/1.extensions.md) says what those
are.

You write something in two places: the component's manifest and the Context.

## Declare it in the manifest

A component asks for an extension with a top-level key named after it. The smallest declaration
has no value:

```yaml
# components/store.catalog/manifest.toa.yaml
name: catalog
namespace: store

stash: ~
```

The operations of `store.catalog` now find the cache on their context:

```typescript
// components/store.catalog/operations/price.ts
import type { Context, PriceInput } from '../types/index.d.ts'

export async function computation (input: PriceInput, context: Context) {
  return await context.stash.get(input.product)
}
```

What an extension puts on the operation context is called an *aspect*. Most extensions take a
declaration with content instead of `~`; what goes in it is described in the extension's article:

```yaml
# components/store.orders/manifest.toa.yaml
configuration:
  schema:
    properties:
      limit: { type: integer }
  defaults:
    limit: 5000
```

A manifest that declares something the extension does not accept is refused when the manifest is
read, before anything starts.

### What every component already has

Three extensions are present without a declaration:

| Extension | On the context |
| --- | --- |
| Telemetry | `context.logs`, `context.span`, `context.metrics` |
| Fetch | `context.fetch` |
| Introspection | nothing; the component appears in the topology |

Write a `telemetry` or `introspection` key only when the component has something to say to them:
the metrics it records, or that it wants to be left out of the topology.

`context.atom` is also there for every component. It comes from a connector and has no manifest
key at all.

## Set it up in the Context

Where the cache is, how much is logged and the like are written once for the whole application,
in `context.toa.yaml` under the same key. These declarations are called *annotations*:

```yaml
# context.toa.yaml
name: store

stash: redis://redis.example.com

telemetry:
  logs:
    level: info
```

The manifest says the component uses a cache; the Context says where the cache is. A component
never reads an address.

### A different value per environment

Append `@` and an environment's name to any key of the Context. The plain key is what every other
environment takes:

```yaml
# context.toa.yaml
stash@local: redis://localhost:6379
stash@production: redis://redis.internal:6379

telemetry:
  logs:
    level: debug
    level@production: info
```

The suffix works at any depth of an annotation, on a key that holds a value or a whole block. See
[Environments](../shipping/2.environments.md).

## Try it

With Redis running locally and `stash@local` pointing at it, regenerate the environment and call
the operation:

```shell
$ toa env --dev
$ toa map
$ toa compose ./components/*
```

```shell
$ toa call store.catalog.price "{ input: { product: 'a1' } }"
```

The reply is `null` until something has been stored under that key. Running locally is covered in
[Run It and Call an Operation](../start/3.running.md).

## The full form

The short keys are shortcuts. A manifest groups its extensions under `extensions`, keyed by
package reference, and a Context groups its annotations under `annotations`:

```yaml
# components/store.catalog/manifest.toa.yaml
extensions:
  '@toa.io/extensions.stash': ~
```

```yaml
# context.toa.yaml
annotations:
  '@toa.io/extensions.stash': redis://redis.example.com
```

You need the full form only for an extension without a shortcut, which means one of your own: see
[Write an Extension of Your Own](13.own-extensions.md).

## Ports that are taken

Some extensions run a process of their own, a *service*, and each service that listens takes a
fixed port. Do not use them for anything you run in the same process:

| Port | Taken by |
| --- | --- |
| `8000` | the gateway |
| `8001` | the readiness probe of a composition |
| `8002` | the introspection page |
| `8003` | the configuration page |
| `8004` | the readiness probe of the gateway |
| `8005` | streamed calls to a component |

Two services that claim the same port in one process are refused when the deployment is exported:

```text
Port 8001 is claimed by both the readiness probe and the readiness probe of 'exposition-gateway'
```
