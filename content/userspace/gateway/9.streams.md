# Streams and Flow

Most routes answer one value. Others do more: routes that answer a stream of
values, routes that keep a client's copy of a collection current, routes whose request body
flows through an operation, routes that reach one particular process — and the `flow`
directives that reshape or redirect a reply.

The concepts behind them are in the model:
[collection streams](../../model/flow/2.collections.md),
[streamed calls](../../model/flow/3.streams.md) and
[stateful operations](../../model/flow/4.stateful.md). Here is how each looks over HTTP.

## Reply streams

An operation that answers a stream — a generator, or a `Readable` in object mode — is exposed
like any other. Nothing in the route says it streams:

```javascript
// components/store.orders/operations/export.js
export async function * effect (input, context) {
  for (const month of input.months)
    yield await summarize(month, context)
}
```

```yaml
# components/store.orders/manifest.toa.yaml
exposition:
  /exports:
    POST:
      endpoint: export
      io:output: [month, orders, revenue]
```

The reply is a [multipart response](5.protocol.md#multipart-responses), one part per yielded
value, sent as it is produced:

```http
POST /store/orders/exports/ HTTP/1.1
content-type: application/yaml
accept: application/yaml

months: [2026-01, 2026-02]
```

```http
HTTP/1.1 201 Created
content-type: multipart/yaml; boundary=cut

--cut
ACK
--cut
month: 2026-01
orders: 312
revenue: 1840200
--cut
month: 2026-02
orders: 287
revenue: 1699000
--cut
FIN
--cut--
```

- [`io:output`](6.io.md#output) applies to every object the stream yields. Without it the stream is
  closed unread and the reply is `204`.
- A client reads parts as they arrive. A stream that fails midway ends with `FIN` like one that
  completed, so an operation whose consumers must know it finished yields a last part that says
  so.

## Collection streams

A client that keeps a copy of a collection — an order list in an admin console, an offline
catalogue — reads the collection once and afterwards asks only for what changed. An operation of
scope `stream` serves this; the generic prototype provides one, named `stream`.

```yaml
# components/store.orders/manifest.toa.yaml
exposition:
  /feed:
    auth:role: staff
    GET:
      endpoint: stream
      io:output: [id, customer, status, total, VERSION]
      query:
        criteria: status!=cancelled
        limit: { value: 100, range: [1, 500] }
```

The reply is multipart, with three kinds of parts:

```http
GET /store/orders/feed/ HTTP/1.1
accept: application/yaml
```

```http
HTTP/1.1 200 OK
content-type: multipart/yaml; boundary=cut

--cut
ACK
--cut
entry:
  id: 4c4759e6f9c74da989d64511df42d6f4
  status: pending
  total: 4200
  VERSION: 1
--cut
removed: 99988d785d7d445cad45dbf8531f560b
--cut
token: eyJ2IjoxLCJwIjoi...
--cut
FIN
--cut--
```

| Part | Meaning for the client's copy |
| --- | --- |
| `entry` | An entity of the collection: one it has, or one that changed. Insert or replace it. |
| `removed` | The id of an entity that left the collection: deleted, or no longer matching. Drop it. |
| `token` | The last part of a complete reply. Keep it. |

### Reading in windows

Each request carries the token the previous reply ended with:

```http
GET /store/orders/feed/?limit=100                 100 entries, then a token T1
GET /store/orders/feed/?token=T1&limit=100        the next 100, then T2
GET /store/orders/feed/?token=T2&limit=100        42 entries: the collection is read; then T3

GET /store/orders/feed/?token=T3&limit=100        later: what changed since, then T4
```

A window shorter than `limit` means the collection has been read. From then on the token
answers changes only, and an empty reply — a token and nothing else — means nothing changed.

A client's loop is therefore the same from the first request on: send the last token, apply the
parts, keep the new token.

**A reply that ends without a token was cut.** Send the same request again, with the token it
carried.

### Newest first, then changes

A long collection is often shown from its newest end, without ever reading all of it. `stop`
ends the read after the first window, and its token continues with changes:

```http
GET /store/orders/feed/?sort=CREATED:desc&stop HTTP/1.1
GET /store/orders/feed/?sort=CREATED:desc&token=T1 HTTP/1.1
```

### Rules

- A stream route that declares no `limit` answers the whole collection in one reply.
- `omit` is refused.
- `sort`, beside `limit` or `token`, takes only `id` and `CREATED`, which never change for an
  entity. Anything else is `400`.
- A token belongs to the criteria and order it was issued under. Presented under others, it is
  `400`.
- A token too old for the storage to continue from is `410 Gone`. Drop the copy and read the
  collection again without a token.
- Include `VERSION` in `io:output`, so that the client can tell an older state from a newer.

The query declaration of a stream route is described in
[Queries](4.queries.md#streams-of-a-collection).

A [collection stream](../flow/4.collection-streams.md) is complete but not immediate: the client
learns of a change when it asks. To be told the moment something changes, combine it with
[Realtime](13.realtime.md).

## Turning a stream into one value

Some clients cannot read multipart, and some streams are really one answer assembled in steps.
`flow:compose` collects the parts of a reply stream and answers a single value built from them.

Its value is an object whose values are JavaScript expressions. The collected parts are
available as the array `$`:

```yaml
exposition:
  /exports/summary:
    POST:
      endpoint: export
      io:output: true
      flow:compose:
        first: $[0].revenue
        second: $[1].revenue
        total: $[0].revenue + $[1].revenue
        months: $
```

```http
HTTP/1.1 201 Created
content-type: application/yaml

first: 1840200
second: 1699000
total: 3539200
months:
  - month: 2026-01
    orders: 312
    revenue: 1840200
  - month: 2026-02
    orders: 287
    revenue: 1699000
```

- A value that is not an expression over `$` is taken literally: `count: 1`. A string that
  should be literal is escaped with a backslash: `label: \total`.
- Arrays are composed element by element: `pair: [$[0].month, $[1].month]`.
- The value may be a single expression instead of an object: `flow:compose: $[1]`.
- The value may be a list of shapes. The first one whose expressions all evaluate is answered,
  which handles a stream that may end early:

  ```yaml
  flow:compose:
    - total: $[0].revenue + $[1].revenue
    - total: $[0].revenue
  ```

The whole stream is held in memory until it ends. Compose short streams.

Its most common use is with file uploads, to answer one object instead of the workflow's parts;
see [File Workflows](12.workflows.md#one-reply-instead-of-parts).

## Streamed request bodies

A body that has to flow through an operation — a file being checksummed, transcoded, parsed or
forwarded — is handed to it as a stream with [`map:stream`](7.mapping.md#the-body-as-a-stream). The
operation declares which input property carries the stream:

```yaml
# components/store.catalog/manifest.toa.yaml
operations:
  import:
    type: effect
    stream: sheet
    input:
      properties:
        supplier:
          type: string

exposition:
  /imports/:supplier:
    POST:
      endpoint: import
      io:output: [imported, rejected]
      map:segments:
        supplier: ~supplier
      map:stream: sheet
```

```javascript
// components/store.catalog/operations/import.js
export async function effect ({ supplier, sheet }, context) {
  let imported = 0

  for await (const row of parse(sheet.stream))
    imported += await add(supplier, row, context)

  return { imported, rejected: 0 }
}
```

The property is filled with an object:

| Member | Holds |
| --- | --- |
| `stream` | The request body, a `Readable`. |
| `type` | The request's `content-type`. |
| `accept` | The media type to answer with, see below. |

The body is not parsed, so the rest of the input comes from the path and other `map` directives.
The directive names the same property the operation declares in `stream`; a route that maps a
stream onto an operation that does not take one is refused when the manifest is read.

### Limits and media types

The long form states what the route takes and what it answers:

```yaml
      map:stream:
        property: sheet
        accept: [text/csv, application/vnd.ms-excel]
        limit: 20MiB
```

| Key | Meaning | Default |
| --- | --- | --- |
| `property` | The input property that carries the stream. | — |
| `accept` | Media types a client may send. Another one is `415`. | any |
| `limit` | The largest body, in bytes or with a unit. A larger one is `413`. | `64MiB` |
| `produces` | Media types the route answers bytes in. | — |

Units of `limit` are those of file uploads, see [Files](11.files.md#size-limit).

### Answering bytes

An operation may answer a stream of bytes — a rendered PDF, a converted image. The route states
the media types it can answer in with `produces`:

```yaml
exposition:
  /thumbnails:
    POST:
      endpoint: thumbnail
      io:output: true
      map:stream:
        property: source
        accept: [image/jpeg, image/png]
        produces: [image/webp, image/jpeg]
        limit: 10MiB
```

The request's `accept` is resolved against `produces` before the call. The operation is handed
the one media type chosen, as `accept` beside the stream, and answers bytes in it; the response
carries it as `content-type`.

- A client that names several of them gets the first it named. A client that names none, or
  accepts anything, gets the first the route lists.
- A client that asks for something the route does not produce is `406`, and the operation does
  not run.
- **A route that declares `produces` answers bytes.** If the operation answers a value there,
  the response is `422`.
- Everything `produces` lists must be the same answer in another encoding. A route that would
  answer two different things answers them at two paths.

### When not to stream

A [streamed call](../flow/5.streamed-calls.md) is made on a connection of its own and is neither
queued nor retried: if it fails, the client is told and nothing tries again. Map a stream only when
a body must pass through an operation.

- A body that is to be **kept** is a file: store it with
  [`octets:put`](11.files.md#uploads) and process it from a workflow.
- A body small enough to be a value is a value.

## Stateful operations

A [stateful operation](../flow/6.stateful.md) runs in one particular process — the one holding a
connection, a session, a running job — and a call to it names that process. Over HTTP the name
travels in a route variable, which `map:instance` points at:

```yaml
# components/store.assistant/manifest.toa.yaml
exposition:
  /sessions/:instance:
    auth:anyone: true
    POST:
      endpoint: say
      io:input: [message]
      io:output: false
      map:instance: instance
```

`store.assistant` here is a component that holds a conversation with a customer in memory; `say`
is declared `stateful: true`.

```http
POST /store/assistant/sessions/7f3a9c1e/ HTTP/1.1
content-type: application/yaml

message: Where is my order?
```

The variable is taken out of the input and out of the criteria; it only addresses the call.

| Situation | Response |
| --- | --- |
| The route to a stateful operation has no `map:instance` | `400` |
| No process holds the name | `404` |
| The process did not answer within its timeout | `504` |

How does a client learn the name? From the application: an ordinary operation returns it. A
process reads its own name as `context.instance`, so the operation that starts a session stores
or returns that value, and the client uses it in the path from then on.

A name is not a secret by itself and not an access rule. Protect the route as any other, and
have the stateful operation check that the caller is the one the session belongs to.

## Answering with someone else's content

`flow:fetch` answers a request with content fetched from a URL the application chooses. The
client asks the application; the application decides where the content really is; the gateway
fetches it and passes it on.

The directive names an operation that returns the URL:

```yaml
# components/store.invoices/manifest.toa.yaml
exposition:
  /:id/pdf:
    auth:role: staff
    GET:
      io:output: true
      flow:fetch: store.invoices.locate
```

```javascript
// components/store.invoices/operations/locate.js
export async function computation ({ parameters }) {
  if (!/^[a-f0-9]{32}$/.test(parameters.id)) return new Error('NO_INVOICE')

  return `https://billing.example/invoices/${parameters.id}.pdf`
}
```

The operation receives as input:

| Property | Holds |
| --- | --- |
| `authority` | The identifier of the host the request was sent to. |
| `path` | The path of the request. |
| `parameters` | The route variables. |

and returns one of:

- a URL string, fetched with `GET`;
- an object `{ url, options }`, where `options` may hold `method`, `headers` and `body`;
- an error, which answers `404`.

The fetched response's body is streamed to the client with its `content-type`,
`content-length` and `etag`. A fetch that does not succeed is `404`. If the client disconnects,
the fetch is abandoned. A request that carries `if-none-match` is answered `304` without a
fetch.

The endpoint is written in full — `namespace.component.operation` — also inside a component's
own manifest.

Use it to serve documents kept at a third party without giving their addresses or credentials
to the client. For files the application stores itself, use [Files](11.files.md).
