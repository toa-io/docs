# Exposing a Component

A component is called by other components and by the CLI without any HTTP involved. To let the
world outside call it, the component declares how its operations appear as HTTP resources, and
the gateway serves them. What the gateway is, and why a component holds no server of its own, is
in [Resources](../../model/edge/1.resources.md).

## The smallest exposition

Add an `exposition` section to the manifest. It maps a route and an HTTP method to an operation:

```yaml
# components/store.orders/manifest.toa.yaml
name: orders
namespace: store

exposition:
  /:
    anonymous: true
    io:output: true
    GET: enumerate
```

The Context names the host the application is served on:

```yaml
# context.toa.yaml
name: store

exposition:
  authorities:
    shop: api.store.example
```

That is all. Listing the orders is now a request:

```http
GET /store/orders/ HTTP/1.1
host: api.store.example
accept: application/yaml
```

```http
HTTP/1.1 200 OK
content-type: application/yaml

- id: 4c4759e6f9c74da989d64511df42d6f4
  customer: b70a7dbca6b14a2eaac8a9eb4b2ff4db
  status: pending
  total: 4200
```

Three lines of the declaration need a word each.

- `GET: enumerate` maps the method to the operation. `enumerate` comes from the
  [generic prototype](../components/5.prototype.md).
- `io:output: true` lets the reply through. **A method that declares no `io:output` answers no
  body**: the request succeeds with `204 No Content`. Naming the properties a route returns is
  covered in [Input and Output](6.io.md).
- `anonymous: true` lets anyone call the route. **A route that declares no access rule is answered
  `401 Unauthorized`.** Access is declared with `auth:` directives, described in
  [Access](../identity/6.access.md).

## Where a component is mounted

The routes of a component are mounted under `/{namespace}/{name}`, or `/{name}` for a component
without a namespace. Route keys in the manifest are relative to that prefix.

```yaml
# components/store.orders/manifest.toa.yaml
exposition:
  /: ...
  /:id: ...
  /:id/items: ...
```

```
/store/orders/
/store/orders/:id/
/store/orders/:id/items/
```

**A request path ends with a slash.** The route key in the manifest does not.

```http
GET /store/orders HTTP/1.1
```

```http
HTTP/1.1 404 Not Found

"Trailing slash is required"
```

The only paths without a trailing slash are those of stored files, see
[Files](11.files.md).

## More routes and methods

A node of the tree holds methods, nested routes, or both:

```yaml
# components/store.orders/manifest.toa.yaml
exposition:
  /:
    io:output: true
    GET: enumerate
    POST: create
    /:id:
      GET: observe
      PUT: approve
```

| Request | Call |
| --- | --- |
| `GET /store/orders/` | `store.orders.enumerate` |
| `POST /store/orders/` | `store.orders.create`, with the body as input |
| `GET /store/orders/4c47…d6f4/` | `store.orders.observe` of that order |
| `PUT /store/orders/4c47…d6f4/` | `store.orders.approve` of that order |

The route variable `:id` selects the order: it becomes the `id` of the call's query. Creating an
order sends its properties as the body:

```http
POST /store/orders/ HTTP/1.1
host: api.store.example
content-type: application/yaml
accept: application/yaml

customer: b70a7dbca6b14a2eaac8a9eb4b2ff4db
items:
  - product: kettle
    quantity: 1
total: 4200
```

```http
HTTP/1.1 201 Created
content-type: application/yaml

id: 99988d785d7d445cad45dbf8531f560b
```

`io:output` is written once on `/` and applies to every method below it. Keys of the form
`family:name` are *directives*; a directive on a node applies to that node and everything nested
in it. The tree, its variables and the rules of nesting are the subject of
[The Resource Tree](2.routes.md); what each method may be mapped to is in
[Methods and Calls](3.methods.md).

## The long form

`exposition` is a shortcut. The same declaration can be written as an extension of the manifest,
and the Context's part as an annotation:

```yaml
# components/store.orders/manifest.toa.yaml
extensions:
  '@toa.io/extensions.exposition':
    /:
      GET: enumerate
```

```yaml
# context.toa.yaml
annotations:
  '@toa.io/extensions.exposition':
    authorities:
      shop: api.store.example
```

Use the shortcut.

## Routes declared in the Context

The Context may declare routes of its own under the `/` key of its `exposition`. They are mounted
at the root, not under a component's name, so this is where an application gives a resource an
address that does not follow `/{namespace}/{name}`:

```yaml
# context.toa.yaml
exposition:
  authorities:
    shop: api.store.example
  /:
    /pending:
      io:output: [id, total]
      GET:
        endpoint: store.orders.enumerate
        query:
          criteria: status==pending
```

`GET /pending/` now lists pending orders. An endpoint in the Context is written in full:
`namespace.component.operation`, or `component.operation` for a component without a namespace.

Where a route of the Context and a route of a component have the same path, the Context's wins.

Directives placed on the Context's `/` apply to the whole application, since every component's
tree is nested under it:

```yaml
# context.toa.yaml
exposition:
  authorities:
    shop: api.store.example
  /:
    languages: [en, fr]
```

## Running it

The gateway is a service of the runtime. Locally it runs beside the components when the
application is started in one process, and listens on port `8000`:

```shell
$ toa mono components/*
```

```shell
$ curl -H 'accept: application/yaml' http://localhost:8000/store/orders/
```

Starting an application and its environment is covered in [Running](../start/3.running.md);
everything about running the gateway itself — in a composition, on its own, its probe and its
deployment options — is in [Running the Gateway](17.running.md).

Components and the gateway find each other at run time. A component that starts announces its
routes, and the gateway begins serving them; a new version of a component replaces the routes of
the previous one. Nothing is registered by hand, and the gateway is not restarted when a
component changes.

## A component without exposition

A component that declares no `exposition` is not reachable over HTTP and is otherwise complete:
other components call it, receivers and scheduled work run in it. Expose what clients need, and
leave the rest inside.
