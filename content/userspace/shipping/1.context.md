# Describe the Application

The shop works on your machine. To run it anywhere else, something has to say what the
application is called, what it connects to, how its components are grouped into processes and how
it is deployed. That is `context.toa.yaml`, the Context.
[Create an Application](../start/1.application.md) wrote the first few lines of it; shipping the
application is a matter of adding to it.

## Where it starts

The Context from [Create an Application](../start/1.application.md) is the starting point: `name`,
`registry`, the addresses of the broker, the database and the cache, a storage, the host the
gateway answers on, and a key for tokens. `name` and `registry` are required by every command;
the rest is what `toa env` and a local run ask for.

The components of a Context are the directories under `components/` beside the file. Nothing
lists them.

**An unknown top-level key is refused.** A misspelled key fails every command that reads the
Context, naming the key.

Every key, at any depth, may carry an `@<environment>` suffix to give a value for one environment
only: `mongodb@production: mongodb://db.internal`. See
[Give Each Environment Its Values](2.environments.md).

## Name and version

```yaml
name: store
version: 1.4.0
description: A small shop
```

- **`name`** — letters, digits and underscores in words joined by hyphens, starting with a
  letter. The deployed release and the application's database are called by it: `store`.
- **`version`** — the version of what is deployed. A local run does not need it; `toa deploy`
  refuses a Context without one.
- **`description`** — optional.

## Images

```yaml
registry:
  base: registry.example.com/store
  platforms: [linux/amd64]
  credentials: registry-credentials
  services: published
  build:
    arguments: [NPM_TOKEN]
    run: apk add --no-cache ffmpeg

runtime:
  version: 1.0.0
  registry: https://npm.example.com
  proxy: http://proxy.example.com:3128
```

- **`registry`** — where images are pushed and how they are built. `registry: <string>` is
  shorthand for `registry.base`.
- **`runtime`** — optional. `version` is the Toa release the deployed images are built on; absent,
  it is the release of the CLI that deploys. `runtime: 1.0.0` is shorthand for it. `registry` and
  `proxy` are the npm registry and proxy an image build installs from.

Every option is shown in [Build Images](5.images.md).

## Processes

```yaml
compositions:
  - name: core
    components: [store.orders, store.accounts]
    services: [exposition]
    replicas: 3

evicted:
  components: [store.pictures]

resources:
  cpu: [200m, 1]
  memory: [256Mi, 1Gi]

mono:
  replicas: 2
```

- **`compositions`** — which components run together as one process, how many replicas, with
  what resources.
- **`evicted`** — components and services this deployment leaves out.
- **`resources`** — the default CPU and memory of every workload that states none of its own.
- **`mono`** — replicas and resources of the single-image deployment.

All four are shown in [Decide What Runs Together](3.compositions.md).

## Ingress

```yaml
ingress:
  hosts: [api.example.com]
  class: nginx
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: 16m
  default: true
```

The hosts under which the gateway and the built-in pages are reachable from outside the cluster.
See [Deploy](4.deployment.md#ingress).

## Connectors and extensions

Every other key configures a connector or an extension:

```yaml
amqp: amqp://rmq.example.com
mongodb: mongodb://mongo.example.com
stash: redis://redis.example.com

exposition:
  authorities:
    main: api.example.com

configuration:
  store.orders:
    limit: 10000
```

| Key | What it configures | Shown in |
| --- | --- | --- |
| `amqp` | the broker the components talk through | [Connectors](../platform/11.connectors.md) |
| `mongodb` | the database | [Connectors](../platform/11.connectors.md) |
| `http` | where a component answers streamed calls | [Stream a Reply or an Input](../logic/16.streams.md) |
| `stash` | transient shared state (Redis) | [Stash](../platform/4.stash.md) |
| `storages` | file storages | [Storages](../api/10.storages.md) |
| `exposition` | the gateway | [Running the Gateway](../api/17.running.md) |
| `realtime` | realtime routes | [Realtime](../api/13.realtime.md) |
| `configuration` | component configuration values and secrets | [Configuration](../platform/2.configuration.md) |
| `telemetry` | logs, traces, metrics | [Exporting Telemetry](../platform/9.exporting-telemetry.md) |
| `introspection` | the topology and [halt](9.halt.md) | [Introspection](../platform/10.introspection.md) |
| `cadence` | schedules and delayed calls | [Do Something Later](../logic/14.delays.md) |
| `continuity` | resuming failed workflows | [Write a Multi-Step Workflow](../logic/12.workflows.md) |
| `convergence` | regions | [Run in More Than One Region](8.regions.md) |

These keys are shortcuts for package names. A package without a shortcut is configured under
`annotations`, by its name:

```yaml
annotations:
  '@toa.io/extensions.stash': redis://redis.example.com
```

### Addresses

`amqp`, `mongodb` and `stash` take addresses. One address serves everything:

```yaml
mongodb: mongodb://mongo.example.com
```

To give a namespace or one component its own, write a map. A component takes the most specific
key that matches its `<namespace>.<name>`; `.` is the default:

```yaml
mongodb:
  .: mongodb://mongo.example.com               # everything else
  store: mongodb://store.mongo.example.com     # every component of `store`
  store.catalog: mongodb://catalog.example.com # `store.catalog` alone
```

Without a `.` key, a component that matches nothing is refused by name. A component without a
namespace is in `default`.

A key may hold several addresses, as a list or a range; `{1-3}` expands to `redis1`, `redis2`,
`redis3`:

```yaml
stash:
  .:
    - redis://redis0.example.com
    - redis://redis{1-3}.example.com
```

The broker has two sections. `amqp: <address>` is shorthand for `amqp.context`; `amqp.sources`
holds the brokers that events of other applications come from, keyed by source:

```yaml
amqp:
  context: amqp://rmq.example.com
  sources:
    warehouse: amqp://rmq.warehouse.example.com
```

**An address never carries a user name or a password.** They are supplied as secrets; see
[Supply Secrets](6.secrets.md#credentials).
[Addresses and Credentials](../platform/12.addresses-and-credentials.md) has the rest.

### Resources of extension services

Some extensions run a process of their own: the gateway (`exposition`), the configuration values
service (`configuration`), the topology explorer (`introspection`), the scheduler (`cadence`).
The gateway, the values service and the explorer take `resources` inside their own key, in the
same form as the Context's:

```yaml
exposition:
  resources:
    cpu: [200m, 2]
    memory: [200Mi, 1Gi]
```

Without it the service takes the Context's `resources`.

## Events another application reads

`store.orders` announces `approved`, and a warehouse system outside the application listens. A
deployed component publishes an event only when a receiver in the application consumes it, so an
event read from outside has to be named:

```yaml
events:
  - store.orders.approved
```

Each entry is `<namespace>.<component>.<event>`. **Without the entry and without a receiver, a
deployment does not publish `approved` at all.** A local run, `toa mono`, and a composition
booted in a test publish every event, so the difference shows only after deploying.
[Announce a Change](../logic/7.events.md) covers declaring events.

## Runtime settings

All optional.

```yaml
atomicity:
  redis: redis://redis.example.com
  interval: 1000

outbox:
  interval: 5000
  batch: 100
  retention: 86400

inbox:
  retention: 3600

addressed:
  timeout: 30000
```

| Key | Sets | Shown in |
| --- | --- | --- |
| `atomicity.redis` | one Redis address, or an odd number of independent ones, where replicas decide together | [Shared Decisions](../platform/5.shared-decisions.md) |
| `atomicity.interval` | how often a replica registers, ms, at least `100` | same |
| `outbox.interval` | how often unpublished events are looked for, ms, at least `100` | [Look After It](10.operating.md#events-are-not-published) |
| `outbox.batch` | how many are read at once, at least `1` | same |
| `outbox.retention` | seconds a published event is kept as a change log, `0` or more | same |
| `inbox.retention` | seconds a call is remembered for deduplication, at least `600` | [Handle Repeated Calls](../logic/10.repeats.md) |
| `addressed.timeout` | ms an addressed call waits for its reply by default | [Keep Something in a Process](../logic/17.processes.md) |

## Every top-level key

| Key | Required | Purpose |
| --- | --- | --- |
| `name` | yes | the application's name |
| `registry` | yes | where images go and how they are built |
| `version` | to deploy | the version of what is deployed |
| `description` | no | a description |
| `runtime` | no | Toa version, npm registry and proxy for builds |
| `compositions` | no | components grouped into processes |
| `evicted` | no | what this deployment leaves out |
| `resources` | to deploy | default CPU and memory, or `null` |
| `mono` | no | replicas and resources for `--mono` |
| `ingress` | no | hosts, class and annotations for what is reachable from outside |
| `annotations` | no | configuration of packages by package name |
| shortcut keys | no | `amqp`, `mongodb`, `http`, `stash`, `storages`, `exposition`, `realtime`, `configuration`, `telemetry`, `introspection`, `cadence`, `continuity`, `convergence` |
| `atomicity`, `outbox`, `inbox`, `addressed` | no | runtime settings |
| `events` | no | events consumed outside the application |

## A complete example

```yaml
# context.toa.yaml
name: store
version: 1.4.0

registry:
  base@local: localhost:5000
  base@production: registry.example.com/store
  platforms@local: ~

resources:
  cpu: [200m, 1]
  memory: [256Mi, 1Gi]

compositions:
  - name: core
    components: [store.orders, store.accounts, store.catalog]
    replicas: 3
  - name: media
    components: [store.pictures]

amqp@local: amqp://localhost
amqp@production: amqp://rmq.internal.example.com

mongodb@local: mongodb://localhost
mongodb@production: mongodb://mongo.internal.example.com

exposition:
  authorities:
    main@local: localhost:8000
    main@production: api.example.com

ingress:
  hosts@production: [api.example.com]

configuration:
  store.orders:
    limit: 10000
    limit@local: 100
```

One file describes the shop on a developer's machine and in production.
