# Stateful Operations

A call is addressed to a component, and whichever replica is free takes it. Occasionally
something exists in exactly one process — an open connection to a device, a session held in
memory — and a call has to reach that process and no other. There are two tools for it: memory
that belongs to a process, and operations that are called by the process's name. The concept is
described in [Stateful Operations](../../model/flow/4.stateful.md).

## Process memory

Declare the `state` extension, and every operation of the component finds an object at
[`context.state`](../services/5.stash-and-state.md#state):

```yaml
# components/store.catalog/manifest.toa.yaml
state: ~
```

```javascript
// components/store.catalog/operations/price.js
export async function computation (input, context) {
  context.state.prices ??= new Map()

  if (!context.state.prices.has(input.product))
    context.state.prices.set(input.product, await lookup(input.product))

  return context.state.prices.get(input.product)
}
```

The object is empty when the process starts and is shared by the operations of the component
*in that process*. There is nothing else to configure.

It is the same object a [run command](../components/10.lifecycle.md) receives, so what a
component opens when it starts is usually put there, and released when it stops:

```javascript
// components/store.terminals/rc/connections.js
export function preflight (context) {
  context.state.connections = new Map()
}

export async function dispose (context) {
  for (const connection of context.state.connections.values()) await connection.close()
}
```

**Process memory is a cache, not state.** Each replica has its own, it is lost when the process
stops, and no other replica sees it. Whatever has to survive, or be seen by another replica,
belongs in the entity.

A [pulse declared `scope: replica`](1.pulses.md#work-that-belongs-to-a-process) is how each
process looks after its own memory on a rhythm.

## Addressing a process

`store.terminals` drives card terminals at the tills. A terminal keeps one connection open, and
that connection lives in the process that opened it. Charging a card has to happen in that
process.

Declare the operation `stateful`:

```yaml
# components/store.terminals/manifest.toa.yaml
state: ~

entity:
  properties:
    holder: { type: string }

operations:
  charge:
    type: computation
    stateful: true
    input:
      type: object
      properties:
        terminal: { type: string }
        amount: { type: integer }
      required: [terminal, amount]
    errors: [NOT_HELD, DECLINED]
```

A stateful operation is served by every process of the component under that process's own name.
A process reads its name as `context.instance` and gives it to whoever will need it later —
usually by storing it in the entity:

```javascript
// components/store.terminals/operations/connect.js
export async function effect (input, context) {
  context.state.connections.set(input.terminal, await open(input.address))

  await context.local.assign({
    query: { id: input.terminal },
    input: { holder: context.instance }
  })
}
```

`connect` is an ordinary operation: whichever process takes the call opens the connection and
records itself as the terminal's `holder`.

The stateful operation works with what its process holds:

```javascript
// components/store.terminals/operations/charge.js
export async function computation (input, context) {
  const connection = context.state.connections.get(input.terminal)

  if (connection === undefined) return new Error('NOT_HELD')

  // ...
}
```

A caller names the process in `instance`, beside `input`:

```javascript
// components/store.orders/operations/pay.js
export async function effect (input, context) {
  const terminal = await context.remote.store.terminals.observe({
    query: { id: input.terminal }
  })

  return await context.remote.store.terminals.charge({
    input: { terminal: terminal.id, amount: input.amount },
    instance: terminal.holder
  })
}
```

The rest of the call is unchanged: it has a contract, it is validated and traced, and it answers
a value or an error. A component calls its own stateful operation the same way, through
`context.local`.

### What may name a process

These calls are refused with the `RequestContract` exception before anything is sent:

- a call to a stateful operation that names no `instance`;
- a call to an ordinary operation that names one;
- a [task](../../model/reliability/4.tasks.md) or a [delayed call](3.delays.md) that names one:
  both are made later, by whichever process takes them;
- a call to an ordinary operation that states a `timeout` or a `signal` (see
  [Waiting](#waiting)).

A [receiver](../components/7.receivers.md) may be bound to a stateful operation. Its adaptation
names the process in the request it returns, and the call reaches that process from whichever
replica took the event:

```javascript
// the adaptation of a receiver in store.terminals
export function request (order) {
  return { input: { terminal: order.terminal }, instance: order.holder }
}
```

### The name

A name is generated when the process starts. To give a process a name of your choice, set the
`TOA_INSTANCE` environment variable:

```shell
$ TOA_INSTANCE=till-7 toa compose ./components/store.terminals
```

**A process is called by its name only once it serves its operations.** A process that hands its
name out as it starts does so in the `ready` run command, not in `preflight` or `settle`; a call
made before `ready` may be refused with `Addressee`.

```javascript
// components/store.terminals/rc/register.js
export async function ready (context) {
  await context.remote.store.tills.register({ input: { process: context.instance } })
}
```

## What an addressed call ends in

**An addressed call is unreliable.** An ordinary call reaches a component, and a component comes
back: the call waits, is kept, is tried again. An addressed call reaches one process. When that
process is gone — it crashed, it was stopped, it lost its connection to the broker — no replica
can answer in its place.

| Outcome | Code | What it means for the caller |
| --- | --- | --- |
| The reply | | The process answered. |
| `Addressee` | `403` | Nothing held the name. The call did not run. |
| `Abandoned` | `404` | The wait ended. The call may have run, and may still. |

Both are exceptions, thrown where the call is made, and both are ordinary events in the life of
such a system. **A caller of a stateful operation is written to expect them**, and tells them by
`exception.code`:

```javascript
// components/store.orders/operations/pay.js
const ADDRESSEE = 403
const ABANDONED = 404

export async function effect (input, context) {
  // ...

  try {
    return await context.remote.store.terminals.charge({
      input: { terminal: terminal.id, amount: input.amount },
      instance: terminal.holder
    })
  } catch (exception) {
    if (exception.code === ADDRESSEE) return new Error('TERMINAL_OFFLINE')
    if (exception.code === ABANDONED) return new Error('TERMINAL_UNCERTAIN')

    throw exception
  }
}
```

After `Addressee` it is safe to recover: here, to have the terminal connected again by another
process. After `Abandoned` the caller does not know whether the card was charged, and has to find
out before trying again.

A third outcome is the stateful operation's own answer. The process named may be alive and no
longer hold the thing — it was restarted under the same name, or let the connection go. That is
why `charge` returns `NOT_HELD`: an [error](../components/3.errors.md) the caller handles like
any other.

## Waiting

An addressed call waits 5 seconds for its reply. A call sets its own wait in a second argument:

```javascript
await context.remote.store.terminals.charge(
  { input: { terminal, amount }, instance },
  { timeout: 60_000 }
)
```

| Option | Meaning |
| --- | --- |
| `timeout` | Milliseconds to wait for the reply. |
| `signal` | An `AbortSignal` that ends the wait when it aborts, within the timeout. |

```javascript
await context.remote.store.terminals.charge(
  { input: { terminal, amount }, instance },
  { signal: AbortSignal.timeout(10_000) }
)
```

When either ends the wait, the call throws `Abandoned`. A signal that is already aborted when the
call is made, or aborts while the component is still being looked up, means the call is made
nowhere.

Only an addressed call takes these options, remote or local. An ordinary call waits for as long
as its reply takes, and is refused if it states either.

For a [streamed reply](5.streamed-calls.md#streamed-replies) the wait covers the start of the
stream, not its length.

A call still waiting to be taken when its timeout passes is dropped and never runs. A call whose
signal ended the wait earlier stays in line until its timeout, and may still run.

The default wait is set for the whole application:

```yaml
# context.toa.yaml
addressed:
  timeout: 5000 # milliseconds
```

## Keeping the exception small

`stateful` is a declared departure from what the rest of the component guarantees, so keep it to
the operations that touch the live resource.

- **Keep durable facts in the entity.** `store.terminals` stores which process holds each
  terminal. Its ordinary operations — `connect`, `observe`, `enumerate` — are reliable; only
  `charge` is stateful.
- **Record the holder, and clear it.** A process that stops lets go of what it holds in
  `dispose`, while it can still call other components.
- **Notice a holder that vanished.** A process that crashed clears nothing. A
  [pulse](1.pulses.md) that probes the recorded holders with a cheap stateful operation, and
  treats `Addressee` as "gone", lets the rest of the system recover.

## Limits

- **A name lasts as long as its process's connection to the broker.** While the process
  reconnects, calls to it are refused and calls waiting for it are abandoned, though the process
  itself keeps running. It holds its name again once it is back.
- **A name given by `TOA_INSTANCE` passes to the next process started with it**, which then
  answers the calls meant for the process before it. Check what the process holds, as `charge`
  does.
- **Two live processes given one name can both hold it** and both answer calls. Each logs
  `Instance name taken`. Give each process a name of its own.
- **The first call to a component looks the component up**, and waits for as long as the
  component takes to appear. The timeout counts from when it is found.
- **Declaring `stateful` on an operation that used to be ordinary** changes how it is called.
  Every caller has to run a runtime version that knows the declaration before it is deployed.
