# Pulses

A pulse calls an operation of its own component at a regular interval. It is the first of the
three ways a component is called by time rather than by a request; the other two are
[schedules](2.schedules.md) and [delays](3.delays.md). The concept is described in
[Cadence](../../model/flow/1.cadence.md).

## The smallest pulse

`store.orders` cancels orders nobody paid for. Name the operation under `cadence` and state the
number of seconds between calls:

```yaml
# components/store.orders/manifest.toa.yaml
cadence:
  expire: 3600 # once an hour

operations:
  expire:
    input:
      type: object
      properties:
        n: { type: integer }
        i: { type: integer }
```

```javascript
// components/store.orders/operations/expire.js
const DAY = 24 * 3600 * 1000

export async function effect (input, context) {
  const deadline = context.now() - DAY

  const orders = await context.local.enumerate({
    query: { criteria: `status==pending;CREATED<${deadline}`, limit: 100 }
  })

  for (const order of orders)
    await context.local.cancel({ query: { id: order.id } })
}
```

Every hour one replica of `store.orders` calls `expire`. Nothing else is needed in the component.

Three rules apply to the operation a pulse names:

- It is an operation **of the same component**. A name that is not one is refused when the
  manifest is read: `Cadence refers to undefined operation 'expire'`.
- Its type is `transition`, `assignment`, `effect` or `unmanaged`. An observation or a
  computation changes nothing, so there is nothing to call it periodically for, and it is refused.
- **It declares an input that accepts `{ n, i }`**, because that is what a pulse calls it with
  (see [below](#spreading-a-cycle)). An operation that declares no input accepts none, and every
  call of the pulse would be refused.

A pulse sends no query. An operation that works on entities selects them itself, as `expire` does
through `context.local`.

## When the calls happen

A cycle is counted from the Unix epoch, not from the moment the component started. `3600` means
the top of every hour and `86400` means midnight UTC, in every replica and after every restart.

A cycle that does not divide a day lands on boundaries that are no particular time of day. When
you need a time of day in a time zone, a weekday or a day of the month, declare a
[schedule](2.schedules.md).

## Spreading a cycle

The full form states the cycle and the number of intervals it is split into:

```yaml
# components/store.orders/manifest.toa.yaml
cadence:
  sweep:
    cycle: 86400 # seconds one whole cycle takes
    intervals: 24 # so one call an hour
```

The gap between calls is `cycle / intervals`. The operation is called with both numbers as its
input: `n` is `intervals`, and `i` is the interval this call is for, from `0` to `n - 1`.

```javascript
// components/store.orders/operations/sweep.js
export async function effect ({ n, i }, context) {
  const orders = await context.local.enumerate({
    query: { criteria: `status==pending;shard==${i}`, limit: 1000 }
  })

  // ...
}
```

An operation that takes `i` as its share of the work does a twenty-fourth of it every hour instead
of all of it at midnight. How an entity falls into a share is yours to decide. Here every order
was given a `shard` from `0` to `23` when it was created.

The shorthand `expire: 3600` is `cycle: 3600` with `intervals: 1`, so `expire` is called with
`{ n: 1, i: 0 }`.

`intervals` may not exceed `cycle`: an interval is at least a second long.

**`intervals` is not a replica count.** The cycle is spread over time, not over the replicas. With
`intervals: 24` and three replicas, each replica makes eight of the day's calls. Replicas beyond
`intervals` make none.

## What a pulse promises

A pulse stores nothing, and its promises follow from that. Write the operation with them in mind.

**An interval may be missed, and is not made up.** A rollout, a crash, or an operation that threw
or outran its interval costs that interval.

**So select by state, not by position.** `expire` above cancels *every* pending order older than
a day, not "the orders that expired in the last hour". A missed hour is healed by the next one.
With `intervals` above `1` the shares are a partition: a missed `i = 5` is not covered by `i = 6`
and waits a whole cycle. Take what in the share is still due, not everything in the share, and a
missed interval costs a delay instead of a day's work.

**An interval is called once.** A second call for the same interval is possible only in the
moment the work changes hands between replicas whose clocks disagree.

**A call is never made while the previous one is still running.** If the work does not fit the
gap, the next interval is skipped and the skip is logged. When you see that in the logs, the cycle
is too short or has too few intervals.

**An operation that throws loses its interval.** Nothing is retried, and there is no setting for
it.

When a call has to happen even if nothing was running at its moment, it has to be stored. A
[schedule](2.schedules.md) is stored, and so is a [delay](3.delays.md).

## Work that belongs to a process

By default a pulse is the component's: however many replicas run, one of them makes each call.
That suits work over shared state, such as a collection to sweep or a report to rebuild.

Some work concerns what one process holds: a cache, a buffer, a pool of connections, a file the
process wrote in its own container. Declare `scope: replica` and the call is made in every
replica:

```yaml
# components/store.catalog/manifest.toa.yaml
state: ~

cadence:
  trim:
    cycle: 60
    scope: replica

operations:
  trim:
    input:
      type: object
      properties:
        n: { type: integer }
        i: { type: integer }
```

```javascript
// components/store.catalog/operations/trim.js
export async function effect (input, context) {
  const deadline = context.now() - 600_000

  for (const [key, cached] of context.state.prices)
    if (cached.at < deadline) context.state.prices.delete(key)
}
```

`store.catalog` keeps prices it looked up in [process memory](6.stateful.md#process-memory) — a
`Map` it creates when the process starts — and each replica trims its own. The operation runs in
the replica that made the call.

What changes under `scope: replica`:

- `intervals` still splits the cycle over time. Every replica walks the whole split, so
  `intervals: 24` with a daily cycle is each replica doing a twenty-fourth of its own work every
  hour.
- An interval is called once *per replica*. While a rollout has old and new replicas up together,
  that is more calls than either count.
- **Nothing spaces the calls out.** Every replica calls at the same boundary by the same clock. An
  operation that reaches a database or an API reaches it as many times at once as there are
  replicas. Keep a `replica` pulse to the process's own work, and put everything else in a
  component's pulse.
- It needs nothing configured; see the next section.

## What a pulse needs to run

A pulse of the component (`scope: group`, the default) relies on the replicas agreeing which of
them makes each call. They agree through Redis, which the Context names once for the whole
application:

```yaml
# context.toa.yaml
atomicity:
  redis: redis://redis.example.com
```

**Without it, a component's pulse is never called**, and nothing reports an error. A pulse
declared `scope: replica` does not need it and is called either way.

Locally, with `TOA_DEV=1`, Redis is expected at `redis://localhost`. The annotation and its other
uses are covered in [Shared Decisions](../services/6.shared-decisions.md); the concept is in
[Atomicity](../../model/platform/5.atomicity.md).

A pulse starts a new [chain](../../model/reliability/6.chains.md) with every call, so an
operation called by one may call anything an ordinary request may.

## Several regions

In an application deployed as several [regions](../running/10.regions.md), every region makes every
pulse for itself. A pulse that is work for the whole application names the one region that makes it
with `region`. It is declared the same way for pulses and schedules; see
[One region or every region](2.schedules.md#one-region-or-every-region).

## Reference

```yaml
cadence:
  <operation>: <seconds>          # shorthand: a cycle with one interval
  <operation>:
    cycle: <seconds>
    intervals: <number>
    scope: group | replica
    region: <rank>
```

| Key | Default | Meaning |
| --- | --- | --- |
| `cycle` | required | Seconds one whole cycle takes; an integer, at least `1`. |
| `intervals` | `1` | Calls per cycle; an integer from `1` to `cycle`. |
| `scope` | `group` | `group`: one replica makes each call. `replica`: every replica does. |
| `region` | every region | Rank of the only region that makes the calls. Not allowed with `scope: replica`. |

An operation may have several entries, pulses and schedules mixed; see
[Several entries](2.schedules.md#several-entries).

Input of the called operation:

| Property | Meaning |
| --- | --- |
| `n` | The number of intervals in the cycle. |
| `i` | The interval this call is for, `0` to `n - 1`. |
