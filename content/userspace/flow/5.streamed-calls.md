# Streamed Calls

An ordinary call carries values: the input goes in whole and the output comes back whole. A call
can also carry a stream, in either direction. A streamed *reply* costs nothing and needs no
declaration. A streamed *input* is a different kind of call and gives up most of what an ordinary
call has. The concept is described in [Streamed Calls](../../model/flow/3.streams.md).

## Streamed replies

An operation answers with a stream by being a generator:

```javascript
// components/store.orders/operations/receipt.js
export async function* observation (input, order) {
  yield `Order ${order.id}\n`

  for (const item of order.items)
    yield `${item.quantity} x ${item.product}\n`

  yield `Total: ${order.total}\n`
}
```

or by returning a `Readable`:

```javascript
// components/store.pictures/operations/thumbnail.js
import { Readable } from 'node:stream'

export async function computation (input, context) {
  return Readable.from(render(input.picture))
}
```

`store.pictures` is a component that works with product pictures.

Nothing is declared for it, and an operation may decide call by call: it answers a value or a
stream, whichever the work came to. The call itself is an ordinary one. It is queued, delivered,
retried and traced like any other, and any binding carries it.

**A reply is a value or a stream, never a value with a stream inside it.**

### Reading a streamed reply

The caller receives a `Readable` and reads what the operation yields as it is yielded:

```javascript
const receipt = await context.remote.store.orders.receipt({ query: { id } })

for await (const line of receipt) {
  // ...
}
```

The stream carries bytes where the operation yielded Buffers, and values otherwise.

### When a streamed reply fails

**A reply stream that ends was written to its end.** A truncated stream is never presented as a
complete one:

- where the operation throws after its first value, the exception is thrown on the caller's
  stream, inside its `for await`;
- where the process serving the call stops mid-reply, the caller's stream is destroyed.

So wrap the reading, not only the call, where the caller has something to undo:

```javascript
try {
  for await (const line of receipt) await write(line)
} catch (exception) {
  await discard()

  throw exception
}
```

## Streamed input

An operation may *take* a stream: it reads what its caller writes while the caller is writing it,
and nothing in between holds the payload. `store.pictures` computes the checksum of a picture as
it is uploaded.

Name the input property that carries the stream, and declare a binding that can carry one:

```yaml
# components/store.pictures/manifest.toa.yaml
bindings: [amqp, http]

operations:
  checksum:
    type: computation
    stream: content
```

The operation finds a `Readable` there:

```javascript
// components/store.pictures/operations/checksum.js
import { createHash } from 'node:crypto'

export async function computation (input) {
  const hash = createHash('sha256')

  for await (const chunk of input.content) hash.update(chunk)

  return hash.digest('hex')
}
```

A caller puts a stream there:

```javascript
const sum = await context.remote.store.pictures.checksum({ input: { content } })
```

### Declaring

`stream` names one input property. The rest of `input` is declared and validated as usual, so a
call carries ordinary values beside the stream:

```yaml
# components/store.pictures/manifest.toa.yaml
operations:
  resize:
    type: effect
    stream: source
    input:
      type: object
      properties:
        width: { type: integer }
      required: [width]
```

The named property itself is not validated, since a stream has no schema. It is required: a call
that omits it is refused.

`stream` may be declared on an `effect`, a `computation` and an `unmanaged` operation. It may not
be declared on a transition: a transition may be run twice over one call, and a stream cannot be
read twice.

**The operation needs a binding that carries a stream**, which is `http`, declared beside the
component's other bindings — for the whole component, as above, or for the operation alone under
its own `bindings`. Without one the component does not start:

```
Operation 'resize' takes a stream, which none of its bindings carries
```

Ordinary calls, tasks and events of the component go on travelling over its other binding.

Components composed in the same process need none of this: a stream is passed between them as it
is.

### Calling

The property holds the stream, or an object whose `stream` member holds it, beside whatever the
caller wants to say about it:

```javascript
await context.remote.store.pictures.resize({ input: { width: 320, source } })

await context.remote.store.pictures.resize({
  input: { width: 320, source: { type: 'image/png', accept: 'image/webp', stream } }
})
```

The second form is what the gateway hands over for an upload: `type` is what arrived and `accept`
is what to answer with. An operation that may be called both ways reads either:

```javascript
// components/store.pictures/operations/resize.js
export async function effect (input, context) {
  const stream = input.source.stream ?? input.source

  // ...
}
```

These calls are refused with the `RequestContract` exception before anything is sent:

- a call to an operation that takes a stream and carries none;
- a call that carries a stream to an operation that takes none;
- a value where the stream goes;
- a [task](../../model/reliability/4.tasks.md) or a [delayed call](3.delays.md) that carries a
  stream.

### What it gives up

An ordinary call is a message: it can wait in a queue and be delivered again. A stream in
progress exists only while its writer is writing, so a streamed call has none of that.

| An ordinary call | A streamed call |
| --- | --- |
| Waits for a component that is not running. | Fails, with the `Unreachable` exception. |
| Is delivered again when the replica that took it fails. | **Is not retried.** |
| Can be made as a task or delayed. | Cannot be deferred. |
| Shares connections. | Opens a connection of its own, closed when it ends. |
| Is balanced between replicas. | Goes to a replica picked at random. |

What this means for the code you write:

- **Handle the failure in the caller.** Nothing beneath it will have tried again. Whether to
  retry is the caller's decision, and it needs a fresh stream to do so.
- A component that is scaled to zero or is between deployments fails the call.
- A hundred calls in flight are a hundred sockets at each end.

### When to use it

A streamed call is for bytes that have to flow *through* an operation and are not kept: a
checksum, a transcode, a parse, a forward. Three things resemble it and are something else:

- **An input that is a value** is an ordinary call, however large the value is.
- **An answer that arrives in pieces** is a [streamed reply](#streamed-replies).
- **An upload that is to be kept** is stored by the gateway as it arrives, and components are called
  afterwards with a reference to it; see [Files](../gateway/11.files.md) and
  [File Workflows](../gateway/12.workflows.md). Where bytes are to be stored *and* processed, store
  them first and process them afterwards.

Used for any of these, a streamed call pays the price in the table above and buys nothing.

### Addresses

A streamed call is made to the component's address. In a deployment there is nothing to state: a
component is addressed at the service rendered for it, on port `8005`.

Where processes run side by side on one machine, state the ports in the Context:

```yaml
# context.toa.yaml
http@local:
  store.pictures: http://127.0.0.1:8005
  store.imports: http://127.0.0.1:8006
```

A key is a component, a namespace, or `.` for every component. A process listens on the port in
the address of each component it serves, and callers use the same map to reach it.

## Limits

- **Declaring `stream` on an operation that used to be ordinary** changes how it is called. Every
  caller has to run a runtime version that knows the declaration before it is deployed.
- **A component is reachable at one address.** A component that runs in a network of its own is
  still called over the broker, and a streamed call to it fails.
- **A streamed reply cannot be continued.** An operation run under
  [continuity](../../model/reliability/5.continuity.md) answers values.

## Over HTTP

The gateway serves a streamed reply as a streamed response, and hands a request body to an operation
