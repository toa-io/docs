# Schedules

A schedule calls an operation of its own component at the moments of a calendar: noon on
weekdays, the first of the month, nine on Monday morning in Berlin. Where a
[pulse](1.pulses.md) is a rhythm that stores nothing, each occurrence of a schedule is stored
ahead of its moment, so it is made late rather than lost.

## The smallest schedule

`store.orders` builds a sales report every weekday at noon. A string under `cadence` is a cron
expression:

```yaml
# components/store.orders/manifest.toa.yaml
cadence:
  report: 0 12 * * 1-5 # noon UTC on weekdays

operations:
  report:
    input:
      type: object
      properties:
        at: { type: integer }
      required: [at]
```

```javascript
// components/store.orders/operations/report.js
const DAY = 24 * 3600 * 1000

export async function effect ({ at }, context) {
  const orders = await context.local.enumerate({
    query: { criteria: `status==approved;CREATED>${at - DAY};CREATED<${at}`, limit: 1000 }
  })

  // ...
}
```

The operation is called with `at`: the moment the call was scheduled for, in milliseconds since
the epoch. **It is the moment of the schedule, not of the call.** A report made twenty minutes
late is still the report for noon, so compute the period from `at` and never from the clock.

The rules for the operation are those of a pulse: it belongs to the same component, its type is
`transition`, `assignment`, `effect` or `unmanaged`, and it declares an input that accepts what
it is called with, here `{ at }`.

## The expression

An expression has five fields — minute, hour, day of the month, month, day of the week — or six,
where the first is seconds.

```yaml
cadence:
  invoice: 0 6 1 * *        # six in the morning on the first of the month
  poll: '*/5 * * * *'       # every five minutes
  tick: '*/30 * * * * *'    # every thirty seconds: six fields
```

**Quote an expression that begins with `*`.** YAML reads a leading `*` as its own syntax.

An expression that does not parse, has another number of fields, or never comes due is refused
when the manifest is read.

## Time zone and lateness

The full form states the expression under `schedule` and adds options:

```yaml
# components/store.notifications/manifest.toa.yaml
cadence:
  digest:
    schedule: 0 9 * * 1 # nine on Monday morning
    zone: Europe/Berlin # in Berlin
    overdue: 3600 # seconds it may be late and still be made
```

`zone` is the IANA time zone the expression is read in, `UTC` by default.

`overdue` is how many seconds late a call may be and still be made. Without it, a call is made
until the next occurrence comes due. A schedule cannot state "no bound": `overdue: ~` is refused.

## What a schedule promises

Each occurrence is a [delayed call](3.delays.md) handed over ahead of its moment, and what a
delayed call [may and may not do](3.delays.md#what-a-delay-promises) holds for it.

**A call is made late rather than lost.** An occurrence is stored as soon as the one before it
comes due. A component that is down at noon is called when it is back, with the `at` of noon.

**At most one occurrence is owed.** A call is not made once the next one is due. A component that
was away from Friday to Monday is called for Monday and not for Friday, and an outage of a month
does not come back as thirty calls. `overdue` states a tighter bound.

**An occurrence is lost where the component did not run at all** between the occurrence before it
and its own moment: nothing was there to store it.

**A call may be made more than once.** Where a second one would cost something, the operation
refuses it by `at` — for example, by recording the `at` it last worked for.

**Calls may overlap.** A pulse skips an interval its work did not fit in; a schedule does not, and
a call may be made while the one before it is still running.

**A schedule that was changed or removed may be called once more**, at the moment already stored
for it.

**Seconds are served coarsely.** Stored calls are looked over once a minute by default, so an
occurrence closer than that to the one before it is made at the next pass, not at its moment. The
same period limits how small an `overdue` is worth stating. See
[Discreteness](3.delays.md#discreteness).

## Several entries

An operation that has more than one entry takes a list, of either kind:

```yaml
# components/store.orders/manifest.toa.yaml
cadence:
  sweep:
    - cycle: 3600 # what is due, every hour
    - schedule: 0 3 1 * * # and everything, on the first of the month
```

The entries are independent and nothing keeps their calls apart. An operation given both kinds is
called with `{ n, i }` by the pulse and with `{ at }` by the schedule, so declare an input that
accepts both and tell them apart by what arrived:

```javascript
// components/store.orders/operations/sweep.js
export async function effect (input, context) {
  const everything = input.at !== undefined

  // ...
}
```

Two schedules of one operation that fall on the same moment are one call.

## One region or every region

In an application deployed as several [regions](../../model/running/5.regions.md), every region
makes every pulse and every schedule, each for itself. An entry that is work for the whole
application names the region that makes it, by rank:

```yaml
# components/store.orders/manifest.toa.yaml
cadence:
  sweep:
    cycle: 3600
    region: 0 # a pulse only region 0 makes
  invoice:
    schedule: 0 6 1 * *
    region: 0 # made once, however many regions there are
```

Different regions can take different entries of one operation:

```yaml
# components/store.notifications/manifest.toa.yaml
cadence:
  digest:
    - schedule: 0 9 * * 1
      zone: Europe/Berlin
      region: 0
    - schedule: 0 9 * * 1
      zone: America/New_York
      region: 1
```

**An entry that names a rank no region has is never made**, and nothing says so. An application
deployed in one place is rank `0`.

`region` cannot be stated beside `scope: replica`: what lives in a process is that process's own
in every region.

When a region is lost, another one can take over its entries together with its delayed calls; see
[Taking over a lost region](3.delays.md#taking-over-a-lost-region).

## What a schedule needs to run

A schedule relies on the same two things a delay does: the
[`atomicity`](../services/6.shared-decisions.md#setting-it-up) annotation in the Context, and the
cadence service that keeps and makes stored calls. Without them no scheduled call is made. Both are
described in [Running cadence](3.delays.md#running-cadence).

## Reference

```yaml
cadence:
  <operation>: <expression>       # shorthand: a string is a schedule, a number is a pulse
  <operation>:
    schedule: <expression>
    zone: <IANA time zone>
    overdue: <seconds>
    region: <rank>
```

| Key | Default | Meaning |
| --- | --- | --- |
| `schedule` | required | Cron expression of five fields, or six where the first is seconds. |
| `zone` | `UTC` | Time zone the expression is read in. |
| `overdue` | until the next occurrence | Seconds a call may be late and still be made; `0` or more. |
| `region` | every region | Rank of the only region that makes the calls. |

An entry states either `cycle` or `schedule`. One that states both, or neither, or a key of the
other kind, is refused when the manifest is read.

Input of the called operation:

| Property | Meaning |
| --- | --- |
| `at` | The moment the call was scheduled for, milliseconds since the epoch. |
